# Tripo3D 生成参数

2026-09-09。参数定义逐条核对自官方文档 `platform.tripo3d.ai/docs/generation` 与 `/docs/texture`。

## 贴图必须开（一次说错的更正）

早先写的「关掉 pbr」会连带把贴图关没。实测白模的 GLB 是 `images=0, textures=0`，顶点属性只有
`POSITION`/`NORMAL`，**连 UV 都没有**。没有贴图就只能整件上一个颜色，多材质件（拱门=石+铜钟+藤蔓，
巨树=树干+树冠）必然穿帮，已实测验证。

| 选项 | 设成 | 依据 |
| --- | --- | --- |
| `texture` | **true** | 关掉即白模，多材质件救不回来 |
| `pbr` | **false** | 文档明载 `texture_quality=detailed` + `texture=true` + `pbr=false` = 「重新生成 HD 贴图但不带 PBR」。金属度/粗糙度/法线我们的 shader 不吃，纯占包体 |
| `texture_quality` | **standard**（+10 分）| `detailed`(+20) 升到 **4K**、`extreme`(+30) 更高，但我们一律压到 ≤1024，多出的全被丢掉。除非某件出图糊否则不值 |
| 模式 | **Clean Topology**（`quad=true`）| 四边面减面时轮廓不塌。会强制输出 FBX，导入器两种格式都收 |
| `face_limit` | 见下表 | quad 模式范围 500–10000，**计的是四边面**，1 quad ≈ 2 三角面 |
| `orientation` | `align_image` | 自动对齐输入图朝向 |
| `smart_low_poly` | 不用 | 文档明说复杂模型有失败可能，拱门/巨树正是复杂件 |

**已生成的白模不用重做几何体。** `texture_model` 是独立任务，接受 `original_model_task_id`，
可直接对已有模型补贴图；网页版对应模型详情页里的重新贴图 / Retexture 入口。

## 贴图分辨率按屏幕占比分档

不是按物件实际尺寸：路灯和旗杆虽高但很细，占不了几个像素。贴图是**逐模型一张、所有实例共用**，
因此实例数只影响面数预算，不影响贴图开销。

| 档 | 用于 | 件数 |
| ---: | --- | ---: |
| **1024** | 悬钟石拱门、巨树带板根、悬浮水晶喷泉、钟塔 | 4 |
| **512** | 石亭、民居B、谷仓、民居A、市集摊、圆形石台、民居C、店铺、小亭、花树、木藤架、断裂石柱、缠根岩、青水晶簇、符文石 | 15 |
| **256** | 农用推车、石阶、雕花路灯、石凳、旗帜立柱、桶箱堆、花箱 | 7 |

26 件合计约 **5.4 MB**（DXT1 含 mipmap）；一律 1024 约 13MB，分档后少一半以上。包体预计 59MB → 约 **64MB**。

Tripo 侧不必正好按这个分辨率出图——**出得比目标大没关系**，导入器会降采样到分档上限；
出得比目标小则无法补救，所以 `standard` 是下限而非上限。

## 还要注意

- 贴图另存为 `Textures/tripo_<name>.png`，文件名**不含** `handpainted`，构建器按 **Clamp** 导入——图集 UV 要 Clamp，平铺才要 Repeat。
- 所有 Tripo 件一律作为**非行走装饰**，不进导航网格。导航顶点 **4037 / 4095**，余量只剩 58。
- 拿不到贴图时导入器会自动 Smart UV Project 展 UV 并按 `FALLBACK_MATERIAL` 上调色板色兜底，但只保证能看体量。
- 帧率必须实机验证。
