# 程序化低模替换清单

2026-09-09。目标：用 Tripo3D 模型替换观感较差的程序化几何。下面的数量、尺寸、面数全部从
`sky_island_layout.json` 与 `sky_island_geometry.json` 实测统计，不是估计。

当前场景：**1,355,134 可见三角面 / 753 渲染器 / 导航 4037 顶点（上限 4095）**。

## 一、不能替换（换了会坏功能）

| 对象 | 生成处 | 为什么不能换 |
| --- | --- | --- |
| 岛体壳与地表 | `island_shell` / `terrain_and_boundary` | 它本身就是**可行走面**，提供 27 个 ground MeshCollider，并且是 A\* 导航网格的来源 |
| 路径铺装 | `make_paths` | 同为可行走面，参与导航三角化 |
| 桥面 | `bridge_details` 与桥体 | 导航关键路径。**导航顶点 4037/4095，余量只剩 58**，任何顶点数变化都可能直接超限 |
| 云海 | `world_clouds` | 依赖 `SkyIslandCloud.shader` 的漂移、三档空气透视与 `_CloudLayer` 远景雾底；换成普通网格就没有昼夜天色了 |

## 二、可以替换：碰撞与视觉是解耦的

这是本清单成立的前提。`generate_sky_island.py` 里碰撞来自
`collision_box(obs['id'], obs['center'], obs['size'])`——**读的是 layout 登记的中心与尺寸**；
而 `house()`、`tree()` 之类只负责画外观。因此只要 Tripo 模型按登记 footprint 缩放，
换掉外观不影响碰撞、不影响导航。

## 三、不建议用 Tripo 的部分

**774 个小散件（灌木球 327 / 石块 219 / 花球 228）和 3,502 个 Kenney 自然素材。**

它们观感差的原因不是"模型简陋"，而是 **`smooth=False` 加上 8 段 4 环的低分段**——
棱角是着色方式造成的，不是面数不够。改 `sphere()` 的调用参数即可：

- 现在：`sphere(..., 8, 4, False)` = 64 面，硬边刻面
- 改成：`sphere(..., 12, 6, True)` = 144 面，平滑

774 个散件按此改动只增加约 **6.2 万面**，就能消掉绝大部分"刻面感"；
而换成 Tripo 模型要增加约 **26 万面**，还要额外 774 份贴图采样。**性价比差一个数量级。**

Kenney 自然素材（草、花、蘑菇）单个只有几十面且屏幕占比极小，换 Tripo 纯属浪费预算。

## 四、面数账

| 方案 | 净增面数 | 场景总面数 | 相对当前 |
| --- | ---: | ---: | ---: |
| 只换树 + 建筑 | +112,000 | 1,467,000 | +8% |
| 再加地标 + 掩体 | +130,000 | 1,485,000 | +10% |
| 再加石块 | +204,000 | 1,559,000 | +15% |
| 全部换（含灌木花球） | +380,000 | 1,736,000 | **+28%** |
| 散件改平滑（不用 Tripo） | +62,000 | 1,417,000 | +5% |

**建议走「树 + 建筑 + 地标 + 掩体用 Tripo，散件改平滑」**：合计约 +19 万面（+14%），
覆盖了几乎全部视觉冲击，而把 327 个灌木球换 Tripo 那 16 万面省了下来。

## 五、实现要点

替换与新增不同：新增只要 `addmesh` 就行，**替换需要抑制原来的程序化绘制**。
对建筑类是在 `generate_sky_island.py` 的障碍循环里，当该 `obs['id']` 有对应 Tripo 件时
跳过 `house(obs, index)` 改为 stamp Tripo 网格并按 `obs['size']` 缩放；
`collision_box()` 照常先调用，因此碰撞不变。树与散件同理，在各自的散布函数里分流。

按 footprint 缩放与目前的按高度缩放不同，`sky_island_tripo_import.py` 需要增加一个
"按 XZ 占地缩放、高度随比例"的模式，否则 43×23 米的寺庙会被按高度压成错误比例。
