# 天空岛剧情与持久化

2026-09-08，分类 `COMPAT / SCHEMA+`。天空岛使用独立槽位故事，不借用鸭王征程章节或关系好感字段。

`SkyIslandStoryRules` 是无 Unity 依赖的候选状态规则。先完成 D 与 D_02 两组再修复风标，完成 G 与 G_02 两组再修复星灯，两个方向没有先后要求；双航标开启归航钟庭资格。钟守可以战胜，也可在旧信、航路图、观星镜、折翎和解齐备时和解，最后一次敲钟写入结局。通关之后可以重访、补种植支线和手记，不能反复领取同一叙事解锁。

四条支路消费 `Search_S1` 至 `Search_S4`：种植记录、旧信、航路图、观星镜。种植记录允许先捡后交；旧信加航路图允许与折翎和解。明确挑战开始不会写永久敌对，只有实际战胜才提交结果。折翎和解与战胜、钟守和解与战胜分别互斥；道路与结局不依赖 NPC 实例存活。K1 / K2 / K3 分别要求风标、星灯、双航标。世界交互、门与实际战斗回调由 `SkyIslandSession` 接线。

固定存档 key 为 `BossRush_SkyIsland_Story_v1`，`schemaVersion = 1`。DTO 保存 `flags`、`visitedRegions`、`clearedEncounters`、`discoveredNotes`。区域位 0–7 对应 A–H，位 8–11 对应 S1–S4；掩码含义与枚举位在发布后冻结。奖励是道路、陈设和叙事记录，不创建 TypeID、货币或经济物品。

`SkyIslandStoryService` 每次会话持有一个 `BossRushSlotJsonStore` 与 `BossRushSaveCoordinatorEngine`，复用共享 parser / writer。动作先构造副本，通过 Store 后再公开候选事实；提示区分“已记录，待保存”和完成物理同步。独立出击地图通过 `Tick(safeToFlush)` 显式传入非战斗条件，协调器允许非基地写盘；重试也走受该条件保护的 `RequestFlush`，不用只在基地运行的共享 `Tick`。退出用 `SkyIslandStorySaveRecovery.CloseOrRetain`，官方存档繁忙或物理保存失败时保留服务与订阅，每秒重试；重试成功或槽位改变后释放，宿主销毁时最后尽力保存。有同槽恢复 owner 时入口应等待，避免两个 store 覆盖同一 key。

未知版本、损坏 JSON、错误字段类型和互斥结局进入共享写屏障，原 key 不覆盖；换槽与同槽删档使旧会话失效。没有 Unity 对象写入存档，也没有每次入岛重置剧情。

正式内容表 `Assets/Data/SkyIsland/World.json` 由 `SkyIslandContent` 经共享 `JsonDataRegistry` 严格加载：15 组遭遇的 ID、作者 marker、手动挑战标志完整且唯一，每组 1–4 人；K1 / K2 / K3 / BellCourt / ZhelingPass 的进度条件冻结。缺失、重复、未知字段或版本、错误绑定都整表回退，不让半张表漏掉必需遭遇。Source 为 `Json` 或 `Fallback`，回退有正式构建可见的去重错误日志。

`SkyIslandEncounters` 的死亡事实保存在普通 `SkyIslandEnemyRecord`，不随官方延时销毁的角色本体消失。一组全部死亡后按每秒一次提交清场，直到存档 predicate 接受；提交失败时不重刷已死敌人。没有死亡回调却失去角色对象时，只补那个未死槽。`IsCleared(D/G)` 聚合两组，构造器 predicate 仍必须查询单组 ID；`HasLivingEnemies` 同时覆盖生成中/待补位的遭遇，为保存提供保守安全门。

正式出击直接启用官方 `dropBoxOnDead`，沿用官方箱子、经验与魂路径，不再二次搬运 CharacterItem。在途 preset 只由 await 的局部 owner 持有，退出时等迟到角色返回再回收；已生成角色上的 `SkyIslandEnemyLife` 负责生命事件与 preset，角色清理后延后 0.1 秒销毁 preset，避免其他 OnDestroy 仍需读取它。准备阶段失败的角色通过 finally 回收。

剧情执行回归直接链接真实规则、Codec、Service、Content、共享存档与协调器，96 条断言通过；遭遇回归直接链接完整生产 owner，28 条断言通过。覆盖正式 JSON、先死后销毁、提交重试、缺 Health、迟到创建与取消；Unity、异步工厂和存储替身不能证明实机交互、官方掉落与 ES3 实盘。入口为 `python tools/run_runtime_regressions.py --filter SkyIsland`。最终 Windows 全 Mod 编译、实机进出与战斗验收以本轮总体交付记录为准。

## 独立出击加载、取消与返航

`SkyIslandRaidLease` 预载独立 `sky_island_raid` 场景包，经官方 SceneLoader 加载 `BossRush_SkyIsland`。
最小关卡装配归租约：在 sceneLoaded 配置关闭状态的 SkyIslandLevel 根、天气与初始 Buff 集合、A* 后才激活官方服务。
即使 Session 在加载中销毁，租约仍须完成这一步，避免官方状态机永远等不到 LevelManager。
Session 只绑定地形、登记导航初始化等待、准备碰撞与图；完整路径校验后建立实体/导航门，再解除初始化屏障。

加载失败与外部切图先取消路径并 Dispose 扫描迭代器，再解除官方初始化等待；返航开始停止旧 Build。
取消后可等待官方初次加载完成，再直接返基地，不再生成居民或遭遇。
完整官方死亡任务拥有墓碑、物品损失与返航；OnPlayerDied 只暂停本地图玩法、隐藏 UI 并保存已提交故事。
环境声音在返航开始和死亡回调即停，不等 emitter 随旧 Scene 销毁。

正常返航保留请求直到成功，失败按租约节流重试。Session/宿主消失后，租约用独立持久的 SkyIslandRaidRecovery 接续安全返航；
玩家已死亡时 recovery 等官方死亡任务，不触发第二次撤离。只有目标 Scene 已卸载且本租约发起的加载/返航任务已完成才释放 bundle。
故事保存同样可由独立 SkyIslandStorySaveRecovery 接续，不把待保存记录挂回正在销毁的宿主。

`SkyIslandRaidLease` 生产执行回归 30 条断言通过；覆盖加载中关闭、迟到服务装配、回调/卸载顺序、死亡归属、返航失败重试、清理，以及激活前合同失败 → 不启动官方服务 → 有界返航 → 归还令牌 → 可重入。
这仍是官方加载器与 Unity 替身测试，真实场景切换和死亡验收以游戏 smoke 为准。

### 撤离规则（2026-09-08，CR-2026-09-08-002）

撤离只有一条路：走进撤离圈并停满 3 秒，离圈取消倒计时。判定收敛为 `SkyIslandSession.IsInsideExtraction()` 单一事实源，半径与秒数是 `ExtractionRadius` / `ExtractionHold` 两个常量；码头恒开，归航钟庭要求敲钟结局（`BellExitIfUnlocked()`）。

**地图不提供任何返航入口**（2026-09-09 起地图已换成官方 M 键地图，撤离点位置改由世界里的撤离圈本身指示）。旧版地图面板上的「立即返回基地」允许玩家在任意位置、战斗中、借地图暂停发起完整撤离（官方 `notifyEvacuation:true, saveToFile:true`），绕过出击损失与暴露时间约束，已删除。Dev 场景实验面板与初始化失败恢复各自保留内部返回入口，不经玩家可达路径。`SkyIslandPlayerEntryGuard` 以反例断言钉住：`OpenMap()` 内不得出现 `Close(` / `returnToBase` / `ReturnToBase`——打开地图不得夹带任何返航动作。

### 初始化失败的可观察终点（2026-09-08，CR-2026-09-08-005）

官方 `InitLevel` 的异常不会传给等待 `LevelInited` 的外层加载，外层会一直等下去。桥接因此对官方 `SceneLoader.LoadScene` 状态机的 `MoveNext` 做 transpile，把那**唯一一处** `LevelManager.LevelInited` 读取换成会在失败时抛 `OperationCanceledException` 的 `LoaderLevelInitialized`；`NotifySaveBeforeLoadScene` 的前缀则保证半初始化的角色不覆盖出发前的官方快照（玩家已死亡时照常保存）。

令牌归租约：`Prepare` 领取、`OnSceneLoaded` 绑定场景并在**激活官方服务之前**跑 `SkyIslandOfficialContract.VerifyBeforeActivation`（provider 唯一且启用、SubScene 位置表、出生点与缓存一致、导航不超过 4095 顶点），装配异常与会话超时/取消都经 `Abort` 发信号，`TryRelease` 归还。**令牌漏还会让下一次进岛在 `Prepare` 直接抛「上一段初始化尚未释放」**，夹具专门为此留了重入断言。

## 天空岛环境与装置反馈（2026-09-08，COMPAT / WIRE+）

`SkyIslandAmbience` 是 `SkyIslandSession` 独占的环境 owner。它只创建风铃集、风标、星灯、观星镜、菜畦和归航钟六组装饰节点；不会停用地图区域根对象、碰撞体、敌人或交互点。每帧集中更新近处光丝旋转和呼吸光，每 0.25 秒按玩家距离调度一次，以 38 米进入、44 米离开的滞回控制灯光与声源。没有每个节点各自运行的 Update，也没有全图扫描协程。

风标、星灯、观星镜、菜畦与终章的可见反馈直接从已提交的故事 flag 重建。首次载入记录只恢复状态；后续新增 flag 才在玩家附近触发装置和弦或归航钟声。风铃集每隔约 13 秒响一组轻风铃，修复后的风标播放近域风声；它们经官方 `AudioManager.PostCustomSFX(path, emitter, loop)` 使用游戏音效通道。离开区域或会话回收前，显式调用该 emitter 的官方 `AudioObject.StopAll`，再停用/销毁对象，因为不能假设 AudioObject 的销毁自动停止 programmer sound。

原创音频由 `tools/gen_sky_island_sfx.py` 使用标准库合成，可重新生成到 `Assets/Sounds/SkyIsland/`；`--check` 校验 PCM 格式、帧数、峰值与首尾零交叉。四个文件为 `island_wind.wav`、`wind_chimes.wav`、`homecoming_bell.wav`、`device_awake.wav`。真实游戏 DLL 已核对音效/停止签名与 StopAll 内部调用；听感、空间衰减与实机反复进出仍属于人工验收，静态检查不替代听音验证。

引用：`DebugAndTools/SkyIsland/SkyIslandAmbience.cs`、`tools/gen_sky_island_sfx.py`。

## 官方时钟光照（2026-09-08，COMPAT / WIRE+）

`SkyIslandLighting` 在独立天空岛 Scene 内创建自己的 Directional Light 与 LightControl Volume，不再经 `ArenaPrototypeLighting` 扫描、借用基地 SodaPointLight 模板。Session 调用无参 `Tick()`；默认读取 `GameClock.TimeOfDay.TotalHours`，不写官方时间。5–7 点星夜渐变至晨光、7–10 点晨光渐变至晴昼、16–19 点晴昼渐变至暮色、19–21 点暮色渐变至星夜，其余为昼夜稳定区间。颜色与强度使用平滑权重，日照旋转使用四元数插值，午夜没有换档跳变。

导览牌的手动循环为自动 → 晴昼 → 暮色 → 星夜 → 晨光 → 自动；固定档持续到再次切换或离岛。材质全局光色、实际角色日光与 Volume 使用同一次混色结果。日光/Volume/profile 全属地图会话；只有原 Scene 仍加载且仍活动时才能返还 RenderSettings。专用 Shader globals 另用 owner 标记，迟到清理不能覆盖下一会话。

`tests/fixtures/SkyIslandLighting` 链接完整生产类与真实游戏/Unity DLL，仅执行无引擎 API 的时间插值，64 项断言覆盖四时段锚点、午夜、边界连续、异常与跨日输入。场景实际观感、Volume 生效与切图清理仍需 Unity 实机。引用：`DebugAndTools/SkyIsland/SkyIslandLighting.cs`、`tests/fixtures/SkyIslandLighting/`。

## 剧情门几何与导航回归（2026-09-08）

`SkyIslandGates` 的 K1/K2/K3/BellCourt/ZhelingPass 分别横断真实桥 K1/K2/K3/EH/FG。实体门使用旋转 BoxCollider，A* 使用该 collider 的世界 AABB 与三角形 AABB 相交，封锁属于本地图的三角形；开门恢复原 walkability。`tests/SkyIslandGateNavigationPropertyTest.py` 直接读取生产 Add 调用的坐标、朝向、宽度与真实 layout 导航，校验物理 OBB 覆盖整幅桥宽，并枚举全部 32 种开闭组合。初始 D/F/S2/S3 可达、H 不可达；全部故事 flags 打开后全图连通。五门各封 6/6/6/16/9 个导航三角形，均未碰到其他岛桥区域。

五项负向探针覆盖移门离桥、沿桥纵向放门、缩窄门、门高程错误和放到邻岛，全部被拒绝。它验证几何与连通性，不代替 Unity 实体碰撞和 A* 工作项实机执行。当前门多靠近解锁一端：K1/K2 分别距 D/G 约 8 米，K3 距 E 约 8 米；从 B 进入关闭的捷径会先走过较长桥段。实机导览与近桥提示应明确捷径锁定状态。

验证补录：2026-09-08 按用户要求不进入游戏测试；Windows编译、572项全量守卫及7套天空岛回归通过。Session在sceneLoaded与正式设置活动场景之间显式等待自己的活动scene handle和官方相机，再创建光照，避免协程与UniTask恢复顺序影响初始化。

桥头提示补录：五桥两端共10块独立木牌显示开门条件或已通行，开放后继续保留。使用作者木材质与游戏TMP字体；位置基于真实桥口向岛内偏移并检查地面，Apply更新文字、Dispose独立回收。最终Release编译及相关guard通过。

## 进出岛：与原版同一条流程（2026-09-09）

入口挂在基地**原有船点**的交互组上（`SkyIslandRuntimeModule` 找 `IsBaseHubBoatInteractable`），
走的是官方 `SceneLoader.LoadScene`、真实 `LevelConfig` / `LevelManager` / `MultiSceneCore`，
因此 `isRaidMap` 为真、`RaidUtilities.NewRaid()` 照常触发，死亡完全交给官方 `CharacterDieTask`。

两处观感必须与原版对齐，已在 `SkyIslandRaidLease` 里对齐并由守卫钉住：

- **进图**用 `clickToConinue: true`，与官方 `MapSelectionView.LoadTask` 一致：读条完停在「点击继续」。
  用 false 会把玩家直接甩进战斗区，和原版任何一张地图都不一样。
- **撤离**照抄官方 `SceneLoaderProxy.Task` 的顺序：`NotifyEvacuated`（顺带让主角在结算期间无敌）
  → `ClosureView.ShowAndReturnTask(1f)` → 幕布换成 `EvacuateScreenScene` → `LoadScene`。
  结算画面是表现层，失败也必须 fail-open 继续返航，不能把玩家留在图里。
  官方自己会在 `SceneLoader.LoadScene` 内部再 notify 一次，这个「两次」是原版既有行为，如实照搬。

仍与原版不同、属于有意的产品决定：**天空岛出击免费**（原版 `MapSelectionEntry.Cost` 会扣费），
且**没有目的地预览与确认面板**——与船点交互即开始加载。

2026-09-09 对照官方 `CountDownArea` / `SceneLoaderProxy` 复审后补齐三处（`SkyIslandPlayerEntryGuard` 钉住，五条人为破坏逐条转红）：

- **撤离圈在官方界面打开时不推进**：判定行带 `View.ActiveView == null`，开着背包站在圈里不会被送回基地。
- **返航派发即封锁输入**：`Close` 先 `BlockInputForReturn()` 再派发；封锁源是岛场景内临时对象，随场景卸载解封，`Cleanup` 也销毁它。
  不能挂在 DontDestroyOnLoad 的宿主上——`InputManager` 只在源对象销毁/失活时解封，否则回基地后输入永久锁死。
- **官方加载器拒绝时立刻失败**：`SceneLoader.LoadScene` 遇 `IsSceneLoading`/身份未登记只记 LogError 就同步返回，
  等 root 的循环观察 `lease.LoadFinished`，按「未起航」清理，不空等 120 秒、不发起多余的回基地加载。

仍是已知差异：官方倒计时控件 `EvacuationCountdownUI` 未复用（HUD 文本倒计时）；服务根/地形根由 Mod 在 `sceneLoaded`
之后才激活，先于租约订阅的处理器看到的是没有 `LevelManager` 的场景。新增一张官方级 Mod 地图的完整流程见
`docs/制作教程/从零搭建自定义场景_Blender到Unity到Mod完整教程.md` 第 21 节。

`LevelManager.loadLevelBeaconIndex` 不需要设置：它被消费后自清零，且找不到 `StartPoints_N` 时
会回退到 `StartPoints`，天空岛只有一个出生点。

## 地图：用官方的，不自绘（2026-09-09）

官方地图系统是**纯场景数据驱动**的：`MiniMapDisplay.AutoSetup()` 就是一句
`FindAnyObjectByType<MiniMapSettings>()`，`MiniMapView.OnOpen()` 每次开图都会重跑它，
而玩家侧的开合走 `CharacterInputControl.OnUIMapInput -> MiniMapView.Show()`。
换句话说，让一张新图支持官方地图**不需要写任何运行时代码**，只要场景里有那份数据。

天空岛原先没放，于是 `MiniMapView.Open()` 里的 `MiniMapSettings.Instance == null` 早返，
官方地图键在岛上是**死键**，Mod 反而自绘了一整套 F6 界面。现在已改正：

- 场景包里带一条 `MiniMapSettings.MapEntry`（sceneID / sprite / imageWorldSize / mapWorldCenter），
  由 `SkyIslandRaidBuilder` 在构建独立出击场景时装配；
- 贴图由 `tools/build_sky_island_minimap.py` 从 `layout.json` 的地面三角**离线烘焙**，
  和导航面用的是同一份权威几何，地图轮廓与实际可走地面不会对不上；
- Mod 侧删掉 `SkyIslandMap.cs`（自绘 UI）与全部 F6 输入处理，只在航路图交互体和 F3 菜单里
  保留一个 `MiniMapView.Show()` 的同等入口。

三个必须记住的坑：

1. **`combinedSprite` 要留空**。设了它就走 combined 通道，而 `SetupCombined` 会把 `sceneID`
   清成空串，让 `TryConvertWorldToMinimap(worldPos, sceneID, …)` 按 sceneID 找不到条目。
2. **不要放 `MiniMapCenter`**。它的 `Cache()` 会用自己的 transform 覆盖 `mapWorldCenter`，
   和离线烘焙出来的中心打架。
3. **`GetSceneID(int)` 需要桥接**。官方的「居中到玩家」走
   `GetSceneID(GetActiveScene().buildIndex)`，bundle 场景恒为 -1 且天空岛刻意没进全局 `entries`，
   原实现只会返回 null。桥里补了第三个 prefix，但它按「**当前活动场景**是天空岛」判定，
   绝不能写成「buildIndex == -1 就返回天空岛」——那是被禁的全局 -1 别名，
   `SkyIslandSceneReferenceBridgeGuard` 与隔离回归两侧都钉了这条。

**分区「未探索」灰显保留了下来，而且是纯数据实现**：场景包里放的是 1 张底图（全岛暗灰剪影，永远显示）+ 12 张分区彩色图层。`MiniMapDisplay.Setup` 里有
`if (cur.Hide) showGraphics = false;`，`OnOpen()` 又每次都重跑 `AutoSetup()`，
所以运行时只要按存档的 `visitedRegions` 翻 `hide` 就行——不重绘贴图、不要可读纹理、
不接管任何官方界面。owner 是 `SkyIslandMapFog`，装配时刷一次、每新到访一个区域再刷一次。
图层按 **sprite 名字**认领而不是列表下标，下标会随烘焙输出顺序漂移。

守卫：`tests/SkyIslandMiniMapGuard.py`（贴图 sha256、覆盖范围复算、图层初始 hide、认领方式）与 `tests/SkyIslandMiniMapLayerAlignmentPropertyTest.py`
（按官方那三行摆放公式把 12 张分区贴图贴回底图坐标系，与全彩参考图逐像素比对，实测 0.000% 错位——`imageWorldSize` / `offset` 因此不必等实机确认）。

## 物资搜集、敌人档次与噬风（2026-09-09，COMPAT / SCHEMA+）

本轮把交付文档留作「后续内容定稿」的经济与战斗深度补齐，**不新增 TypeID、不重建场景包**。

### 搜刮点

`SkyIslandScavenging`（Session 持有）+ `SkyIslandLootTables`（纯逻辑内容表）。39 个锚点覆盖 8 主区与 4 支路：
生活物资 11（A/B/C）、航务补给 18（D/E/F/S1–S3）、星工遗存 10（G/H/S4）。锚点写成
「已有作者标记 + 方位角 + 距离 + 档次」，进图时一次解析成落点，四道检查任一不过即跳过该点：
地面射线命中本图地面、无墙体胶囊阻挡、距任一玩法标记 ≥ 4.5 m、距其它已落位点 ≥ 3 m。

玩家进入 72 m 才建箱，每 0.5 s 最多建一个（4.12 门控）。内容按 `(raidSeed, anchorId)` 固定：
同一次出击离开再回来是同一份，重新出击才重新 roll；不进存档。开箱进度经官方
`InteractableLootbox.OnStartLoot` 记账（订阅/退订成对），HUD 第三行显示「物资 已搜/可搜」。
**刻意不在地图上标搜刮点**——值钱的东西要靠走出来。

档次只决定品质带（1–3 / 2–5 / **4–8**）与件数（1–2 / 2–3 / 2–4），池子来自官方 `ItemAssetsCollection`。
件数与品质带必须**同向递增**：件数曾经是 2–3 / 2–4 / 2–3，中段的航务补给比全图最深处出得还多，而当时守卫一个件数都没钉。现在 `check_loot_anchors` 解析方法体逐档比对并断言单调不减。
游戏一共 8 档品质，最深一档必须够得到顶档，否则第 8 档物品在天空岛永远刷不出来。

池子的**形状与排除口径与既有 Boss 奖池一致**：逐个官方 tag 做 `requireTags` 再取并集
（只给 `excludeTags` 会把无 tag 的占位件、内部道具、无标签任务件整批放进来），
排除标签统一来自 `Config/LootExcludeTagPolicy.cs`——`DestroyOnLootBox`、`DontDropOnDeadInSlot`、
`LockInDemoTag`、`Quest`（本版本不存在，保留反射），天空岛另加 `Special` / `Character` 收窄。
Boss 奖励箱、通关奖励、空投与搜刮点现在共用这一份列表，`LootBlacklistRegistry` 仍是按 TypeID 的第二道闸。

箱子本身走 `SkyIslandRewardCrate` 唯一建造点。官方 `CreateLocalInventory()` 只 `AddComponent<Inventory>()`，
既不设容量也不设 `NeedInspection`（字段默认 false），因此建箱后必须显式补上 `needInspect` /
`NeedInspection` / `SetCapacity`——不补就得到「开箱即全明牌、没有鉴定过程」的箱子，
与本 Mod 其余三条建箱路径和原版口径都不一致。

### 敌人档次与噬风

`SkyIslandEnemyTier` 是无依赖枚举文件，内容表与运行时装饰共用。`Tier` / `Lead` 两个字段让每组
区分「带队者」与「随从」：D / G / S4 的带队者是断风游猎（Elite），折翎与钟守是 Champion，
新增手动组 `Storm` 是噬风 + 2 名断风游猎。

噬风血量 ×13、模型 ×1.9、风暴染色，相位阈值 0.80 / 0.60 / 0.40 / 0.20（四次），预警 1.4 秒后放三波扩张范围伤害（7 / 8.5 / 10 m）并提速，击败后原地留星工遗存箱。
原值是 ×18 + 两档相位 + 9 m / 1 s 预警：整场是「打很久的血包 + 两次特殊时刻」，而且官方
`ExplosionManager.CreateExplosion` **没有距离衰减**，从圈心跑出 9 m 只有 1 秒（需 9 m/s），
贴脸的近战流在数学上必吃满三段 114。现在 7 ÷ 1.4 ≈ 5 m/s，正常跑动可达；守卫直接断言这个比值 ≤ 5.5。它**可选**，但击败后成为说服钟守的第五条路线（原路线要四件物证齐备）。

两条容易踩空的实现口径：

- **预警是贴地圆环**（`LineRenderer`，半径 = 真实作用范围，后两波在 0.45 s 间隔里提前画出）。
  俯视视角下点光源读不出 AoE 边界，而三波 38 伤害站在中心必死。半径只有 `RadiusForWave`
  一个来源，圆环与伤害不会漂移。
- **改档次的 `nameKey` 必须同时打开 `characterPreset.showName`**：`HealthBar` 有
  `if (!characterPreset.showName) return;` 的门控，普通拾荒者 preset 上它是 false，
  只改 `nameKey` 血条上根本不显示。精英与 Boss 显式打开，`Scav` 保持匿名。
  连带影响：官方在主角击杀时会 `SavesCounter.AddKillCount(nameKey)`，那是写进正式存档的
  `Count/Kills/<key>`，所以天空岛击杀记在自己的键下，**不再计入**官方拾荒者击杀数，
  `RequireEnemyKilled` 解锁与击杀类任务也不会推进。
  因此 **`Scav` 一律不改名**（2026-09-09 可玩性复审）：它的 `showName` 恒为 false，
  自定义名玩家根本看不到，却要付出「击杀白打」的代价；自动组改成按出击刷新后这批击杀会反复产生，
  代价更大。精英以上仍用自己的 key，模组内容本就该独立计数。

三张倍率表（血量 / 伤害 / 反应）必须**随档次严格递增**。Champion 曾经是 2.2 / 1.3 / 1.25，
比守航标的 Elite（2.6 / 1.35 / 1.3）还软——折翎是单挑的主线对手，却比路上的杂兵小队更弱，
而守卫当时只钉了「伤害封顶 3」这条赋值语句在位，一个数字都没钉。现在是
Scav 1 / Elite 2.6 / Champion 4.5 / Storm 13，守卫解析方法体逐值比对并断言单调。

数值层是乘法（血量 `*=`、反应时间 `/=`），重复施加会复利（13 倍血跑两遍就是 169 倍），
因此档次与 AI 调参各有一个一次性标记组件；两者必须分开，`AICharacterController`
常常就挂在角色本体上，共用一个标记会让先跑的 `ApplyAi` 把后跑的 `Apply` 一起挡掉。

新增 flag `StormSlain = 32768`（`KnownFlags` 32767 → 65535）。旧档读出为 0，语义即「尚未挑战」；
Codec 拒绝「已击败但航标没亮」这种不可能状态。

### 居民服务与航务委托

`SkyIslandServices`（Session 持有）提供渡口整备、苔药调理（按缺失血量比例计价、回满生命、冷却 300 s）、
归航菜（交还种植记录后每次出击一份 `MaxHealth` / `RunSpeed` / `WalkSpeed` 加成，销毁时统一摘除）。
三项都**不依赖官方 `StockShopView`**——它是场景内预制体，独立出击关卡不保证存在。

经济口径必须跟着官方，有三条：

- **渡口整备按官方公式计价**：`ceil(Value × 修复量 / MaxDurability × 0.5)`，即按**物品价值**，
  不是按耐久点数。价值无关的「每点 N 元」盈亏平衡点落在 `Value = 6 × MaxDurability`，
  高价值武器会被卖得比官方维修台便宜一到两个数量级，廉价高耐久护甲反而更贵。
  岛上只额外压一个服务费下限。
- **整备同样累加永久磨损**（`DurabilityLoss += lostPercentage`，写法同官方 `ItemRepairView.Repair`）。
  官方每修一次都会永久削一点上限；不跟就等于开了个「又便宜又无损」的修理站，
  把官方设计的装备损耗沉降口整个架空。
- **付费的账户门控读 `LevelConfig.accountAvailable`**，官方 `ContextualMoneyAndCash` 也用它决定
  是否显示账户余额。**不要**用 `SaveCharacter`：那是「是否把主角写回存档」，raid 图里同样为 true
  （天空岛的官方合同还硬性要求它为 true），拿它当账户门控恒真、等于没门控。
  天空岛场景包目前没有显式关掉 `accountAvailable`（序列化默认 true），所以现在账户是可以花的；
  要改成只收现金，把作者场景那个字段设为 false 重打包即可，代码侧会自动跟随。
- **苔药按缺失血量比例计价**（2026-09-09 可玩性复审）：`HealPriceFor` = `max(60, ceil(480 × 缺失比例))`，
  冷却 120 s → 300 s。旧口径是「120 定额 + 全额回满 + 120 s 冷却」，叠加上一条的「账户可花」，
  等于岛上根本没有血量压力：只要有钱就能无限满血。用**比例**而不是按血量点数，报价与玩家
  `MaxHealth` 的实际量级无关，官方改血量或玩家吃了上限加成都不用重算。

归航菜是免费的，因此只补「上限涨出来的那一截」而不回满血——免费全回会让付费苔药永远没人买。
归航菜同时挂在**青穗梯田的菜畦装置**上（2026-09-09 补）：晴禾是 `isPermanent` NPC，与玩家结婚后
由婚姻系统接管、不再上岛（`SkyIslandResidents.SpawnOneAsync` 跳过生成，`PermanentDuckNpcModule`
对 `SkyIslandRaid` 恒返回 false），此前只挂在她身上的归航菜会**永久失联**。苇白的委托早有留言板
兜底，这条纪律必须对称。`mealUsed` 是单次布尔，两个入口不会双领。

`SkyIslandBounty` 是纯逻辑的可重复委托：清理威胁 / 回收补给 / 巡视区域三选一，进度按接单基线相减，
目标随完成单数递增，第三单起谢礼升到星工遗存档，单次出击最多 3 单。按出击计、不进存档。
委托同时挂在风铃集留言板装置上，苇白婚后离岛也能接能交。
谢礼箱按轮次错开落点（`BountyRewardBearing + round × 120°`，距锚点 3 m，走
`SkyIslandRewardCrate.TryFindCratePosition` 的地面/墙体裁决）：交单锚点是苇白本人或留言板，
直接落在锚点上会把箱子塞进 NPC / 告示牌里抢同一次交互选择，而三轮锚点完全相同、箱子会一摞叠住。

**三个计数器的信号源寿命不同，这是本系统最容易出错的地方。**
回收补给与清理威胁数的都是**按出击刷新**的东西（搜刮点重 roll、自动遭遇重新生成），
而巡视区域的源头是**持久存档事实**：区域走过一次就永久记进 `visitedRegions`
（`RecordRegionVisited` 对已访问区域返回 false）。于是走遍群岛之后，巡岛类的
**本局可完成量可能是 0**。

> 2026-09-09 可玩性复审前，清理威胁也属于「持久事实」那一类：`RemainingClearable` 用
> `!completed(id)` 过滤，第二次进岛起恒为 0，这类委托永远派不出来。自动组改成按出击刷新后
> 该过滤必须一并去掉，否则改了生成、没改可完成量，委托侧仍然是死的。

因此派单前必须用 `SkyIslandSession.AvailableBountyProgress(kind)` 与本轮目标比对，
只挂出做得完的单；这些量随进度单调递减，接单时 `available ≥ target` 就保证这一单做得完。
另外苇白永远提供**退单**（`TryAbandon`：让出委托槽，不计完成数、不给谢礼，重新接单会重取基线），
作为门控疏漏时的兜底——没有退单，一张做不完的单就会把本局委托槽卡死一整局。

## 可玩性复审修复（2026-09-09，COMPAT）

以可玩性为口径把上一轮内容扩充复审了一遍。**核心一条：这张图跑完一遍之后不再是出击图。**

### 遭遇按出击刷新（最要紧的一条）

13 组自动遭遇全部走 `clearedEncounters` **永久**抑制生成（`Tick` 里那句
`if (!encounter.Started && completed(encounter.Id))` 短路），而 39 个搜刮点每趟重刷。
于是第二次及以后进岛 = **零敌人 + 约百件产出（含 ~25 件品质 4–8），无限重复**：
一张 raid 图退化成无风险刷宝台。编译、当时的守卫和执行回归都查不出来
——fixture 只在**同一个 owner** 上验证「清完不重生」，从没构造过第二次出击。

修法是把短路条件收窄到手动组：

```csharp
if (!encounter.Started && encounter.Manual && completed(encounter.Id)) { encounter.Cleared = true; continue; }
```

- 自动组每趟重新生成，风险回来了；具名剧情对手（折翎 / 钟守 / 噬风）语义不变，仍是一次性。
- **存档 schema 一个字节没动**：`clearedEncounters` 照旧写、照旧幂等，只是对自动组改为
  「剧情装置的前置证据」（修风标要 D + D_02、修星灯要 G + G_02、校准观星镜要 S4），
  一次达成永久有效，重刷的敌群不会把已完成的装置重新锁上。回退到一次性清场也不丢数据。
- `RemainingClearable` 必须同步去掉 `!completed(id)` 过滤，否则生成改了、可完成量没改，
  「清理航路威胁」委托从第二趟起永远派不出来。
- fixture 补了两组 **returning raid** 场景（新 owner + 预填 `Saved`）：自动组重新生成、
  手动组仍被短路、重清仍记一次账。

### 剧情面板的战斗门

面板走共享模态租约把 `Time.timeScale` 压到 0，而这个暂停**是可靠的**——
`ModBehaviour.LateUpdate` → `LateUpdateZombieModeRuntime` → `EnforceModalInputPause()`
排在官方 `TimeScaleManager.Update()` 之后，Unity 保证所有 Update 先于所有 LateUpdate。
于是它就是一个战斗中随手可用的免费暂停键，而且面板里还挂着眠苔的苔药与浮舟的整备
——可以定格战斗再花钱回满血。这不是理论问题：五个自动遭遇的生成点本身就是搜索点
（`Search_C_02` / `D_02` / `E_02` / `F_02` / `G_02`），眠苔站在 `POI_D`、距 `EnemySpawn_D` 只有 47 m。

`SkyIslandSession.CanOpenStoryPanel` + `SkyIslandEncounters.HasLivingEnemiesWithin(point, 35f)`
挡住打开时机，`SkyIslandWorldStory.Tick` 在面板已开而条件转假时自动收起
（在途 async 生成会在 `timeScale = 0` 下继续完成）。

按**半径**而不是全图判定：`HasLivingEnemies` 是全图口径，玩家把一组敌人丢在岛的另一头
就会让全岛剧情交互永久不可用——那是死锁，不是门控。

## 同点交互、爆炸遮挡与相位复利（2026-09-09 可玩性复审第二轮，COMPAT / WIRE+）

同一天的可玩性复审分两轮。上一节是内容与数值侧，本节是**交互可达性与官方语义**侧。

### 交互体不得与已有玩法标记同点

官方 `CA_Interact.SearchInteractableAround` 用 `OverlapSphereNonAlloc` 取半径 0.3 的球，再按
**玩家到 collider 的距离严格小于**挑唯一目标；同点的两个交互体距离完全相等，谁赢由物理返回
顺序决定，而滚轮切换只在**同一个交互组**内生效。因此「两个交互体摆在同一个世界坐标」
= 其中一个永久按不到，且不报错、编译与结构守卫都查不出来。

本轮命中两处：

- `SkyIslandWorldStory.Beacon` 把完成纪念物建在装置**自身**位置上。
  Search_D / Search_G 上挂着 K1 / K2 捷径，Search_E 挂着 K3 与噬风挑战，Search_H 挂着敲响归航钟
  —— 被一块只读纪念牌盖住就是捷径与终章永久点不到。
- `SkyIslandGuideInteractable.Attach` 用 `localPosition = Vector3.zero` 挂在 `Search_A_02` /
  `Search_B_02` 上，而这两个标记本身已有见闻交互体（`PrepareMarkers` 给所有 `Search*` 都挂了）。

两处统一改为：复用 `SkyIslandRewardCrate.TryFindCratePosition`（全岛唯一经过真实几何回归的放置
算法）按标记名的稳定散列取方位角，退开共享常量 `InteractableSeparation = 3.2f`
（纪念物触发盒半边 1.5 + 见闻点半边 1.1 = 2.6，3.2 保证不重叠）。
纪念物找不到净空就**只留光、不挂交互体**；航路图退回纯方位角偏移——它是手柄玩家开地图的入口，
宁可落点没过地面校验，也不能与见闻点叠在一起。

### 官方爆炸遮挡在抬高地形上恒失效

`ExplosionManager.CheckObsticle` 把遮挡射线的起终点 y **硬编码成 0.5**，这是按原版地面在 y≈0
写的「齐腰高度水平视线」。天空岛 12 个岛按 `layout.json` 分布在 y = 0 / 8 / 16 / 18 / 24 / 26 /
28 / 42 / 44 / 52 / 62，除登云码头外没有任何地面在 0.5 附近，射线整条跑在岛体下方、恒定打空、
`CheckObsticle` 恒返回 false。叠加官方 `CreateExplosion` **没有距离衰减**这一点，后果是
噬风三段脉冲与双方所有手雷、套装反击爆炸**全部穿墙**，躲掩体毫无意义。

`SkyIslandExplosionObstaclePatch`（Harmony 前缀）把两点压到 `min(startY, endY) + 0.3`：
官方传进来的是 `爆点 + 0.2` 与 `目标 + 0.6`，在 y=0 平地上算出来正好是 **0.5**，与原版逐位一致，
只有地面抬高时才跟着抬高。补丁**只在天空岛生效**——`SkyIslandRaidLease` 在 raid 场景加载时
`Arm(scene)`、卸载与释放两处 `Disarm()`，前缀先看 `armed` 再比对活动场景句柄，
未武装时直接交还原方法，官方地图零行为变化。层掩码沿用官方 `wallLayerMask | groundLayerMask`。

### 相位提速不得自乘

`SkyIslandStormBoss.EnterPhase` 原本每进一档 `/= 1.25f`。两档时总量 1.56 尚可，相位加到四档后
复利成 1.25⁴ ≈ 2.44，再叠档次自带的 1.7 倍，末段反应时间只有官方拾荒者的 1/4.15 —— 没有反应窗口。
改为在 `Bind` 记下基线（此刻 `ApplyAi` 已跑过，基线已含档次倍率），按 `PhaseSpeedup(phase)`
算**绝对值**赋回，四档线性摊到 `MaxPhaseSpeedup = 1.6` 封顶，重复进入同一档不再叠加。

### 其余三条

- `SkyIslandEncounters.Spawn` 的 `sources[i % sources.Count]` 与遭遇身份无关：全岛 13 组的带队者
  永远是按名字排序的第一个 preset。改为 `PresetIndex(id, index)` 走 `StableHash`（不能用
  `string.GetHashCode`，Mono 与 .NET Core 口径不同会让不同机器刷出不同敌人），
  不同区域拿到不同 preset、同一位置跨局稳定。
- `SkyIslandStoryRules` 的钟守物证路线只认 `ZhelingReconciled`。但同一份内容表里 `ZhelingPass`
  门就是 `ZhelingReconciled | ZhelingDefeated` 任一即开 —— 选择挑战折翎的玩家被永久关在物证
  路线之外，失败提示还在要求他去「与折翎和解」（对已了结的折翎 `ReconcileZheling` 直接拒绝）。
  改为 `source.ZhelingResolved`，提示同步说明「和解或战胜都算」。
- 存档落盘门 `story.Tick(!encounters.HasLivingEnemies)` 是全图口径。自动组改成按出击刷新后全岛
  几乎总有活敌，等于把落盘门永久关上，已接受事实只能等离岛或死亡才写。改为
  `HasLivingEnemiesWithin(玩家位置, SaveQuietRadius = 45)`，保留「不在交火帧写盘」的本意。
- `SkyIslandStoryPresentation.Show` 只在打开那一刻把选项烘成按钮：接完委托，三个「接委托」按钮
  还挂着；交完单，派单选项要退出再进才看得到。`SkyIslandWorldStory` 增加 `reopen` + `Refreshed()`，
  任何成功改变状态的选项都重开当前页，返回文案写进新面板正文。

### 叙事层曾经整层没有英文（CR-2026-09-09-011，P1）

只是接线漏了。全 Mod 约 2700 处 `L10n.T`（Campaign 的叙事同样走它），
`WikiContent/en/map__sky_island.md` 也按英文正文维护，英文玩家进岛却一句都读不懂。

现在 **274 条成对文案**全部走 `L10n.T("中文", "English")`：

- 地名 / 人名 / 装置名统一采用在线 Wiki 已发布的英文（Cloudrise Dock、Windchime Market、
  Hanging Root Wood、Windsong Boardwalk、Fallen Star Workshop、Bell Court、Qinghe、Weibai、
  Fuzhou、Miantai、Zheling、the Silent Bell Keeper、Windeater），不另造一套；

- 居民显示名复用 `SkyIslandWorldStory.ResidentName()`，交互提示、血条名与面板标题同一份；
- **诊断文本保留中文**：`Debug.Log*` / `DevLog` / `CriticalLog` / `throw new ...Exception` /
  `lease.Abort` 是给维护者看的（`AGENTS.md` 的「维护语言中文」），且只在 Mod 部署损坏或
  官方契约变更时才露面，外层提示语（「天空岛创建失败：」）本身已双语。

新守卫 `tests/SkyIslandLocalizationGuard.py` 钉住这条不变式：登记文件里的中文字面量必须落在
`L10n.T(中文, English)` 或「中文串 , 纯 ASCII 串」这类成对实参里，唯二豁免是上面的诊断上下文

### 撤离点没有任何视觉标识（CR-2026-09-09-012，P2）

`Exit` / `BellExtraction` 在作者场景里只是 Blender Empty（`tools/generate_sky_island.py`
的 `marker()`），自绘地图删除后官方小地图也不标撤离点——可 F3 面板与中英 Wiki 三处都写着

码头那个还好（离 `PlayerSpawn` 13 m，落地就踩上了），**归航钟庭那个是终章后才开放、
离最近地标 14.4 m、既无标识也无地图点**。

新增 `SkyIslandExtractionRings`（`SkyIslandGroundRing.cs`）把两个圈真的画出来：半径直接取

### 每帧开销（CR-2026-09-09-014/015，P2/P3）

- `SkyIslandRuntimeModule.OnUpdate` 每帧调 `SceneManager.GetActiveScene().name`。`Scene.name`
  **每次调用都新建一个托管字符串**，而这个模块在**所有场景**每帧都跑（基地、每张官方出击图、
  每场 BossRush），节流判断又排在它后面。改为按 `Scene.handle`（结构体整数，不分配）缓存，
  并在开始切图与关卡就绪两处作废缓存兜住句柄复用。口径同
  `CampaignFinalBoss.IsCampaignArenaSceneCached`——项目自己早就把这个模式标注成
  「每帧产生垃圾（AGENTS.md 4.12）」。
- `SkyIslandEncounters` 的 `Find(e => e.Id == id)` / `Exists(e => e.Spawning)` 闭包捕获了参数，
  每次调用都要新建闭包与委托；而 `IsBusy` 是每帧路径（会话对折翎与钟守各问一次）。
  改成显式循环的 `Find(string)` / `AnySpawning()`。
- `SkyIslandLighting.Tick()` 每帧重写 6 个 `VolumeParameter.Override`、3 个
  `RenderSettings.ambient*Color`（Trilight 下每次赋值都让 Unity 重算环境球）与 4 个
  `Shader.SetGlobal*`；锁定预设时这些值**恒定**却照写。加了感知阈以下的变化门
  （颜色 0.002 ≈ 8 位色的 0.5 级、太阳角 0.05°，实测最快的黄昏过渡也只有约 0.0044°/帧），
  切档时用 `dirty` 强制落地。**未实测帧率**，只做了纸面推算。

### 折翎战败后仍会短暂现身（CR-2026-09-09-013，P3）

`SetVisible("sky_zheling", !IsStoryChallengeActive("Zheling") && !ZhelingDefeated)` 用了两个

钟守不改：他的战斗对象是「失控的守钟装置」，人本来就该在战斗结束后回来。
