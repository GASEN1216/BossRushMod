# 天空岛剧情与持久化

## 2026-09-23 船点浮空文字移除（COMPAT）

按 owner 对 `image-23.png` 的复查要求，`SkyIslandRuntimeModule` 不再创建独立的「天空岛 · 晴岚群岛」世界画布，并移除招牌的逐帧朝向与语言缓存。航路解锁后仍通过原船点交互组选择「前往天空岛」；组内子项维持 `MarkerActive=false` 和禁用自身交互碰撞体，避免额外交互圈。首次开放提示仍每进程一次。守卫改为禁止重新创建招牌，并保留组内入口、稳定本地化 key 与生命周期验证；场景中最终是否无残余文字待 owner 重启后复测。

## 2026-09-18 取蛙卵与头目补发的交付可靠性（COMPAT）

蛙卵仍由镜水寺夜间取用、消耗一把云苔纤维、携带至蛙鸣池放生。`SkyIslandFieldcraft.ConsumeOne` 已复用 `SkyIslandInventoryTransaction`：在库存回调前占用操作，预留失败归还原件，预留后再次检查会话，提交后才返回成功；旧的独立 `ConsumeFromPack` 已删除，合成、点灯和一件扣料共用同一份库存语义。官方先改库存后通知，通知抛错不再让玩家丢材料却拿不到蛙卵。

头目/岛主抽中的装备若未穿上，`SkyIslandBossLoot.TryAddFresh` 仍在官方建尸体箱之前补一件到角色背包，但交付改走现有 `InteractableLootboxInventoryHelper.TryAddExtraItem`：已有空位复用、满箱扩一格、挂载后通知异常按实际归属确认；外层仅清理未归属物品。没有新增掉落通道或改变概率。

`SkyIslandDelivery` 直接链接生产库存事务和 helper、逐字执行取卵/补发入口；覆盖异常、重入、换场景、满箱与回滚，证据为 L2，物理掉落和实际操作待 L3。完整内容复核与验收步骤见 `docs/reports/sky-island/2026-09-18-晴岚群岛生产复核与交付可靠性.md`；本轮不承诺未经采样的帧时间。


## 2026-09-18 入口语言、居民姓名与气泡失败修复（COMPAT）

船点、序章仪器交互和地图标记的三个既有 key 统一在 `SkyIslandPreludeFlow.InjectLocalizations` 注入，经现有全局语言变更链刷新。船点浮空招牌已在 2026-09-23 按 owner 要求移除，组内交互名继续使用原有 key。`SkyIslandResidents.Tick` 在暂停和气泡节流前更新姓名，只在语言变化时遍历该会话持有的居民，含隐藏居民及两位永久居民；异步出生落地后重新取当前语言。`NPCNameTagHelper.UpdateOriginalHealthBarDisplayName` 只改已有登记的文字，保留高度、样式与原 UI，不复活已注销登记。

官方 `DialogueBubblesManager.Show` 缺 manager / prefab 会返回已完成的 UniTask，不能把 `Forget` 没抛异常当成展示成功。发送先检查现存管理器，再检查返回任务：立即结束的请求消费一次结果后返回 false；正时长的正常展示进入跨帧流程才记账，后续异常由不捕获 owner 的静态回调观察。没有读取私有 prefab 或另造气泡池。`SpokenCount` 表示进入展示流程的请求数，不能据此推断像素可见或播放完整；原 `speed=-1` 的注释已纠正为官方默认速度。

回归入口为 `SkyIslandEncounters` 与 `SkyIslandInteraction`，调用接线由 `SkyIslandLiveLocalizationGuard` 保护。对应 `CR-2026-09-17-023` / `024` / `025`；验证与实机操作见 `docs/reports/sky-island/2026-09-18-天空岛复审三项修复与验收.md`。

## 2026-09-17 头顶气泡与居民漫步（COMPAT）

这张图此前是静止的：居民钉在标记上不出声，敌人从生成到倒下一个字没有。本轮按「活人感」补三件事。

**走动。** `Assets/Data/DuckNpcs.json` 把晴禾 / 苇白 / 浮舟的 `canWander` 打开（眠苔本来就是），半径维持 2.5 m——居民离最近交互体实测 ≥ 8 m（`SkyIslandInteractionCompetitionPropertyTest`），留 5.5 m 余量。折翎守旧航路、无声钟守守钟，两位按人设站定。走动本身复用既有的 `DuckNpcMovement`（官方 A\* + 官方移动管线），没有新的移动栈。说话时人要停下：`SkyIslandResidents.Tick` **按状态**比较「此刻在不在对话 / 暂停里」，变了才调 `HoldForDialogue` / `ReleaseFromDialogue(1f)`——官方对话是异步的，取消路径有五条，逐条挂事件必漏。

**话语表。** `SkyIslandChatterLines`（纯规则、无 Unity 依赖，隔离回归直接执行）是全岛气泡文案的唯一来源：6 位居民按剧情进度分池、云沿拾荒者与断风游猎两个小兵共享库（闲逛 / 注意到你 / 身边倒下一个）、9 类头目 × 3 个时刻（断风三变体各不相同）、折翎战斗体与守钟装置两位具名对手。每个说话者上方有一行 `【声音】` 人设注释。**按人设不说话的三位**：无声钟守只有「铛——」与省略号，守钟装置是机器，噬风是一股风（话语表里没有它）。

**调度。** `SkyIslandChatter` 是实例化的气泡预算（无静态状态），四道门：静音（官方对话中 / `BossRushUI.IsGamePaused()` / 会话失效）、展示预算（常规请求每个 owner 至多一个，倒下台词可强制插入；不能当成像素层的绝对上限）、距离（20 m，平方比较）、单人冷却（居民 15–25 s，小兵 35–60 s，头目 6 s）。出口复用官方 `DialogueBubblesManager.Show`，与基地的阿稳同一套。小兵由 `SkyIslandEncounters.Tick`（既有 0.25 s 节流）驱动，每次派发只挑一个候选，优先级「身边倒下一个 > 注意到你 > 闲话」；头目走 `SkyIslandBossVoice`（出场 / 血线 60%、30% / 倒下），经 `SkyIslandBossContext.Bark` 共用敌人侧预算，`OnDestroy` 成对退订。机制预警仍然只走 `SkyIslandHud.Caption` 的警示通道，两条通道一上一下互不打断。

**居民对白改写。** `SkyIslandBossRules.ResidentLine` 的 12 条攻略腔（「先拆供能桩，等炉子过热再打它」）与 `DescribeNpc` 里四句 UI 腔换成各人自己的口气，信息一条不少。改写**保持屏数不变**：全自动验收按屏序截图并对某一屏断言关键词，关键词（星工装备 / Starworks outfit、悬根林的风标底下蹲着个猎首 / huntmaster crouches、断风游猎 / Galebreaker Ranger holds、观星手 / stargazer up on、熔晶炉）原样保留。核对屏数的尺子是 `tools/sky_island_line_screens.py`。

**事件与战斗判定（2026-09-19 修复）。** 小兵和头目共用 `SkyIslandChatter.TargetsPlayer`：优先认当前 `searchedEnemy`，未锁定目标时才接受 12 秒内的玩家动静。`noticed` 永久置位，`NoticeFromCharacter` 也可能保留旧来源，均不可单独当战斗事实。小兵在有当前敌人或最近动静时不选闲话，脱战后仍可恢复闲话。

`SkyIslandChatterEvent` 是不持有 Unity 对象的有限待播进度，发现玩家、同伴死亡和 Boss 血线复用它。候选未选中、忙碌、距离或官方展示入口拒绝均不消费；成功后消费，12 秒过期或目标已改变时丢弃，同类进度合并。事件按距上次实际发送至少 6 秒准入，闲话仍维持完整的 35–60 秒冷却，不因事件缩短。Boss 快速跨过 60%/30% 合并成最新一句；`Update` 每 0.5 秒重试，不依赖再挨一击，死亡取消待播血线。重复绑定先退订旧 Health 再绑定，销毁成对退订。

新增事件时沿用话语表、owner 观测与这个待播结构：先观测版本，再按语境和优先级选候选，只在成功派发后消费。池在发送当刻按语言取，待播不缓存字符串。没有全局队列、每帧反射或新增持久状态。

**F3 的证据边界。** `SKY_CHATTER` 缺居民/敌人 owner 或官方展示入口时 FAIL；依赖齐全但任一侧没有发送观测时 SKIP；双侧有记录才通过请求层检查。指标明确 `visual_check=manual`，不再用两个 Busy 布尔的和冒充同屏数量测量。真实字号、遮挡、漫步和节奏仍待 L3。

守卫 `tests/SkyIslandChatterGuard.py`（人设、长度、去重、四道门、4 走 2 站，五条反向探针）、隔离回归 `SkyIslandChatterRegression`（挑选不重复上一句、进度分支、每位说话者都有话）、只读 F3 用例 `SKY_CHATTER`（判据 `JudgeChatter` 交给 `SkyIslandValidationJudges` 逐字执行）。证据到 L2；气泡的实际节奏、遮挡与观感只能 L3。

## 独立出击加载、取消与返航

`SkyIslandRaidLease` 预载独立 `sky_island_raid` 场景包，经官方 SceneLoader 加载 `BossRush_SkyIsland`。
最小关卡装配归租约：在 sceneLoaded 配置关闭状态的 SkyIslandLevel 根、天气与初始 Buff 集合、A* 后才激活官方服务。
即使 Session 在加载中销毁，租约仍须完成这一步，避免官方状态机永远等不到 LevelManager。
Session 只绑定地形、登记导航初始化等待、准备碰撞与图；完整路径校验后建立实体/导航门，再解除初始化屏障。

### 撤离规则（2026-09-08，CR-2026-09-08-002）

撤离只有一条路：走进撤离圈并停满 3 秒，离圈取消倒计时。判定收敛为 `SkyIslandSession.IsInsideExtraction()` 单一事实源，半径与秒数是 `ExtractionRadius` / `ExtractionHold` 两个常量；码头恒开。**布局 v2（2026-09-10）起**：归航钟庭在双航标点亮后开放（`BellExitIfUnlocked()` 读 `BothBeacons`，不再等敲钟结局）；另有悬根林 / 残星工坊两处航标广场撤离点，借用岛心标记 `Region_D` / `Region_G`（`WindExitIfUnlocked()` / `StarExitIfUnlocked()` 分别读 `WindBeacon` / `StarLamp`）。四个圈共用 `ExtractionMarkerAt`，地面环（`SkyIslandExtractionRings.AddBeaconRings / ApplyBeacons`）与官方地图标记（`SkyIslandMapMarkers`）读同一组解锁函数。

**地图不提供任何返航入口**（2026-09-09 起地图已换成官方 M 键地图，撤离点位置改由世界里的撤离圈本身指示）。旧版地图面板上的「立即返回基地」允许玩家在任意位置、战斗中、借地图暂停发起完整撤离（官方 `notifyEvacuation:true, saveToFile:true`），绕过出击损失与暴露时间约束，已删除。Dev 场景实验面板与初始化失败恢复各自保留内部返回入口，不经玩家可达路径。`SkyIslandPlayerEntryGuard` 以反例断言钉住：`OpenMap()` 内不得出现 `Close(` / `returnToBase` / `ReturnToBase`——打开地图不得夹带任何返航动作。

### 初始化失败的可观察终点（2026-09-08，CR-2026-09-08-005）

官方 `InitLevel` 的异常不会传给等待 `LevelInited` 的外层加载，外层会一直等下去。桥接因此对官方 `SceneLoader.LoadScene` 状态机的 `MoveNext` 做 transpile，把那**唯一一处** `LevelManager.LevelInited` 读取换成会在失败时抛 `OperationCanceledException` 的 `LoaderLevelInitialized`；`NotifySaveBeforeLoadScene` 的前缀则保证半初始化的角色不覆盖出发前的官方快照（玩家已死亡时照常保存）。

令牌归租约：`Prepare` 领取、`OnSceneLoaded` 绑定场景，**先注入**官方天气与空 `startBuffPrefabs`（这两项场景包里本来就没有，见 `ArtSource/SkyIsland/OFFICIAL_SCENE_CONTRACT.md`；天气用的是 `Prepare` 阶段在基地克隆出来的 `DontDestroyOnLoad` 副本，官方 `TimeOfDayConfig`/`TimeOfDayEntry` 都是场景组件，原件出图即销毁），再在**激活官方服务之前**跑 `SkyIslandOfficialContract.VerifyBeforeActivation`（配置与 MultiSceneCore 启用、天气与起始 Buff 已注入、provider 唯一且启用、SubScene 位置表、出生点与缓存一致、导航不超过 4095 顶点）；顺序颠倒会让合同拿包内空值把每一次进岛判死（CR-2026-09-10-002，守卫 `SkyIslandOfficialContractGuard` 钉住该顺序），装配异常与会话超时/取消都经 `Abort` 发信号，`TryRelease` 归还。**令牌漏还会让下一次进岛在 `Prepare` 直接抛「上一段初始化尚未释放」**，夹具专门为此留了重入断言。

## 天空岛环境与装置反馈（2026-09-08，COMPAT / WIRE+）

`SkyIslandAmbience` 是 `SkyIslandSession` 独占的环境 owner。它只创建风铃集、风标、星灯、观星镜、菜畦和归航钟六组装饰节点；不会停用地图区域根对象、碰撞体、敌人或交互点。每帧集中更新近处光丝旋转和呼吸光，每 0.25 秒按玩家距离调度一次，以 38 米进入、44 米离开的滞回控制灯光与声源。没有每个节点各自运行的 Update，也没有全图扫描协程。

## 官方时钟光照（2026-09-08，COMPAT / WIRE+）

`SkyIslandLighting` 在独立天空岛 Scene 内创建自己的 Directional Light 与 LightControl Volume，不再经 `ArenaPrototypeLighting` 扫描、借用基地 SodaPointLight 模板。Session 调用无参 `Tick()`；默认读取 `GameClock.TimeOfDay.TotalHours`，不写官方时间。6–7 点星夜渐变至晨光、7–10 点晨光渐变至晴昼、16–18 点晴昼渐变至暮色、18–22 点暮色渐变至星夜（22 点整进入星夜，与官方运行时 `nightStart` 同相），其余为昼夜稳定区间。颜色与强度使用平滑权重，日照旋转使用四元数插值，午夜没有换档跳变。

## 进出岛：与原版同一条流程（2026-09-09）

入口挂在基地**原有船点**的交互组上（`SkyIslandRuntimeModule` 找 `IsBaseHubBoatInteractable`），
走的是官方 `SceneLoader.LoadScene`、真实 `LevelConfig` / `LevelManager` / `MultiSceneCore`，
因此 `isRaidMap` 为真、`RaidUtilities.NewRaid()` 照常触发，死亡完全交给官方 `CharacterDieTask`。

两处观感必须与原版对齐，已在 `SkyIslandRaidLease` 里对齐并由守卫钉住：

- **进图**用 `clickToConinue: true`，与官方 `MapSelectionView.LoadTask` 一致：读条完停在「点击继续」。
  用 false 会把玩家直接甩进战斗区，和原版任何一张地图都不一样。
- **撤离**照抄官方 `SceneLoaderProxy.Task` 的顺序：`NotifyEvacuated`（顺带让主角在结算期间无敌）
  → `ClosureView.ShowAndReturnTask(1f)` → 幕布换成 `EvacuateScreenScene` → `LoadScene`。
  结算画面是表现层，失败也必须 fail-open 继续返航，不能把玩家留在图里。
  官方自己会在 `SceneLoader.LoadScene` 内部再 notify 一次，这个「两次」是原版既有行为，如实照搬。

仍与原版不同、属于有意的产品决定：**天空岛出击免费**（原版 `MapSelectionEntry.Cost` 会扣费），
且**没有目的地预览与确认面板**——与船点交互即开始加载。

2026-09-09 对照官方 `CountDownArea` / `SceneLoaderProxy` 复审后补齐三处（`SkyIslandPlayerEntryGuard` 钉住，五条人为破坏逐条转红）：

- **撤离圈在官方界面打开时不推进**：判定行带 `View.ActiveView == null`，开着背包站在圈里不会被送回基地。
- **返航派发即封锁输入**：`Close` 先 `BlockInputForReturn()` 再派发；封锁源是岛场景内临时对象，随场景卸载解封，`Cleanup` 也销毁它。
  不能挂在 DontDestroyOnLoad 的宿主上——`InputManager` 只在源对象销毁/失活时解封，否则回基地后输入永久锁死。
- **官方加载器拒绝时立刻失败**：`SceneLoader.LoadScene` 遇 `IsSceneLoading`/身份未登记只记 LogError 就同步返回，
  等 root 的循环观察 `lease.LoadFinished`，按「未起航」清理，不空等 120 秒、不发起多余的回基地加载。

（2026-09-10 更正：官方倒计时控件 `EvacuationCountdownUI` 自 `a613774` 起已复用，计时在全方位审核中改走游戏时间，见文末。）
仍是已知差异：服务根/地形根由 Mod 在 `sceneLoaded`
之后才激活，先于租约订阅的处理器看到的是没有 `LevelManager` 的场景。新增一张官方级 Mod 地图的完整流程见
`docs/guides/从零搭建自定义场景_Blender到Unity到Mod完整教程.md` 第 21 节。

`LevelManager.loadLevelBeaconIndex` 不需要设置：它被消费后自清零，且找不到 `StartPoints_N` 时
会回退到 `StartPoints`，天空岛只有一个出生点。

## 地图：用官方的，不自绘（2026-09-09）

官方地图系统是**纯场景数据驱动**的：`MiniMapDisplay.AutoSetup()` 就是一句
`FindAnyObjectByType<MiniMapSettings>()`，`MiniMapView.OnOpen()` 每次开图都会重跑它，
而玩家侧的开合走 `CharacterInputControl.OnUIMapInput -> MiniMapView.Show()`。
换句话说，让一张新图支持官方地图**不需要写任何运行时代码**，只要场景里有那份数据。

天空岛原先没放，于是 `MiniMapView.Open()` 里的 `MiniMapSettings.Instance == null` 早返，
官方地图键在岛上是**死键**，Mod 反而自绘了一整套 F6 界面。现在已改正：

- 场景包里带一条 `MiniMapSettings.MapEntry`（sceneID / sprite / imageWorldSize / mapWorldCenter），
  由 `SkyIslandRaidBuilder` 在构建独立出击场景时装配；
- 贴图由 `tools/build_sky_island_minimap.py` 从 `layout.json` 的地面三角**离线烘焙**，
  和导航面用的是同一份权威几何，地图轮廓与实际可走地面不会对不上。2026-09-10 起颜色取手绘底图
  `ArtSource/SkyIsland/Minimap/Source/sky_island_minimap_art.png`，由 `tools/sky_island_minimap_art.py` 生成
  （Blender 俯视参考图 → gpt-image-2 带参考图重绘 → ECC 对齐 → 调回原版色带）。形状（alpha）仍逐像素按几何；
  底图记着几何指纹，布局几何变了烘焙脚本会拒绝旧图；
- Mod 侧删掉 `SkyIslandMap.cs`（自绘 UI）与全部 F6 输入处理，只在航路图交互体和 F3 菜单里
  保留一个 `MiniMapView.Show()` 的同等入口。

三个必须记住的坑：

1. **`combinedSprite` 要留空**。设了它就走 combined 通道，而 `SetupCombined` 会把 `sceneID`
   清成空串，让 `TryConvertWorldToMinimap(worldPos, sceneID, …)` 按 sceneID 找不到条目。
2. **不要放 `MiniMapCenter`**。它的 `Cache()` 会用自己的 transform 覆盖 `mapWorldCenter`，
   和离线烘焙出来的中心打架。
3. **`GetSceneID(int)` 需要桥接**。官方的「居中到玩家」走
   `GetSceneID(GetActiveScene().buildIndex)`，bundle 场景恒为 -1 且天空岛刻意没进全局 `entries`，
   原实现只会返回 null。桥里补了第三个 prefix，但它按「**当前活动场景**是天空岛」判定，
   绝不能写成「buildIndex == -1 就返回天空岛」——那是被禁的全局 -1 别名，
   `SkyIslandSceneReferenceBridgeGuard` 与隔离回归两侧都钉了这条。

**分区「未探索」灰显保留了下来，而且是纯数据实现**：场景包里放的是 1 张底图（全岛暗灰剪影，永远显示；手绘版是去色压暗的底图，不再镂空障碍）+ 12 张分区彩色图层。`MiniMapDisplay.Setup` 里有
`if (cur.Hide) showGraphics = false;`，`OnOpen()` 又每次都重跑 `AutoSetup()`，
所以运行时只要按存档的 `visitedRegions` 翻 `hide` 就行——不重绘贴图、不要可读纹理、
不接管任何官方界面。owner 是 `SkyIslandMapFog`，装配时刷一次、每新到访一个区域再刷一次。
图层按 **sprite 名字**认领而不是列表下标，下标会随烘焙输出顺序漂移。

守卫：`tests/SkyIslandMiniMapGuard.py`（贴图与手绘底图 sha256、覆盖范围复算、图层初始 hide、认领方式）与 `tests/SkyIslandMiniMapLayerAlignmentPropertyTest.py`
（按官方那三行摆放公式把 12 张分区贴图贴回底图坐标系，与全彩参考图逐像素比对，实测 0.000% 错位——`imageWorldSize` / `offset` 因此不必等实机确认）。

完整流程与踩坑记录：`docs/guides/sky-island/自定义地图接入官方M键地图.md`。

## 物资搜集、敌人档次与噬风（2026-09-09，COMPAT / SCHEMA+）

本轮把交付文档留作「后续内容定稿」的经济与战斗深度补齐，**不新增 TypeID、不重建场景包**。

### 搜刮点

`SkyIslandScavenging`（Session 持有）+ `SkyIslandLootTables`（纯逻辑内容表）。39 个锚点覆盖 8 主区与 4 支路：
生活物资 11（A/B/C）、航务补给 18（D/E/F/S1–S3）、星工遗存 10（G/H/S4）。锚点写成
「已有作者标记 + 方位角 + 距离 + 档次」，进图时一次解析成落点，四道检查任一不过即跳过该点：
地面射线命中本图地面、无墙体胶囊阻挡、距任一玩法标记 ≥ 4.5 m、距其它已落位点 ≥ 3 m。

玩家进入 72 m 才建箱，每 0.5 s 最多建一个（4.12 门控）。内容按 `(raidSeed, anchorId)` 固定：
同一次出击离开再回来是同一份，重新出击才重新 roll；不进存档。开箱进度经官方
`InteractableLootbox.OnStartLoot` 记账（订阅/退订成对），HUD 第三行显示「物资 已搜/可搜」。
**刻意不在地图上标搜刮点**——值钱的东西要靠走出来。

档次只决定品质带（1–3 / 2–5 / **4–8**）与件数（1–2 / 2–3 / 2–4），池子来自官方 `ItemAssetsCollection`。
件数与品质带必须**同向递增**：件数曾经是 2–3 / 2–4 / 2–3，中段的航务补给比全图最深处出得还多，而当时守卫一个件数都没钉。现在 `check_loot_anchors` 解析方法体逐档比对并断言单调不减。
游戏一共 8 档品质，最深一档必须够得到顶档，否则第 8 档物品在天空岛永远刷不出来。

池子的**形状与排除口径与既有 Boss 奖池一致**：逐个官方 tag 做 `requireTags` 再取并集
（只给 `excludeTags` 会把无 tag 的占位件、内部道具、无标签任务件整批放进来），
排除标签统一来自 `Config/LootExcludeTagPolicy.cs`——`DestroyOnLootBox`、`DontDropOnDeadInSlot`、
`LockInDemoTag`、`Quest`（TagsData 没有对应字段，`TryFindQuestTag` 按名字从 `AllTags` 查到；2026-09-11 离线核对 69 件带它），天空岛另加 `Special` / `Character` 收窄。
Boss 奖励箱、通关奖励、空投与搜刮点现在共用这一份列表，`LootBlacklistRegistry` 仍是按 TypeID 的第二道闸。

箱子本身走 `SkyIslandRewardCrate` 唯一建造点。官方 `CreateLocalInventory()` 只 `AddComponent<Inventory>()`，
既不设容量也不设 `NeedInspection`（字段默认 false），因此建箱后必须显式补上 `needInspect` /
`NeedInspection` / `SetCapacity`——不补就得到「开箱即全明牌、没有鉴定过程」的箱子，
与本 Mod 其余三条建箱路径和原版口径都不一致。

### 敌人档次与噬风

`SkyIslandEnemyTier` 是无依赖枚举文件，内容表与运行时装饰共用。`Tier` / `Lead` 两个字段让每组
区分「带队者」与「随从」：D / G / S4 的带队者是断风游猎（Elite），折翎与钟守是 Champion，
新增手动组 `Storm` 是噬风 + 2 名断风游猎。

噬风血量 ×13、模型 ×1.9、风暴染色，相位阈值 0.80 / 0.60 / 0.40 / 0.20（四次），预警 1.4 秒后放三波扩张范围伤害（7 / 8.5 / 10 m）并提速，击败后原地留星工遗存箱。
原值是 ×18 + 两档相位 + 9 m / 1 s 预警：整场是「打很久的血包 + 两次特殊时刻」，而且官方
`ExplosionManager.CreateExplosion` **没有距离衰减**，从圈心跑出 9 m 只有 1 秒（需 9 m/s），
贴脸的近战流在数学上必吃满三段 114。现在 7 ÷ 1.4 ≈ 5 m/s，正常跑动可达；守卫直接断言这个比值 ≤ 5.5。它**可选**，但击败后成为说服钟守的第五条路线（原路线要四件物证齐备）。

两条容易踩空的实现口径：

- **预警是贴地圆环**（`LineRenderer`，半径 = 真实作用范围，后两波在 0.45 s 间隔里提前画出）。
  俯视视角下点光源读不出 AoE 边界，而三波 38 伤害站在中心必死。半径只有 `RadiusForWave`
  一个来源，圆环与伤害不会漂移。
- **改档次的 `nameKey` 必须同时打开 `characterPreset.showName`**：`HealthBar` 有
  `if (!characterPreset.showName) return;` 的门控，普通拾荒者 preset 上它是 false，
  只改 `nameKey` 血条上根本不显示。精英与 Boss 显式打开，`Scav` 保持匿名。
  连带影响：官方在主角击杀时会 `SavesCounter.AddKillCount(nameKey)`，那是写进正式存档的
  `Count/Kills/<key>`，所以天空岛击杀记在自己的键下，**不再计入**官方拾荒者击杀数，
  `RequireEnemyKilled` 解锁与击杀类任务也不会推进。
  因此 **`Scav` 一律不改名**（2026-09-09 可玩性复审）：它的 `showName` 恒为 false，
  自定义名玩家根本看不到，却要付出「击杀白打」的代价；自动组改成按出击刷新后这批击杀会反复产生，
  代价更大。精英以上仍用自己的 key，模组内容本就该独立计数。

三张倍率表（血量 / 伤害 / 反应）必须**随档次严格递增**。Champion 曾经是 2.2 / 1.3 / 1.25，
比守航标的 Elite（2.6 / 1.35 / 1.3）还软——折翎是单挑的主线对手，却比路上的杂兵小队更弱，
而守卫当时只钉了「伤害封顶 3」这条赋值语句在位，一个数字都没钉。现在是
Scav 1 / Elite 2.6 / Champion 4.5 / Storm 13，守卫解析方法体逐值比对并断言单调。

数值层是乘法（血量 `*=`、反应时间 `/=`），重复施加会复利（13 倍血跑两遍就是 169 倍），
因此档次与 AI 调参各有一个一次性标记组件；两者必须分开，`AICharacterController`
常常就挂在角色本体上，共用一个标记会让先跑的 `ApplyAi` 把后跑的 `Apply` 一起挡掉。

新增 flag `StormSlain = 32768`（`KnownFlags` 32767 → 65535）。旧档读出为 0，语义即「尚未挑战」；
Codec 拒绝「已击败但航标没亮」这种不可能状态。

### 居民服务与航务委托

`SkyIslandServices`（Session 持有）提供渡口整备、苔药调理（按缺失血量比例计价、回满生命、冷却 300 s）、
归航菜（交还种植记录后每次出击一份 `MaxHealth` / `RunSpeed` / `WalkSpeed` 加成，销毁时统一摘除）。
三项都**不依赖官方 `StockShopView`**——它是场景内预制体，独立出击关卡不保证存在。

经济口径必须跟着官方，有三条：

- **渡口整备按官方公式计价**：`ceil(Value × 修复量 / MaxDurability × 0.5)`，即按**物品价值**，
  不是按耐久点数。价值无关的「每点 N 元」盈亏平衡点落在 `Value = 6 × MaxDurability`，
  高价值武器会被卖得比官方维修台便宜一到两个数量级，廉价高耐久护甲反而更贵。
  岛上只额外压一个服务费下限。
- **整备同样累加永久磨损**（`DurabilityLoss += lostPercentage`，写法同官方 `ItemRepairView.Repair`）。
  官方每修一次都会永久削一点上限；不跟就等于开了个「又便宜又无损」的修理站，
  把官方设计的装备损耗沉降口整个架空。
- **付费的账户门控读 `LevelConfig.accountAvailable`**，官方 `ContextualMoneyAndCash` 也用它决定
  是否显示账户余额。**不要**用 `SaveCharacter`：那是「是否把主角写回存档」，raid 图里同样为 true
  （天空岛的官方合同还硬性要求它为 true），拿它当账户门控恒真、等于没门控。
  天空岛场景包目前没有显式关掉 `accountAvailable`（序列化默认 true），所以现在账户是可以花的；
  要改成只收现金，把作者场景那个字段设为 false 重打包即可，代码侧会自动跟随。
- **苔药按缺失血量比例计价**（2026-09-09 可玩性复审）：`HealPriceFor` = `max(60, ceil(480 × 缺失比例))`，
  冷却 120 s → 300 s。旧口径是「120 定额 + 全额回满 + 120 s 冷却」，叠加上一条的「账户可花」，
  等于岛上根本没有血量压力：只要有钱就能无限满血。用**比例**而不是按血量点数，报价与玩家
  `MaxHealth` 的实际量级无关，官方改血量或玩家吃了上限加成都不用重算。

归航菜是免费的，因此只补「上限涨出来的那一截」而不回满血——免费全回会让付费苔药永远没人买。
归航菜同时挂在**青穗梯田的菜畦装置**上（2026-09-09 补）：晴禾是 `isPermanent` NPC，与玩家结婚后
由婚姻系统接管、不再上岛（`SkyIslandResidents.SpawnOneAsync` 跳过生成，`PermanentDuckNpcModule`
对 `SkyIslandRaid` 恒返回 false），此前只挂在她身上的归航菜会**永久失联**。苇白的委托早有留言板
兜底，这条纪律必须对称。`mealUsed` 是单次布尔，两个入口不会双领。

**苔药也补上了同一条纪律（2026-09-12 / `CR-2026-09-12-014`）**：眠苔不是永久居民（不会因结婚离岛），
但异步生成可能失败，而苔药此前**只挂在她本人身上**——她没生成出来的那一趟，玩家连唯一的付费回血都没有，
而星苔药膏恰恰要在她的药臼上做，等于把「回血」整条线掐断。药臼早就有装置兜底（悬根林见闻点
`Search_D_02`「吊在根上的邮袋」，离她站位 14 m），服务却没有，是同一处改动里的不对称。
现在 `Search_D_02` 同时挂苔药与药臼，`healReadyAt` 是 `SkyIslandServices` 的单例字段，两个入口共用同一次冷却。
`tests/SkyIslandFullAuditGuard.py` 新增「每一项居民服务都必须有装置兜底」的结构断言，
把三项服务与三处合成台一并钉住。

`SkyIslandBounty` 是纯逻辑的可重复委托：清理威胁 / 回收补给 / 巡视区域 / 夜里驱蚋四选一，进度按接单基线相减，
目标随完成单数递增，第三单起谢礼升到星工遗存档，单次出击最多 3 单。按出击计、不进存档。
委托同时挂在风铃集留言板装置上，苇白婚后离岛也能接能交。
谢礼箱按轮次错开落点（`BountyRewardBearing + round × 120°`，距锚点 3 m，走
`SkyIslandRewardCrate.TryFindCratePosition` 的地面/墙体裁决）：交单锚点是苇白本人或留言板，
直接落在锚点上会把箱子塞进 NPC / 告示牌里抢同一次交互选择，而三轮锚点完全相同、箱子会一摞叠住。

**三个计数器的信号源寿命不同，这是本系统最容易出错的地方。**
回收补给与清理威胁数的都是**按出击刷新**的东西（搜刮点重 roll、自动遭遇重新生成），
而巡视区域的源头是**持久存档事实**：区域走过一次就永久记进 `visitedRegions`
（`RecordRegionVisited` 对已访问区域返回 false）。于是走遍群岛之后，巡岛类的
**本局可完成量可能是 0**。

> 2026-09-09 可玩性复审前，清理威胁也属于「持久事实」那一类：`RemainingClearable` 用
> `!completed(id)` 过滤，第二次进岛起恒为 0，这类委托永远派不出来。自动组改成按出击刷新后
> 该过滤必须一并去掉，否则改了生成、没改可完成量，委托侧仍然是死的。

因此派单前必须用 `SkyIslandSession.AvailableBountyProgress(kind)` 与本轮目标比对，
只挂出做得完的单；**前三类**的量随进度单调递减，接单时 `available ≥ target` 就保证这一单做得完。
另外苇白永远提供**退单**（`TryAbandon`：让出委托槽，不计完成数、不给谢礼，重新接单会重取基线），
作为门控疏漏时的兜底——没有退单，一张做不完的单就会把本局委托槽卡死一整局。

**「夜里驱蚋」是四类里唯一的软门，不满足上面那条硬不变式**（2026-09-12，`CR-2026-09-12-004`）：
它的可完成量是 `SkyIslandMosquitoRules.CullableBeforeDawn` 算的「天亮之前保守还能打下几只」，
而刷新是概率事件、场上只数 `swarm.Alive` 还会随新群**回升**，所以不单调；更实际的是**玩家自己就能把供给压没**——
接单后整夜焚驱风香或站在灶火烟里，`SpawnWeight` 直接归零、已经围上来的也全 `Scatter`（`killed=false` 不计数）。
纯概率下的风险很小（基础权重整夜期望供给远超一单 12 只），真正的兜底就是退单出口。
口径写在 `SkyIslandSessionGnatBounty.AvailableGnatCull` 的注释里，主文件只留一句指路。

## 可玩性复审修复（2026-09-09，COMPAT）

### 遭遇按出击刷新（最要紧的一条）

13 组自动遭遇全部走 `clearedEncounters` **永久**抑制生成（`Tick` 里那句
`if (!encounter.Started && completed(encounter.Id))` 短路），而 39 个搜刮点每趟重刷。
于是第二次及以后进岛 = **零敌人 + 约百件产出（含 ~25 件品质 4–8），无限重复**：
一张 raid 图退化成无风险刷宝台。编译、当时的守卫和执行回归都查不出来
——fixture 只在**同一个 owner** 上验证「清完不重生」，从没构造过第二次出击。

修法是把短路条件收窄到手动组：

```csharp
if (!encounter.Started && encounter.Manual && completed(encounter.Id)) { encounter.Cleared = true; continue; }
```

- 自动组每趟重新生成，风险回来了；具名剧情对手（折翎 / 钟守 / 噬风）语义不变，仍是一次性。
- **存档 schema 一个字节没动**：`clearedEncounters` 照旧写、照旧幂等，只是对自动组改为
  「剧情装置的前置证据」（修风标要 D + D_02、修星灯要 G + G_02、校准观星镜要 S4），
  一次达成永久有效，重刷的敌群不会把已完成的装置重新锁上。回退到一次性清场也不丢数据。
- `RemainingClearable` 必须同步去掉 `!completed(id)` 过滤，否则生成改了、可完成量没改，
  「清理航路威胁」委托从第二趟起永远派不出来。
- fixture 补了两组 **returning raid** 场景（新 owner + 预填 `Saved`）：自动组重新生成、
  手动组仍被短路、重清仍记一次账。

### 剧情面板的战斗门

面板走共享模态租约把 `Time.timeScale` 压到 0，而这个暂停**是可靠的**——
`ModBehaviour.LateUpdate` → `LateUpdateZombieModeRuntime` → `EnforceModalInputPause()`
排在官方 `TimeScaleManager.Update()` 之后，Unity 保证所有 Update 先于所有 LateUpdate。
于是它就是一个战斗中随手可用的免费暂停键，而且面板里还挂着眠苔的苔药与浮舟的整备
——可以定格战斗再花钱回满血。这不是理论问题：五个自动遭遇的生成点本身就是搜索点
（`Search_C_02` / `D_02` / `E_02` / `F_02` / `G_02`），眠苔站在 `POI_D`、距 `EnemySpawn_D` 只有 47 m。

`SkyIslandSession.CanOpenStoryPanel` + `SkyIslandEncounters.HasLivingEnemiesWithin(point, 35f)`
挡住打开时机，`SkyIslandWorldStory.Tick` 在面板已开而条件转假时自动收起
（在途 async 生成会在 `timeScale = 0` 下继续完成）。

按**半径**而不是全图判定：`HasLivingEnemies` 是全图口径，玩家把一组敌人丢在岛的另一头
就会让全岛剧情交互永久不可用——那是死锁，不是门控。

## 同点交互、爆炸遮挡与相位复利（2026-09-09 可玩性复审第二轮，COMPAT / WIRE+）

同一天的可玩性复审分两轮。上一节是内容与数值侧，本节是**交互可达性与官方语义**侧。

### 交互体不得与已有玩法标记同点

官方 `CA_Interact.SearchInteractableAround` 用 `OverlapSphereNonAlloc` 取半径 0.3 的球，再按
**玩家到 collider 的距离严格小于**挑唯一目标；同点的两个交互体距离完全相等，谁赢由物理返回
顺序决定，而滚轮切换只在**同一个交互组**内生效。因此「两个交互体摆在同一个世界坐标」
= 其中一个永久按不到，且不报错、编译与结构守卫都查不出来。

本轮命中两处：

- `SkyIslandWorldStory.Beacon` 把完成纪念物建在装置**自身**位置上。
  Search_D / Search_G 上挂着 K1 / K2 捷径，Search_E 挂着 K3 与噬风挑战，Search_H 挂着敲响归航钟
  —— 被一块只读纪念牌盖住就是捷径与终章永久点不到。
- `SkyIslandGuideInteractable.Attach` 用 `localPosition = Vector3.zero` 挂在 `Search_A_02` /
  `Search_B_02` 上，而这两个标记本身已有见闻交互体（`PrepareMarkers` 给所有 `Search*` 都挂了）。

两处统一改为：复用 `SkyIslandRewardCrate.TryFindCratePosition`（全岛唯一经过真实几何回归的放置
算法）按标记名的稳定散列取方位角，退开共享常量 `InteractableSeparation = 3.2f`
（纪念物触发盒半边 1.5 + 见闻点半边 1.1 = 2.6，3.2 保证不重叠）。
纪念物找不到净空就**只留光、不挂交互体**；航路图退回纯方位角偏移——它是手柄玩家开地图的入口，
宁可落点没过地面校验，也不能与见闻点叠在一起。

### 官方爆炸遮挡在抬高地形上恒失效

`ExplosionManager.CheckObsticle` 把遮挡射线的起终点 y **硬编码成 0.5**，这是按原版地面在 y≈0
写的「齐腰高度水平视线」。天空岛 12 个岛按 `layout.json` 分布在 y = 0 / 8 / 16 / 18 / 24 / 26 /
28 / 42 / 44 / 52 / 62，除登云码头外没有任何地面在 0.5 附近，射线整条跑在岛体下方、恒定打空、
`CheckObsticle` 恒返回 false。叠加官方 `CreateExplosion` **没有距离衰减**这一点，后果是
噬风三段脉冲与双方所有手雷、套装反击爆炸**全部穿墙**，躲掩体毫无意义。

`SkyIslandExplosionObstaclePatch`（Harmony 前缀）把两点压到 `min(startY, endY) + 0.3`：
官方传进来的是 `爆点 + 0.2` 与 `目标 + 0.6`，在 y=0 平地上算出来正好是 **0.5**，与原版逐位一致，
只有地面抬高时才跟着抬高。补丁**只在天空岛生效**——`SkyIslandRaidLease` 在 raid 场景加载时
`Arm(scene)`、卸载与释放两处 `Disarm()`，前缀先看 `armed` 再比对活动场景句柄，
未武装时直接交还原方法，官方地图零行为变化。层掩码沿用官方 `wallLayerMask | groundLayerMask`。

### 相位提速不得自乘

`SkyIslandStormBoss.EnterPhase` 原本每进一档 `/= 1.25f`。两档时总量 1.56 尚可，相位加到四档后
复利成 1.25⁴ ≈ 2.44，再叠档次自带的 1.7 倍，末段反应时间只有官方拾荒者的 1/4.15 —— 没有反应窗口。
改为在 `Bind` 记下基线（此刻 `ApplyAi` 已跑过，基线已含档次倍率），按 `PhaseSpeedup(phase)`
算**绝对值**赋回，四档线性摊到 `MaxPhaseSpeedup = 1.6` 封顶，重复进入同一档不再叠加。

### 其余三条

- `SkyIslandEncounters.Spawn` 的 `sources[i % sources.Count]` 与遭遇身份无关：全岛 13 组的带队者
  永远是按名字排序的第一个 preset。改为 `PresetIndex(id, index)` 走 `StableHash`（不能用

## 2026-09-13 UI 美术化：图集分档、描边与对比度

起因是「天空岛界面还像原型」。盘点先推翻了一个前提：**`Assets/ui/bossrush_ui_skin` 早就存在且合规**
（8874 B / UnityFS 2022.3.62f3；六张 sprite 尺寸与 Border 逐项对得上规格表；`m_PixelsToUnits=100`、
RGBA32 未压缩、7296 个像素里 0 个 `R != G != B`），加载器也早就接在 `AlwaysOnRuntimeHooks` 上。
真正的问题有两层，都不是「缺素材」：

- **六张图只用了两张，而且分档太粗。** 加载器只取 `panel_surface` / `button_normal`，
  `panel_raised` / `divider` / `scroll_handle` 躺在包里从来取不出来；`ApplyPanelSkin` 只有
  「`radius >= 12` 用面板图、否则用按钮图」两档，于是 3px 的强调竖条与 12px 宽的滚动条轨道
  都穿着 32×32 / border 10 的按钮图——Unity 的 `GetAdjustedBorders` 会把 10+10 等比压进去
  并把中心区归零，画出来是按钮圆角的一道糊痕，**比程序化皮肤还差**。
- **图集里烤进去的内描边被深色 token 乘没了。** `panel_surface` 的描边像素与填充像素灰度差 49/255，
  乘上 `BossRushUIColors.Surface(0.045,0.055,0.065)` 之后屏幕上只剩 **2.9/255**
  （`SurfaceRaised` 上 4.9/255），是 8bit 量化底噪级别。规格 §2 的「描边画进图里」
  与「颜色一律由 `Image.color` 施加」在深色调上互相抵消，该条已在规格文档里作废并改写。

### 改了什么

- **分档扩到六档**（`BossRushUISkinPart`：Hairline / Rule / Button / Card / Panel / ScrollHandle），
  加载器五张全喂（`button_hover` 刻意不注入——按钮三态走 ColorBlock 绝对色，再换底图会和乘色打架），
  `Cleanup` 逐档复位再 `Unload(true)`（漏一档只有那一档白板，现场极难定位）。
  `radius <= 3` 一律程序化：任何图在 3px 上都会被压到中心区归零。
- **描边改成独立 Image**：`BossRushUI.ApplyPanelStroke` + 程序化「只有环、中心透明」的圆角九宫格，
  圆角按图集实际 border 取（`GetSkinCornerRadius`），色用新 token `BossRushUIColors.Stroke`
  （Divider 同色相、alpha 0.78）。实算：面板 / 右上卡片 / 选项行的边在亮云海到暗地形整个区间
  都稳在 **3.1:1 以上**（WCAG 1.4.11 非文本 3:1）。此前选项行底 `SurfaceRaised` 对面板底
  只有 **1.03:1**——不画边，玩家看到的只是几行浮着的字。
- **区域大标题的压暗底改曲线**：竖向从 `0.5-0.5·cos(2πv)` 的余弦钟形换成「两端 smoothstep + 中间平台」。

  改后三行都坐在平台上；压暗底同时加高到 340 并把淡出区拉到 0.28，免得平台曲线让它变成一块看得见的板。
  宽度按**实测文字宽**反算（`FitBannerScrim`）：英文落地提示整句能到约 700px，不扩宽的话行尾会滑进淡出区。
  字幕的压暗底同理按 `文字高 ÷ 平台占比` 给，两行字幕不再顶进淡出区。
- **`Success` / `Warning` 压暗约 7%**：旧值上 `GetButtonTextColor` 选白字，而白字压在旧 Success(L=0.180)
  只有 **4.15:1**、旧 Warning(L=0.170) 4.34:1，都过不了正文 4.5:1。压到 L≈0.15 后是 4.67 / 4.89；
  色相未动，亮底阈值余量反而从 40%/43% 升到 49%/52%。**这是全 Mod 级 token 改动。**
- **F3 天空岛面板的按钮标签改走 `GetButtonTextColor`**（此前写死白字：Accent 底只有 **2.23:1**）。
- **动效**（全部 SmoothStep / ease-out，不引入 DOTween 一类依赖）：右上卡片入场 0.22 s ease-out +
  右侧滑入 8px、退场 0.18 s 线性，取代 `SetActive` 硬开关；「目标更新」时强调竖条闪 0.5 s；
  大标题下的细横线随淡入 0.45 s ease-out 展开；字幕入场上浮 6px；剧情面板开启 0.12 → 0.18 s

### 结构口径

**夜限定在遭遇层，不在 Forge。** 自动组每个位置每趟只刷一次（`Spawn` 跳过 `Died` 与 `Life != null`），Forge 若因白天跳过装配，带队位就永久烧成一个挂着头目击杀键的白板拾荒者。所以：

- `Encounter.NightLead` 在装配遭遇表时读一次（`!Manual && SkyIslandBossForge.IsNightLead(id)`）。`LeadWaiting(encounter, 0)` 为真时，`Spawn` 在落点与创建之前跳过下标 0；`CountMissing` 也不算它，否则这一组每拍都被选中、饿死别的组。
- `AllDead` 跳过没刷出来的夜限定带队：白天随从死光照常清场、写 `clearedEncounters`。
- `Tick` 对已清场的组只放行 `NightLeadDue`（带队没死、没刷、此刻不再等夜）：入夜后玩家走近，带队单独补进已清场的组；死了这一趟就不再刷。
- 补刷的这一位照样算进同时存活上限（12）、`HasLivingEnemies` 与 `HasLivingEnemiesWithin`，剧情面板与保存的安全门看得见它。
- 判夜只在 `SkyIslandBossForge.LeadWaitsForNight` 一处：`SkyIslandNight.IsNight(SkyIslandLighting.ClockHours())`。守卫要求 `TryApply` 里不出现 `NightOnly`。

**两派：换阵营写在敌对安全网之后。** `Encounter.RivalFaction` 装配时读一次；`Spawn` 里 `created.SetTeam(Teams.wolf)` 原句保留，紧接着 `if (encounter.RivalFaction) created.SetTeam(Teams.bear)`，排在 `ApplyAi` / `ApplyIdentity` 之前，带队与随从一起换。官方 `Team.IsEnemy` 下 bear 与玩家、与岛上 wolf 拾荒者都敌对。`SkyIslandBossProps.CreateReceiver` 建的接收体阵营跟随 owner。

**面罩 / 耳机的耐久由控制器照官方口径磨。** 官方 `Health.Hurt` 在出击图上、非真实伤害且不无视护甲时，暴击磨头盔、非暴击磨身甲，面罩与耳机槽不磨。`SkyIslandRootHunterBoss`（FaceMask）、`SkyIslandListenerChief`（Headset）、`SkyIslandPiperChief`（FaceMask）各订自己的 `Health.OnHurtEvent` 调 `SkyIslandBossProps.WearSoftPiece`（暴击、非真实伤害、不无视护甲时按 `armorBreak` 扣），`OnDestroy` 退订，每 0.2 s 节流用 `SkyIslandBossForge.PieceBroken` 读一次。穗镰、镜中客、断风游猎的破甲件在头盔 / 护甲槽，靠官方磨损、不订受击；背包没有耐久，截信人与「伏」的装备联动按血线。

**`SkyIslandBossProps` 共用件**（R1 两位控制器除预警时长外不变）：

- `Teleport(character, target, pause)`：`seeker.CancelCurrentPathRequest(true)` → 给了控制器就 `BossAIController.Pause()` → `SetPosition`（回读不到位就直接写 `transform.position`）→ `Physics.SyncTransforms()`；暂停由调用方在硬直结束时 `Resume(CharacterMainControl.Main)`（自带重新认人）。悬根猎首伏击、断风冲步传控制器；截信人逃跑、镜中客翻身、`CallGroup` 传 null，不暂停。
- `CreateDecoy` / `DestroyDecoy`：蒙皮网格用 `SkinnedMeshRenderer.BakeMesh` 烤成静态网格，挂点上的普通网格共享原网格（最多 32 块）；共享材质，只用 `MaterialPropertyBlock` 调 `_BaseColor` / `_Color`；烤出的 `Mesh` 随倒影销毁。**不 Instantiate 角色**，那样会把身上的 `Item` / `ItemAgent` 一起复制。
- `CreateReceiver` / `Activate` / `Alive`：供能桩 / 云蚋同一配方（失活 → 伤害接收体层非触发球 + 运动学刚体 + `DamageReceiver{useSimpleHealth}` + `HealthSimpleBase` → 激活后与主角、owner `IgnoreCollision`），死亡看 `activeSelf`。
- `SkyIslandPlayerSlow`：经 `RuntimeStatModifierTracker` 在 `WalkSpeed` / `RunSpeed` 上挂负值 `PercentageAdd`，同来源同幅度只顺延；到时、出圈、Boss 倒下与销毁都 `Release`。
- 其余：`NoticePlayer`、`WornIn`、`TryMarker`、`SnapNear`、`ChargeRings` / `DestroyRings`。

**穿戴快照 `SkyIslandBossGearWorn`。** `SkyIslandFieldcraft.Tick` 里的 `TickBossGear` → `SampleBossGear` 读主角 Helmat / Armor / Backpack / FaceMask / Headset 五个槽（`SkyIslandBossForge.FindSlot`，不分配），写 `RootweavePieces` / `SicklePieces` / `WindbreakPieces`（`SetPiecesWorn`）与 `Earmuffs` / `MossgauzeMask` / `MirrorPlate` / `Mailbag`，并把 `MirrorPlate` 写进 `story.Current.wearsMirrorArmor`。招式控制器、`SkyIslandRewardCrate`、`SkyIslandGnats`、`SkyIslandWorldStoryBosses` 只读快照；离岛（`DisposeBossGear`）与模块销毁（`SkyIslandBossForge.ResetStaticCaches`）复位。R1 的星工两件套（合成时读三槽）与观星镜盔站定标敌（读头盔槽）仍在同一文件里现读。

## 2026-09-17 居民对白节奏与角色口吻（COMPAT / SAFE）

`DescribeNpc`、来信/点灯/放蛙提示与 `ResidentLine` 压成短句，保留原剧情条件与可达内容。晴禾、苇白的通用好感对白由 `DuckNpcs.json` 提供，分别围绕菜畦做饭与修灯风铃；剧情任务提醒留在能读取任务状态的 owner，避免日常问候无条件要求已经做完的活。

## 2026-09-22 全仓审计修复复核（COMPAT）
