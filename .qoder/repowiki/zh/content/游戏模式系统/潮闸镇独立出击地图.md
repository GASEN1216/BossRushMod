# 潮闸镇独立出击地图

2026-11-05 起接入，分类 `COMPAT / WIRE+ / SCHEMA+`（新存档键 `BossRush_Tidegate_Story_v1`、TypeID 500111–500115）。设计与原型见 `docs/design/tidegate-town/README.md`（local-only），作者资源与 Unity 构建见 `ArtSource/Tidegate/README.md`（local-only）。本文只记代码结构与不变式。

## 一句话

海边小镇跟着潮水涨落：潮位挂官方游戏时钟（一轮 4.5 个游戏小时），退潮露出滩涂、沉船与排水暗渠，涨潮淹掉它们并让栈桥渡口来船。从基地地堡下水道另一头的「闸伯的竹筏」进入，与天空岛一样走官方 `SceneLoader` 切图，是官方眼里与原版等价的独立出击关卡。

## 多图共用的独立出击基础设施（`Utilities/RaidScenes/`）

天空岛原先的场景身份桥写死只认一张图，而官方 `SceneLoader.LoadScene` 状态机上的转译补丁只能装一份（第二份找不到已被替换的 `LevelInited` 调用），所以接第二张图前先把它抽成多图注册表：

| 文件 | 作用 |
| --- | --- |
| [ModRaidSceneBridge.cs](file://Utilities/RaidScenes/ModRaidSceneBridge.cs) | 身份注册表 `ModRaidSceneIdentity`（sceneID、包内唯一 Scene 路径、Eflatun GUID）与全部官方前缀 / 转译补丁，全局只装一份；每个前缀只接管已登记身份自己的 GUID / sceneID / 场景实例。初始化令牌与黑幕租约是全局单份（同一时刻只有一段 Mod 出击加载）。最后一张图注销时才撤补丁 |
| [ModRaidLease.cs](file://Utilities/RaidScenes/ModRaidLease.cs) | 通用资源租约 + `ModRaidProfile`（包路径、根节点名、出生点、天气副本调整、场景钩子）。进图 `clickToConinue: true`，撤离照官方 `SceneLoaderProxy` 顺序，失败返航、官方加载标志复位与宿主销毁后的 `ModRaidRecovery` 与天空岛租约同语义 |
| [ModRaidOfficialContract.cs](file://Utilities/RaidScenes/ModRaidOfficialContract.cs) | 激活前合同与官方初始化后合同，判据与 `SkyIslandOfficialContract` 一致，按 profile 取出生点路径与必备节点 |

天空岛的 [SkyIslandSceneReferenceBridge.cs](file://SkyIsland/SkyIslandSceneReferenceBridge.cs) 现在只是身份门面（常量与原有入口不变）；天空岛租约与合同仍用自己的那份，迁到通用版是后续单独一步。守卫：`SkyIslandSceneReferenceBridgeGuard`（含「转译补丁全仓一份」）、执行回归 `SkyIslandSceneReferenceBridge`（真 Harmony，含第二张替身地图互不串、注销一张不影响另一张）。

## 淘沙帮跟潮走

刷怪点按标记名分组（`SPAWN_<组>_<种类>_<序号>`）。`dig` 组（淘沙帮）与 `vault` 组（开闸后的海堤增援）每 3 秒改一次官方 AI 的 `patrolPosition`：低潮且离涨潮超过 20 秒时下滩到 `WP_dig_*`（沙老大守在挖沙船跟前），否则回各自的刷怪点；增援等泻湖放干到 −0.9 m 以下才去 `WP_vault_*`。交火时官方行为树照旧。涨潮 / 高潮时泡在深水里超过 8 秒的淘沙帮被潮水卷走（直接移除，不掉东西）。

## 导航

导航网格由 `tools/build_tidegate_navigation.py` 从 three.js 导出的逻辑网格烘成「低潮时可走」的共形三角网（≤ 4095 顶点，当前 3456 / 3906 三角形），作者构建器放在世界根下的 `Navigation`（可读、只挂 MeshFilter），子网格 0 跟外海潮位、1 跟泻湖水位。三角形按高度带切，三个顶点 y 的最小值就是它的被淹高度：水位减去它大于 0.5 m 时 `TidegateTide` 把它设为不可走（`ArenaPrototypeNavigation.SetWalkable`，只改本图的 A* 图）。低潮时从出生点到全部标记单连通；高潮时挖沙船跳板被淹，那里的刷怪点与箱子被隔开——这是「跟着潮水走」的设计。进图时从出生点到每个刷怪点探一次路，够不着的点本趟不刷、记 `NAV_UNREACHABLE`，不让一个点拖垮整趟出击。

## 不变式与验证

- 守卫 `TidegateRaidGuard`：身份只经共用桥登记、进图点击继续、撤离官方顺序、注入早于合同早于激活、返航封锁源挂在本图、撤离读条冻结、刷怪安全网、着色器不降级、互斥、潮汐只读跨天连续时钟、竹筏只用正式模型且包随筏子卸载、正式构建部署场景包与竹筏包。
- 执行回归 `TidegateTideRules`：直接编译生产规则跑断言（相位、连续性、按官方进位走过三个午夜不跳变、泻湖、湿痕、深水与暗渠）。
- 部署前判包：`python tools/verify_tidegate_bundle_shaders.py`（默认两个包都查；环境 / 地形必须带 `UniversalGBuffer`，水面、灯塔光束带 `UniversalForward`，竹筏包只许环境着色器，不许有未登记着色器）。
- 五件物品的图标在正式版只从 `Assets/ui/production_icons` 取（`tools/production_icon_manifest.json` 登记，`tools/optimize_unity_resources.py --stage IconsBuild` 重打）。
- 人工清单：`Assets/Data/GameplayCoverage.json` 的 `M_TIDEGATE_*`。

证据级别目前是 L1/L2；切图、画面、水面、导航、刷怪与性能都没有实机采样。
