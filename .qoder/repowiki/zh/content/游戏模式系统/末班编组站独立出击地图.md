# 末班编组站独立出击地图

2026-11-11 起接入（第一至三期同日写完），分类 `COMPAT / WIRE+ / SCHEMA+`（新存档键、两件新物品）。设计与原型见 `docs/design/last-shift-yard/README.md`（local-only），作者资源与 Unity 构建见 `ArtSource/LastShiftYard/README.md`（local-only）。本文只记代码结构与不变式。

## 一句话

货停在哪由玩家决定，守卫也会跟过去：玩家在悬车楼司机室扳道岔，决定封签货车停西台还是东台，也就挑了取货时的战场。2026-11-13 起是快节奏的多趟激战：两分钟一班、每班停靠都能签一柜、签得越多押运越凶，第 8 班末班车一走就封站；每处有箱子的地方都有守货岗，重要几处由三种小队长带队。入口不在基地：官方仓库区（`Level_HiddenWarehouse`）西场第二座龙门吊外有余响的剪票处，在一趟进行中的出击里剪票上车，背包随身、中途不结算，只在编组站撤离或阵亡时结束这一趟。

## 和潮闸镇的关系

复用潮闸镇抽出来的多图独立出击基础设施（`Utilities/RaidScenes/`：身份桥、租约、合同，见 [潮闸镇独立出击地图](潮闸镇独立出击地图.md)），只登记身份，不另装官方 `SceneLoader` 补丁。差别：

- **出发地是一趟没结束的官方出击。** 租约照常以「不通知撤离、存档」请求官方切图；官方 `LevelManager.HandleRaidInitialization` 只在上一趟已结束时 `NewRaid`，所以从仓库区上车是继续同一趟（与仓库区 → 农场的官方转场同一路径）。天气副本从仓库区自己的户外 `TimeOfDayConfig` 克隆，不用基地出发时那一步换地堡室内 Volume。
- **着色器只有一个**：`BossRush/LastShift/Environment`（站场地坪与站外地面也用它，骨料细节层在着色器里）。全局量用自己的名字 `_LastShift*`，两张图互不串光照。
- **重复件是合并块**：轨枕、道砟、草木、栏杆柱在作者工程里按 48 m 分块合并、实例颜色烘进顶点色，运行时不再实例化。

## 快节奏改版（2026-11-13）

owner 原话：「都做吧，做成快节奏的多趟火车的激战，另外我希望玩家走到每个有宝箱的地方都有激战，然后小队长啥的你也设计一下可以不是 boss 但是有独特的机制和战斗方式。」此前的评估是主线流程只有「扳一次岔 → 打一仗 → 签一柜 → 北公路走人」，火车只对玩家起作用，撤离没有取舍，地图名里的「末班」没有玩法。本轮改动：

- **节奏**：一班 180 → 118 秒（净空 68 → 25 秒），一趟八班约 15 分钟；首班教学的预告 8 秒、停靠 90 秒不变。
- **火车是武器**：车头正面撞押运员同样生效，伤害记在玩家名下；调车长的溜放推车也会撞他自己的手下。
- **末班与封站**：第 8 班末班车恒为重载、必停，押运车厢尾梯是一个跟车走的撤离口；末班车进站即在北公路设卡，出站后封站（条件出口全关、道岔绑死、押运每 10 秒搜一次、补员最快），形成软时限。
- **贪心循环**：每班停靠可签一柜，续签件数减半但头格 Q5 概率逐柜上涨；签收柜数即押运警戒，押运车厢下车人数、小队长与补员速度随之上升。
- **每班一场仗**（owner 追问「敌人是每趟火车来都会刷新的吗？」后加）：列车押运每班至少 3 人、另记一本账不会用光；上一波远处闲着的跟车走；停靠那一侧打光的守货岗补岗。经济改动由 owner 这句「都做吧」授权（上一轮已说明这一条会改经济产出）。
- **加价台逐班抽、进站揭晓**：扳岔变成押注；故事收尾后余响与运单牌提前告知下一班的加价台，作为剧情奖励。
- **每处有箱子的地方都有激战**：守货岗按地点逐处开，重要几处由小队长带队。

## 第三轮实机修复：还在闪、人身上没亮、押运长离签收太远、签收太少（2026-11-13）

- **还在闪**：截图里那些锯齿边的深绿 / 土黄大块是 three.js 的磨损地皮（`yard-details.mjs` `stain`，`Connected yard / worn ground 0–3`）。原型里它是顶点 alpha 贴花（斑心 0.24–0.64、外圈 0，`transparent` + `depthWrite:false`），第二轮把它当共面层，顶点 alpha 被改写成层号、进 Unity 按不透明画，几百块斑在同一张网格里互相压着闪（约 4950 m²）。现在组装脚本 `mark_vertex_alpha_decals` 按「材质 Alpha 直接接顶点色」认出贴花，保留原 alpha、不进分层，清单记 `decal`；作者工程构建器给它建透明队列、`SrcAlpha / OneMinusSrcAlpha`、不写深度的材质，着色器前向 pass 的 `Blend` / `ZWrite` 改走材质属性。另外共面分层的单位从对象细到「对象里的连通块」（同一张网格里的院落地坪、枕木、废轨互相压着，约 1461 m²），当时同层重叠为 0、最高第 5 层。独立验收又发现原 0.02 m² 单面 / 0.01 m² 交集门槛漏掉很小的面；现移除视觉面积门槛，仅以 1e-8 数值容差排除退化面，并跨空间分桶边界比较，由 `LastShiftCoplanarPropertyTest` 回归。FBX 可用 `tools/rebuild_lastshift_fbx_layers.py` 只重排分层，坐标 / 索引 / RGB / UV 等不变；本次未重新生成 .blend，构建证据见 ArtSource README。
- **人身上没亮**：灯数组只有自研着色器读；[LastShiftLighting.cs](file://LastShiftYard/LastShiftLighting.cs) 第三轮最初加了四盏强度 2.4 的普通点光，后续实机仍不满足人物亮度。现按官方 `SodaPointLight` 路径改用 `SodaPointLightMesh` / `ZeroPoint` 占位材质，官方相机 `SodaLight` RenderObjects 在延迟光照前覆盖绘制；通过深度 / 法线 / GBuffer 反照率给角色补光，自研环境 albedo 为 0，仍只走环境灯数组。主相机的真实 feature / 层 / 材质 / 事件读回校验，缺失时明确记录回退实时点光。会话先按本帧脚点更新房间，再切换补光，进出屋当帧切换。
- **押运长 / 签收**：见上表 `LastShiftEnemies` 与 `LastShiftLoot` 两行。
- **官方网格灯跨图**：`LastShiftSession` 在 `lease.BeginLoad()` 前调用 `lights.PrepareIndoorFill()`；停用 DDOL 节点克隆最小安全 SodaPointLight 叶组件与其共享网格 / 材质，不复制房间或父级触发器。世界材质检查后 `lights.Bind(world)`，结束或装配失败均 `Dispose`；官方源组件随仓库卸载不会令补光失效。日志 `INDOOR_FILL_READY mode=SodaPointLight` 只确认通路，最终亮度仍需目检。
- **从地坪冒出的草**：四组 `Connected yard / grass ribbons 0..3` 与 `Verges and drainage reeds` 是地图原型细节脚本生成的 8451 个三角面，初版到去草前各版 Mesh 字节相同，不是官方额外草生成器。当前包关闭这五个 Renderer，源 FBX 移除对应 leaf Model/Geometry，原型不再输出、旧 GLB 在 Blender 组装时按精确名称过滤。其它地贴、树冠、灌木、围栏及随机序列不变，工具 `tools/remove_lastshift_grass.py`、名单 `tools/lastshift_vegetation.py`。
- 守卫：`tests/LastShiftReadabilityPropertyTest.py` 第三轮段（源码 + 组装 / 构建报告的 `decals`）。
