# 天空岛生产复核与交付前置

## 2026-09-30 场景净空、穿模与质感

实机反馈：房子、桌凳压在路上，模型互相插、悬空，部分件像塑料。57a5408f 的判据只覆盖村口家具与 Tripo 锚点件、按道路中心线查，岛缘散布（树、石、灌木、花）、按旧坐标画的地标零件（风铃集圆桌凳、镜水寺石灯、邮亭、码头货箱、洞口灯）、灯标记处的铜灯、中继平台灯都没过判据；几处替换成 Tripo 件后的程序化地标（风铃横梁、S1 圆池、S3 球石洞、S4 望远镜）是重复发射。

新流程：生成器 `--audit-ledger` 给每件东西记实例台账（真实世界网格），`tools/sky_island_scene_audit.py` 按离地 0.06–2.2 m 身体层与高度带截面判压路（路面 + 0.2 m 路缘）、互穿、悬空（接触图：不接地也不接任何实体）、陷地、伸出岛缘、挡桥口 / 门口 / 玩法标记 / 运行时物件、共面闪烁；运行时物件由 `tools/sky_island_runtime_placements.py` 复用两份属性测试的落点复算。修法统一为 `PlacementSpace.fit`：量实际截面、就近平移或撤下，花草最后撒。结果：修前 352 条、修后 0 条（23 条设计接触逐条写理由）；Unity 碰撞校验与 ECM2 移动实跑 0 失败。

质感：39 个环境材质改为「颜色进贴图、`_BaseColor` 全白」（`tools/sky_island_surface_textures.py`；原有平铺材质保持 1024²，新增调色板材质 512²）。Tripo 件焊接后按平滑扇区求法线（共享一条 <40° 的边即同扇区，平滑面不留折痕、棱角保持硬边），岛缘卵石走别名材质 `Pebble` 单独成组带上法线。26 张 Tripo 图集从原件重导到 1024 / 2048。水晶类光泽 0.64 → 0.28–0.42，发光材质底色压到 0.5，自发光按日照压暗，花圃小植物轻量版（每丛 8.7k → 4.5k 三角形）。瀑布水 / 石分面在整件上求同一份扇区法线；面的朝向取「源绕序」与「bmesh 定向」里相邻冲突少的一份（bmesh 在非流形边处会整块翻反）。全场可见三角形 3,426,285 → 2,904,928，渲染器 840 → 824，材质 99 → 98；包体 160.9 → 232.3 MB（BC7 贴图 34 → 90 MB，网格 318 → 283 MB）。

第一轮出包后另做了一次只读材质复测，查出第一轮自己留下的退步：石木瓦平铺图烘成 512² 让纹素减半，逐面取邻面平均的法线在平滑面上仍有折痕，卵石没吃到新法线；第二次复测又查出瀑布仍走旧法线、卵石被整块翻反。第三次出包全部返工，场景级 Tripo 折痕全 0%、绕序冲突 ≤0.19%。复测还发现生成器给巡守槽位让位会形成「几何 → 导航 → 槽位 → 几何」的环：槽位从导航派生，生成器现在不读它（`DERIVED_RUNTIME_KINDS`），场景审计照样查槽位净空。

路灯夜间照明（2026-10-01）：
- 原先的问题：雕花路灯与铜灯柱的灯罩是图集里画出来的不透明玻璃，塞在里面的发光灯芯被挡住；岛上也没有任何灯光源。环境着色器自己算光照（`UniversalMaterialType=Unlit`），URP 点光源照不到岛面。

- 守卫：`SkyIslandStreetLampGuard`。

## 2026-09-30 模型碰撞与部署

作者 `.blend` / FBX 的岛地面保留完整轮廓；建筑占位只供设计导航避让，不能再裁掉玩家脚下地面。Unity 的 `SkyIslandCollisionBuilder` 从最终硬质 VIS 面生成双面静态非凸碰撞，保留门洞和树下空间；旧名义墙体包围盒不再发布。Flora、Paving、GroundDetail 和软材料按生成分组排除，斜桥支柱按桥面坡度避开桥板。

`ArtSource/SkyIsland/collision_navigation.json` 是发布 NAV，设计布局仍保留在 `layout.json`。生成阶段需核对布局、重新枚举当前硬物名称集合并校验含桥梁的全硬物指纹；新增、删除或硬软转换使旧 sidecar 失效。高度切片的岛区对象名单与签名的全硬物名单分开。修改模型后按 [NAVIGATION.md](../../../../../ArtSource/SkyIsland/NAVIGATION.md) 重建。作者数据的几何连通、门控组合、最终 raid 包 PhysX 射线与胶囊扫描属于 L2；实际角色移动、AI 跟路、战斗和帧时间仍需 L3。运行时 ground / wall layer 由 `SkyIslandRendering` 在激活前按官方 mask 重绑。

2026-09-30 已用正式构建替换上轮 Dev DLL，并将通过验证的 raid 包部署到本机游戏 Mod 目录，实际目标 SHA-256 与构建产物一致。完整记录与 COLL-01～06 的操作、截图命名和不合格条件见 [模型碰撞交付报告](../../../../../docs/reports/sky-island/2026-09-30-天空岛模型碰撞修复与交付.md)。本轮没有启动游戏或访问玩家存档，不能沿用旧实机结论。

## 2026-09-29 发布前复审

正式进岛的第一次场景等待经 `SkyIslandRaidLease.HasSceneLoadTimeRemaining` 计时。官方 `SceneLoader` 在激活目标场景之前等待“点击继续”；只有本租约仍在加载、未释放、无错误且公开诊断为 `Wait for click...` 时延长期限，真正读包与点击后激活仍保留超时。官方更新若改变这句诊断或顺序，要重新对照 DLL。`SkyIslandLifecycleGuard` 钉住 Session 的调用点，生产租约执行回归覆盖长时间等待、错误、取消和真实超时。

## 已确认并修复

`CR-2026-09-11-004`，P1 / COMPAT：原 `SkyIslandWorldStory.GrantKeepsakes` 先 `RecordNote(Keepsake_*)`，随后 `SkyIslandItems.TryGive` 才查询 prefab 和实例化。缺资源或实例化失败会永久记为已发；资源恢复后 `SkyIslandItemRules.Due` 仍拒绝补发。晴岚航徽和噬风之核已有回码头、服务半价与减风功能，因此会造成实际玩法奖励永久缺失。

现在 `TryGive(typeId, toStorage, recordGrant)` 先准备有效实例，再执行记账回调，最后转移到原目的地。准备失败不调用回调；回调拒绝或抛异常时清掉临时实例；真实转移开始后的异常仍保留已记台账，避免不确定的转移被重复结算。没有增加存档字段，也没有把死亡、卖掉或以前已经标记领取的物品自动补发。无法从历史台账中区分旧版误记与玩家主动处置，需要人工证据后另行处理。

`CR-2026-09-11-005`，P2 / COMPAT：原 `SkyIslandGnats.TakeSpawn` 在当前存档已只读时仍允许扣一把云苔纤维捧蛙卵，`ReleaseSpawn` 才拒绝记录。已知失败的交付仍能接取，玩家会白耗材料与往返时间。现在取蛙卵时先检查 `story.CanWrite`，显示同一份 `SaveStatus`，然后才允许扣材料；正常夜间接取与交付仍走原规则。

## 图集模型的接缝修复（COMPAT）

`tools/sky_island_surface_repair.py` 是独立 Blender 候选工具，不自动修改作者源件或主生成器。带图集 GLB 经常按 UV / 法线拆开同位置顶点；直接对这种网格执行 COLLAPSE，会分别移动接缝两边，产生真正的透底裂口。工具从原 GLB 重新归一化，在 0.000001 米范围内接合重合位置，再沿用原面数预算减面。UV 保存在面角，接合前后逐项校验面角的几何位置与图集坐标关系，最终仍按既有逐顶点 UV 契约导出。

首批候选为 `cave_rock / rock_b / glow_crystal`，来源、原 JSON 与候选 SHA、原件未修改证明、正反 3/4 画面及固定视幅对照保存在 `Build/sky-production-20260914/surface_repair/`。主体缺口减少不等于所有边界都该封闭：贴地底口、原生叶片与相互咬合的晶簇单独审查，工具不自动填这些面。原 `meta.bounds` 作为既有生成与碰撞声明保留，候选实际顶点包络另报，不能把声明未变写成模型每个点未变。使用 `--output`、`--report` 指定独立文件；工具拒绝覆盖原模型路径。采用候选、重导世界和 Unity 验证仍由主生产流程统一执行。

`--contain-placement-bounds` 对超出原范围的轴做最小平移，只有实际跨度大于旧区间才收缩；已在区间内的轴保持原样，不撑满旧减面碎片产生的异常极值。超过 3% 的缩放直接拒绝。候选保留 `meta.bounds`，另记 `meta.actualBounds` 与 `surfaceRepair.placementFit`（适配前包络、缩放、平移），要求每个实际点落在原声明内。最终前三件采用 `surface_repair/contract/` 的约束版。`great_tree` 原来已保留全部 8,831 面，原 GLB 与当前模型拓扑一致；单纯接缝恢复没有实际改进，审图结论为 KEEP，冠层体积属于另一个造型问题。

## 瀑布流水分面与法线（COMPAT）

`tools/sky_island_surface_materials.py` 只对 `waterfall` 取原图集内部样点，把明确青蓝流水放入 `TripoCascadeWater`，其余石壁、苔藓和混合泡沫边缘放入 `TripoCascadeStone`。两组复用原图集和源 UV，几何位置与三角形不变。`crystal_fountain` 的顶部实体晶体也使用青蓝色，颜色分类会误认为流水，因此不支持喷泉分面，保留原静态 `TripoCrystalFountain`。

分面的水网格是开口表面，不能对两个组分别重算法线。先在每个实际实例的世界坐标上，按原未拆分整件的 `create_object` 路径取得面序与每个面角的平滑法线；通过 `addmesh` 的可选 `corner_normals` 传到最终对象并显式设置 Blender custom split normals，跳过该组的独立 recalc。源件有开口和薄片，旧 bmesh 的定向选择会受摆放影响，不能把局部缓存法线只旋转后当作该实例的旧 whole 结果。其它普通几何保留原处理。显式法线与面角数量不匹配、源有退化面、同组混入未保留法线的几何均拒绝生成，不能静默丢弃法线。

Environment / Water 的双面着色使用 `SV_IsFrontFace` 修正法线，面序和法线同时翻转 180° 不能单独作为可见缺陷。验证要比较修正后的角差，并通过实际 FBX 导出再导入检查法线传递、位置及 UV，而不只检查 Python 数组。证据与正背原图集 / 分类 mask 位于 `Build/sky-production-20260914/surface_materials/`；真实流水高光和完整场景由 Unity 总体审图确认。

第三轮独立导出在原坐标与 yaw=37.25°、1.15 倍缩放、世界平移两个实例上实测：每件 3,722 面和 UV 完全对应，面序与平滑标志不变，生成位置误差为 0；FBX 往返位置最大误差 0.000038 米，法线相对原 whole 最大角差 0.106°，其中 FBX 传递本身额外误差小于 0.0033°。这不是逐位相同的法线承诺，保留的显式法线有小角度误差；旧拆组出现的 >5° 残余已归零。实际报告为 `surface_materials/round03/retained_normals_validation.json`。

## 2026-09-14 生成结果稳定性、网格精度与云层（COMPAT）

`tools/sky_island_tripo_props.py` 用 `stable_seed` 的 CRC32 固定随机种子，不再用随 Python 进程变化的字符串 `hash` 决定障碍物朝向。`ArtSource/SkyIsland/model_orientations.json` 封存由原始 World 反解的 29 个障碍物和 35 个锚点朝向；缺省项使用确定种子。绘制和 `collision_fit` 共用 `obstacle_yaw`，避免生成外观与碰撞盒分别转向。两次独立 `PYTHONHASHSEED` 进程原先出现 21 个碰撞 / 29 个外观差异，修复后均为 0。最终 146 个盒与 82 个标记逐值恢复基线；最终 FBX 的 284 个导航、地面、碰撞和标记对象也逐项相同。固定朝向文件是生产输入，不是可丢弃的审查缓存。
