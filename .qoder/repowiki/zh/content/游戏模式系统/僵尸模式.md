# 僵尸模式

## 运行时 Tick 与暂停时钟归属（2026-09-24，COMPAT）

`ZombieModeRuntimeModule` 持有局状态、入场事务、道具生成候选缓存与局内 Tick，并执行暂停判据及按 `unscaledTime` 累计的时钟。宿主 `TickZombieMode` 和暂停 API 保留兼容转发；原控制器调用顺序、传入的 `deltaTime`、模态与官方暂停门维持不变。`AuditModeLifecycle` 直接抽取生产模块 Tick 和暂停方法，验证暂停期间不推进局内时钟、恢复时不补计暂停时长、无活动局时重置。奖励目录、选项生成、刷新与选择也已迁入模块；效果发放和临时 NPC 服务也由模块奖励 partial 执行，RunOnly 记录由模块持有。

## 污染与敌人行为叶子迁入（2026-09-25，COMPAT）

污染叶子的宿主业务状态、调优与词缀方法、特殊 / 精英运行时技能、区域伤害及技能协程现由已注册的 `ZombieModeRuntimeModule` partial 执行：视觉逻辑在 `ZombieModeRuntimeModule_Pollution.cs`，权重、属性和受击逻辑在 `ZombieModeRuntimeModule_PollutionTuning.cs`，技能与区域效果在 `ZombieModeRuntimeModule_PollutionSkills.cs`。`ZombieModeCombatHostBridge.cs` 与 `ZombieModeCombatHostBridge.cs` 保留旧签名的兼容转发，以及与刷怪器和场景协程衔接的窄桥；波次阶段判断、运行时钟、随机采样顺序和协程 yield 点沿用迁移前流程。相关守卫直接检查模块方法体，`AffixCombat` 从技能模块抽取原生爆炸实现验证调度、暂停和兜底路径。

## 奖励目录与局内选择叶子迁入（2026-09-25，COMPAT）

奖励目录构建、按类别加权抽取、早期保底选项、选项展示文本、节点创建、免费 / 付费刷新、选择结算和净化点数扣退由 `ZombieModeRuntimeModule_RewardCatalogAndSelection.cs` 执行。当前节点、剩余选择次数、刷新余额与付费刷新序号继续存放在模块持有的 `ZombieModeRunState`；目录列表仍是每次抽取时临时构建的局部对象。模块沿用原 `Random.Range` 调用位置与循环顺序、分类权重、保底条件和所有奖励键 / 数值；选择发放失败时保留节点，Boss 追加选择只在奖励成功后扣减并重抽，常规选择仍先结算，再进入撤离机会或准备阶段，并按原序生成临时 NPC。宿主 `ZombieModeRewardHostBridge.cs` 保留旧公开入口转发；奖励效果、金额计算、临时 NPC 和面板创建 / 重排现由模块 partial 在原位置直接调用。相关守卫现在直接读模块实际方法体，覆盖候选目录、权重、刷新扣点与选择事务。



## 波次控制器迁入运行模块（2026-09-25，COMPAT）

准备与战斗阶段推进、环境丧尸压力、击杀目标、Boss 波调度、死亡事件处理、净化星生成和波次结算现由 `ZombieModeRuntimeModule_WaveController.cs` 执行。`ZombieModeRunState` 仍由 `ZombieModeRuntimeModule` 持有；事件委托也由模块登记到 RunOnly 清理通道。宿主 `ZombieModeCombatHostBridge.cs` 保留旧入口的兼容转发；刷怪、净化点和附近安全区敌人清理由模块直接调用。

Tick 仍按既有模块调度顺序接收原 `deltaTime`。迁移保持 runId 校验、定时来源、随机调用位置、异步 `UniTask.Yield()` 与结算协程 `yield return null` 的位置和次数。波次压力、暂停门、生成阶段谓词、死亡计数和掉落顺序的守卫现在检查模块实际方法体。

## 安全区与敌人空间查询归属（2026-09-25，COMPAT）

`ZombieModeSafeZoneController.cs` 的业务 partial 已归 `ZombieModeRuntimeModule`，包含两槽位置与边界判断、周期驱逐、威胁距离保存 / 恢复、射击事件订阅及两种附近敌人清理。文件中的 `ZombieModeSafeZoneController` 仍是按实例保存 RunId 的 Unity 组件。`ZombieModeRuntimeModule_EnemyRuntime.cs` 持有可复用敌人查询缓冲区，并执行 RunOnly marker 收集、Owner / AI 缓存、主角索敌、重力牵引和最近目标选择；波次、Boss、撤离与 HUD 在原调用位置直接使用模块方法，宿主保留未迁调用方需要的转发。

安全区 Tick 继续使用原 `Time.unscaledTime` 节流，并先计算抑制条件再驱逐。新部署清理保持先注销敌人身份，再调用绑定的恢复监控注销入口、减少存活计数、停用并销毁对象，最后剪枝 RunOnly 记录；Boss 只驱逐，波次击杀目标不变。射击订阅标记归模块实例，并由原 RunOnly 回调退订和重置。`ZombieModeSafeZoneRuntime` 直接编译生产安全区与调优文件，抽取生产空间查询和记录管理方法，覆盖双槽边界、威胁恢复、销毁顺序、跨 run 隔离及订阅幂等；真实导航、枪械命中与切图仍需游戏内验收。

## 奖励执行、掉落与临时 NPC 归属（2026-09-25，COMPAT）

奖励应用、属性 / 弹道 / 战场 / 触发效果、保险结算、商店与医疗服务、普通和 Boss 掉落、容器补货及临时 NPC 创建 / 回收现由 ZombieModeRuntimeModule 的既有奖励与掉落文件执行。ZombieModeRewardEffects.cs 中的健康订阅、手持订阅、散射快照与清理标记，以及 ZombieModeDropsAndPerformance.cs 中的拾取扫描时间归模块实例。原 Unity 组件保留在同文件；宿主旧接口集中于 ZombieModeRewardHostBridge.cs 向下转发。

ZombieModeRewards.cs 接管候选标签、品质筛选、候选缓存算法和奖励面板创建；ZombieModeRewardItemGrants.cs 接管共用弹药 / 道具辅助；ZombieModeBackpackJunkRecycle.cs 的业务 partial 归模块。原缓存对象仍由已有挂载流程接管。NPC 创建只接收资源解析与 Courier 交互两个窄依赖：原资源加载成功后读取 prefab，每个原调用点只解析一次，再按原顺序实例化和接线。模块内部的选择、波次、撤离与清理路径直接调用这些方法。

本次保持原随机调用、等待帧、时间源、数值和失败处理。服务先扣点，发放失败退回净化点，成功后才扣库存 / 使用次数；属性与奖励清理仍先于 RunId 失效；NPC 服务关闭、RunOnly 回调和销毁顺序不变。ZombieModeRewardRuntime 抽取生产字段和方法验证服务事务、事件 owner、资源调用次数及 NPC 回收；RuntimeOwnership、AffixCombat 与 AuditModeLifecycle 继续执行生产掉落归属、爆炸和生命周期逻辑。真实物品树、碰撞、商店界面和切图仍待 L3。

## 刷怪、开局与地图隔离归属（2026-09-25，SAFE）

`ZombieModeSpawner.cs`、`ZombieModeEntry_StarterLoadout.cs`、`ZombieModeMapIsolation.cs`，以及现金与净化点文件中的业务 partial 均归已有 `ZombieModeRuntimeModule`。模块持有刷怪点去重网格和原版地图对象隔离记录，负责异步刷怪、暂停等待、开局发放、现金校验、SoulCube 查询缓存与净化星结算。视觉缩放恢复和脚标回收归 `ZombieModeRuntimeModule_EnemyRuntime.cs`；同文件 Unity 组件和现金弹窗视图保留原实现，宿主公开入口继续转发。

刷怪仍在原位置调用共享 `SpawnEnemyCore`，保留 runId / 阶段门、名额预占与一次释放、暂停回调销毁后重试、随机采样与 Boss 生命周期登记顺序。开局仍先完成武器、保底治疗、弹药和防具发放，再确认资源并进入 Active；现金校验失败保留旧选择。地图隔离按预缓存、刷怪器、撤离点、角色的顺序执行，恢复按角色、刷怪状态、撤离点的顺序执行。净化星逆序结算，失效 run 只清记录、不加点；SoulCube 未命中缓存沿用，视觉清理保留 destroyed-null 容错。

环境桥只提供原缓存数组、缓存场景名、刷怪器重置 / 禁用和恢复锚点登记的原始单语句；NPC 场景判定继续传入原宿主 `owner`。`ZombieModeSpawnRuntime` 抽取生产异步方法验证暂停、名额、随机 / 登记顺序和敌对兜底；`ZombieModeStarterRuntime` 验证发放失败、现金、净化结算、隔离与视觉清理。两者属于 L2，导航、真实物品树、UI 和跨场景表现仍需 L3 验收。

## 追加爆炸与局内清理（2026-09-17，COMPAT）

暴击爆发、末日脉冲、特殊 / 精英 / Boss 死亡爆炸共用 `ZombieModeRuntimeModule.DeferExplosion`：先让出一帧，离开原始 Hurt / Dead 调用栈，再检查原局、关卡和主角身份 / 存活。暂停时等待；局内清理通过既有 `RunOnlyObjects` 停协程，完成 / 取消 / 调度失败即移除记录。没有另建队列或常驻 Update。末日脉冲的入口校验、三次几何计算与爆炸调度都归模块，范围 / 伤害 / 触发计数不变。

玩家光环与弹道尾迹按效果来源结算，不冒充直接命中；禁止自伤的玩家区域效果在官方接口失败时也不会回退为打自己。敌方技能保留原来源、阵营与 player-only 后备。`AffixCombat` 链接真实模块和逐字入口，覆盖暂停 / 取消、批量反向清理、持续触发不积累记录与参数保留；不代表物理、特效或帧时间已经过实机。

## 掉落回收归属保护（2026-09-05，COMPAT）

普通掉落候选的全表拾取扫描仍按一秒间隔执行，但任何达到回收条件的候选在销毁前都会进行本帧背包/装备槽归属检查。已被玩家拾取的物品仅注销清理记录，不销毁物品；未到期候选不会因此增加逐帧组件扫描。可见掉落 agent 与 Item 根对象的位置不同，所以距玩家 5 米的保护区不能代替所有权判定。Boss/高价值豁免、回收时间和下一波规则保持原值。

## 简介
本文件面向“丧尸生存模式”的系统设计、数值与实现要点，覆盖污染系统、净化点经济、波次控制器、安全区管理、奖励系统、敌人行为模式、生存挑战、资源管理与策略规划。文档以代码为依据，提供流程图与时序图帮助理解关键流程，并给出可操作的调参与集成建议。

## 项目结构
丧尸模式由多个职责清晰的模块组成：
- 入口与生命周期：负责入场校验、资源暂扣、地图加载、运行期状态机推进。
- 波次控制由 `ZombieModeRuntimeModule_WaveController.cs` 负责准备阶段、战斗阶段、环境压力、刷怪节奏、Boss 波调度与死亡事件结算；刷怪与净化点业务由模块 partial 执行，宿主文件保留旧入口转发。
- 污染与敌人：根据污染度调整敌人生成权重、词缀、属性缩放与视觉标识。
- 净化点经济：击杀掉落净化星，自动磁吸拾取，转化为净化点数用于刷新与交易。
- 安全区：部署时立即清除区内非 Boss 丧尸并把 Boss 移到边界外，周期性维持丧尸禁入；玩家在当前安全区内直接伤害丧尸会立即取消整个安全区，圆圈、地图 POI、绑定终端、仇恨压制和丧尸禁入同步解除。一次性便携安全区装置按阶段分流：战斗期使用便携装置会替换主槽安全区，本波结束后由准备期流程重新生成带商人的正常安全区；准备期使用则写入独立副槽，与带商人的正常安全区并存，两槽在下一波开始时一起清除；替换主槽时清理旧视觉、地图 POI 与绑定临时 NPC，写副槽时保留主槽商人。取消判定只认枪械与近战直伤，手雷、投掷物和玩家来源的奖励弹道不会误取消。
- 奖励系统：`ZombieModeRuntimeModule` 负责目录抽取、节点选择和刷新扣点；奖励模块 partial 创建 / 重排面板、发放效果并提供临时 NPC 服务，宿主保留旧入口转发。面板默认只显示当前休息时长和「修改/Edit」按钮，点击后展开 15 秒步进的 15～300 秒选项，初始和回退值为 45 秒，玩家修改后跨波次沿用；经济奖励包含高权重的背包低品质普通废品回收，仅处理没有附件、插槽内容或内置库存的叶子物品，装备奖励包含一次性便携安全区装置。
- HUD：主面板、安全区面板、阶段面板，按节流刷新降低 UI 开销。
- 配置与模型：统一数值常量、枚举与运行时状态对象。

## 核心组件
- 入口与生命周期：入场预检、资源暂扣、地图加载、运行初始化、暂停/恢复时间轴、失败回滚。
- 波次控制器模块：准备倒计时、战斗阶段、周期刷怪、目标击杀数、Boss 波、撤离机会，以及死亡事件与波次结算。
- 污染系统：污染度影响精英/特殊敌人权重、词缀解锁层级、敌人属性缩放、视觉标识。
- 净化点经济：击杀掉落净化星，磁吸+距离拾取，累计为净化点数；用于刷新选项与临时 NPC 服务。

### 净化点经济

撤离时净化点兑换现金必须以后端 `EconomyManager.Add` 成功为准。若经济实例暂不可用，系统保留本局净化点并回到撤离机会，玩家可稍后重新撤离；只有现金到账后才清零净化点并完成场景清理。
- 入场资源回滚走**可持久化欠账账本** `ZombieMode/ZombieModeEntryDebt.cs`（2026-09-12 修 `CR-2026-09-11-019`，`SCHEMA+`）：
  入场先扣邀请函再扣现金，任一后续步骤失败就回滚。但回滚发生在切图途中——`EconomyManager.Instance`
  已随场景销毁（`Add` 返回 false）、`ItemAssetsCollection.InstantiateSync` 可能因资源未就绪返回 null。
  修复前两处都丢掉返回值、还在 `finally` 里无条件清事务状态，玩家花掉的入场费与邀请函会永久蒸发。
  - 账本两个原始类型 key（`BossRush_ZombieMode_RefundDebt_Cash` / `_Invitations`），老档缺键即 0；
    写入后回读核对（官方 `SavesSystem.Save` 在没有当前存档文件时只打日志就返回）。
  - `RefundCash` / `RefundInvitation` 返回「这笔账了结了没有」：退成功或已记进账本都算了结（宿主清事务状态），
    **连账都记不下才返回 false**，宿主据此保留事务状态等下一次清理路径重试。
  - 结账**先到账再销账**；销账失败仍可能重发，保留既有至少一次补偿语义。邀请函逐张推进，中途资源或接收方掉线时剩余张数留在账上。
  - 2026-09-25 修复“已实例化却未送达”：先确认角色/完整仓库就绪，再核对入包、入仓、有效拾取物或 Buffer 内同实例 ID 的物品树。投递前异常不销账；投递后通知异常已有回执则不重发；无归属临时物由交付方法清理。

- 奖励界面卡住：确认输入租赁与关闭逻辑，避免模态阻塞。
