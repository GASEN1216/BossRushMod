## 简介

局内随机事件是在战局进行中按冷却与权重随机触发的限时事件：横幅播报 → 生效 → 到时清理。

它与变异词条构成互补：词条在开局抽定、整局恒定、无时长；事件是限时的、有播报、有调度。
两套系统实现完全独立，只共用底层设施。

系统零存档、零新物品、零自有 Harmony、零新增音频文件。动态商人复用官方角色时会经过共享的
MagicBlend 初始化顺序兼容补丁；该补丁属于全局官方运行时兼容层，不改变事件状态机边界。

## 调度器

状态机：`Dormant → Armed（开局冷却）→ EventActive（并发恒为 1）→ Cooldown → Armed`。

局开始与结束的检测**不侵入各模式的启停代码**，而是用 run signature 边缘轮询：
每帧只做 O(1) 的 bool 读并组合成签名，`none → some` 视为开局（重置计数与冷却），
`some → none` 视为局末（触发全量清理）。

这样做的原因是标准模式的结束路径至少有四处（胜利、死亡、切图、模式专属 End），
逐处插调用既侵入又容易漏；边缘检测天然覆盖全部路径。

一个重要细节：调度器只认「局进行中」，**不认竞技场空闲态**——空闲竞技场有清怪维护循环，
会把事件生成的实体直接清掉。

## 波次隔离

这是本系统最高危的一面。

标准模式与无间炼狱按 Boss **实例匹配**推进波次；Mode D 用逐实例死亡监听。
「Boss 乱入」生成的额外 Boss 必须对这些状态机完全不可见——不写进波次容器、不注册波次死亡回调。

否则会出两类只在实机长局里偶发、人工冒烟抓不到的事故：

- 乱入被计入本波：玩家清完波次却不推进（卡波）；
- 乱入死亡被当成波次 Boss 死亡：波次提前推进（跳波）。

因此设了静态守卫 `tests/RandomEventsWaveIsolationGuard.py`，直接锁死符号面：
`RandomEvents/` 下不得出现任何波次状态机符号。

乱入生成还有两条硬要求：`onCommit` 必须包含敌对性安全网（官方 preset 队伍可能是中立，
漏掉会生成一只不攻击也打不死的雕像），以及固定的 `RndEvt_Intruder_` 命名前缀便于排查残留。

## 模式门控

只在**标准 BossRush / 无间炼狱 / Mode D** 三个入口启用。其余六个入口一律禁用，各有理由：
Mode E 的多阵营与扫箱令交互语义不清；Mode F 的悬赏雷达只认注册过的 Boss 且阶段播报已密集；
Mode G 是固定九波编排与严格奖励事务；Mode H 是观战且独占清场；丧尸模式有独立奖励体系；
普通撤离图上官方 spawner、任务与天气都活跃。

判定形态照遗种巢的模式门控：**先排除后允许**，任何异常都落到「不启用」（fail-closed），
且只经公开门面判定，禁止引用别的模式的内部闸门符号——那会把两个模式的生命周期焊死。

## 与变异词条的边界

两者生命周期语义相反，硬塞进同一套 roll 基建会破坏共享变异系统的不变式。
因此实现完全独立，只共用底层设施（临时属性追踪、生成核心、横幅播报、局内清理注册表、共享 UI 库）。

有一处刻意的联动：乱入 Boss 走 Legacy 生成路径，因此会自动吃到当局的变异词条效果，
与在场其他敌人保持一致，体验上是自洽的。

## 契约与注意事项

- `RandomEventId` 枚举值是 HUD 图标文件名的来源（`evt_<id>.png`），发布后冻结。
- 生成物命名前缀 `RndEvt_`。
- 血月**不使用** `TimeOfDayController` 的夜视静态因子——那些字段会被官方 URP Volume
  组件每帧回写，Mod 写进去会被覆盖。
- 强制天气不进存档（官方只存 seed），但 `WeatherManager.Instance` 可能为 null，
  因此设计成「遮罩必达、天气分支带守卫自适应」。
- 调度器在 Dormant/Armed 状态每帧只有几次 bool 读与一次 float 累加；
  血月补挂敌人增益按 2 秒节流且列表有界。

## 2026-08-31 限时商人库存与实机验收

随机事件系统现属恒开默认内容，频率旋钮仍可调。限时商店在 inactive 状态下先用已存在的
`Merchant_Normal` 引导 `StockShop.Awake`，激活后的同一帧、`Start` 之前切回稳定的
`BossRush_RandomEvent_Merchant`，再覆盖为事件专属条目；这样既不产生官方“未配置商人”错误，
后续保存又仍使用有界的稳定 Mod key。弹药/医疗库存 99、高品质彩头库存 1。

事件基类提供 Dev-only 实机完成状态。同步事件在核心副作用挂载后通过；异步事件分别记录请求、
成功和失败数。F3 逐项等待完成后才判 PASS，Boss 乱入还会在调用 SpawnCore 前幂等准备官方 preset
缓存，避免标准模式从未经过 Mode D/Zombie 初始化路径时出现“目录有 key、生成器找不到 preset”。

Boss 乱入的角色创建完成后还要经过共享的分帧 postprocess 队列。该队列必须独立于 Mode E/F
active 状态持续推进，因为标准 BossRush 的 WavesArena 更新会提前返回；若把 scheduler 放在该
early-return 之后，事件会一直保持 Pending。F3 的乱入用例以实际生成完成为准，并把后续清场中的
`RndEvt_` 自有角色纳入残留检测。
