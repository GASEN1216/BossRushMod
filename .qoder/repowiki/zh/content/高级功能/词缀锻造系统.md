## 简介

词缀锻造在现有重铸系统之上扩出一条新入口，给装备引入 12 条**行为型**词缀。
与重铸的属性 roll 不同，词缀改变的是行为——击杀爆炸、命中吸血、受击反弹、持续流失等。

它是对既有系统的深挖而非另起炉灶：交互点挂在既有的哥布林 NPC 上，UI 复用重铸的劫持骨架，
数据承载复用官方物品自定义变量。

## 玩家视角

- 在哥布林处选择「词缀锻造」，选中一件装备后消耗「词缀熔石」（TypeID 500060）与金钱随机附加词缀。
- 装备可容纳的词缀槽位数按稀有度递增（1 至 3 槽）。
- 可以锁定某个词缀槽再重随机，锁定消耗更多熔石，解锁免费。
- 词缀分三档：普通、稀有、诅咒。诅咒档强力但带明确代价。
- 词缀名会直接显示在装备详情页上（借官方的物品自定义变量展示位）。

熔石有三条获取渠道：哥布林商店（好感度解锁）、许愿池奖池、Boss 掉落。

## 数据承载

词缀只存在官方物品的自定义变量（`Item.Variables`）里，前缀 `AFX_`：
槽位内容、锁定标志、显示名键、schema 版本。

选这条路的关键收益有两个：官方序列化会把这些变量随物品一起存档，因此**跨存档零恢复代码**；
同时**没有任何 Mod 自定义类型进入存档**，避开了「类型改名即读不回」的老坑。

行为参数不进存档——存档里只有词缀身份，具体数值由代码表按 `(id, 档位)` 查出来。

## 运行时门控

词缀行为由一个集中式静态服务承载，只订阅三个官方静态事件（伤害、死亡、射击），
按「当前激活词缀上下文」分发。

这里放弃了两个看似更自然的方案：官方 Effect 挂件会把触发器注册到持有者身上，
**NPC 手持同样会触发**；官方的枪械扩展组件模式则只覆盖枪，近战与护甲没有对应事件。

上下文只由主角专属的手持变化、装备槽变化与关卡初始化事件重建，
**上下文全空时立即退订**。这保证了 NPC 身上、仓库里、背包里的闲置装备零订阅、零组件、零协程。
分发时再做一次归因校验作为双保险。

三处防事故设计值得单独记住：

- 殉爆带重入守卫，防止爆炸连锁递归；
- 荆棘与灌能的追加伤害带标记，分发端据此过滤，避免自触发循环；
- **死契的持续流失绝不调用官方的受伤接口**——致死路径上死亡事件先于受伤事件派发，
  走受伤接口会先触发一轮击杀词缀再把玩家打死。因此直接写当前生命值并 clamp 在 1 点血。

## 与重铸的关系

两者是同一 UI 家族、不同数据面。重铸改属性并记录差值；词缀锻造只动 `AFX_` 变量。

互斥由前缀黑名单双向保证：`AFX_` 已加入重铸的运行时跟踪变量判定（唯一咽喉点），
一处改动就同时把词缀挡在重铸 roll 池、属性锁定 UI 与差值同步之外；
反向上词缀锻造只识别 `AFX_`，重铸的数据天然不可见。

UI 上没有新建第二个劫持管理器——官方分解界面的劫持骨架必须单 owner，
两个静态管理器同时劫持会在事件订阅与清理上打架。因此走「单管理器 + 模式枚举」，
枚举声明在新的 partial 文件里，既有文件几乎不动。

## 契约与注意事项

- 物品变量前缀 `AFX_` 与各字段语义、12 条词缀 id 字符串，发布后冻结。
- TypeID 500060、本地化键前缀、词缀图标命名。
- 重铸判定里的 `AFX_` 分支删掉即数据损坏。
- 与变异词条、装备能力系统、套装 Bonus 均无耦合，可以叠加。
- 明确不做元素反应：灌能只用官方已有的元素系数伤害，不做顺序判定或状态联动。
