## 简介

遗种巢是 BossRushMod 的**基地侧养成与收集系统**，不是第九个游戏模式入口。
它把 Mod 存量最丰厚的内容——Boss 池本身——反转成收集与陪伴对象：

```
打 Boss → 掉「遗种蛋」/「遗魂」 → 巢中孵化幼体 → 单席随从进局 / 天灾远征 → 博物馆图鉴与纪念碑
```

设计动机：Mod 原有八个玩法入口全是"进局—打完—结算—散场"的一次性体验，
没有任何会跨局成长、会让玩家心疼的情感资产。

四条工程硬原则贯穿全案：**最小化修改 / 最大化复用 / 无性能问题 / 最佳设计模式**。
落到实处的三个硬指标：**零新增 Harmony 补丁**、**零新增 Unity 资源制品**、
**只占一个 TypeID**。

## 核心组件

模块的**唯一实例**由 `Common/Lifecycle/BossRushRuntimeModuleRegistration.cs` 持有并注册
（先存字段再注册同一引用），只读门面是 `ModBehaviour.PetNestRuntime`。
建筑、面板、掉落与场景回调一律走这个门面，禁止二次 `new`。

**dormant 契约**是整个系统的第一道闸：`petNestEnabled = false` 时不订阅存档、
不建血脉目录、不 tick 协调器、不产蛋、不生成任何角色。开关运行时可变，
`EnsureBootstrapped()` 幂等且能经 `ShutdownIfEnabledTurnedOff()` 退回 dormant。

## 架构总览

数据流是单向的：

```
官方事件/交互 → 运行时层 → 领域服务层 → 持久化层 → 落盘
                                  ↓
                            只读快照 → 呈现层
```

呈现层**只读已 commit 的结果**：孵化与远征都是 commit-before-reveal——
先落档，再交演出层回放。演出中断不影响已落档的结果。

## 关键机制

### 跟随驱动 = `AICharacterController.leader`

官方 `PetAI` **没有**跟随移动逻辑（只做速度同步 + >40m 传送）。真正的跟随来自
`AICharacterController.Update`：`leader != null && searchedEnemy == null` 时把
`patrolPosition` 同步成 leader 位置。因此随从组件只写 `leader`，索敌与作战完全
交还原生行为树（免费获得自动作战），**不写 `searchedEnemy`、不写 `leaderAI`**。

`patrol` 在有敌人时不跟随，崽会追着敌人跑远，所以自写一份 >40m 传送兜底。

### 中性化五件套

克隆 preset 上、**CreateCharacterAsync 之前**写：`hasSkill=false` / `exp=0` /
`hasSoul=false` / `team=Teams.player` / `dropBoxOnDead=false`。
必须在 await 之前——窗口期间波次统计、掉落、经验、成就只能看到 clone 身份。

激活时阵营取**主人的实际阵营**而不是硬编码 `Teams.player`（Mode E 会换玩家阵营），
并复用既有的 `SanitizeBossRushZombieSpawn` 去掉自爆技能与特殊挂件。

### 只缩 `modelRoot`

角色碰撞体只在 `SetCharacterModel` 内计算一次，缩角色根会让碰撞/寻路与视觉永久失配。
因此幼体只缩 `modelRoot`（public Transform），纯视觉缩小。
已知取舍：大体型幼体碰撞体不缩，可能挡路。

### 捡漏背包 = 借席不夺席

官方 `PetProxy.Update` 被 `LevelManager.PetCharacter` 门控，命中后把 PetProxy 贴到宠物
位置并每秒把容量同步成**玩家**的 `PetCapcity`。backing field 是私有无 setter，需反射写。

**实装期实测修正**：`petCharacter` 并非"无可见赋值点"——每张图的关卡初始化都会创建
官方宠物占席（`.codex_tmp/core_decomp/LevelManager.cs:402`）。若照"在场就让位"字面
执行，捡漏背包将永不激活。因此实现的是**借席不夺席**：只在非基地图借席、
借席前记录原占位者、离场必还、还席前核对席位仍是自己的随从、失败一律 fail-closed。

容量 Modifier 必须挂**玩家**的 `CharacterItem`（官方读的是玩家 stat），
且必须 `ModifierType.Add` 常量加（`PetCapcity` 是格子数）。stat key 官方拼写
就是 `PetCapcity`，少一个 a。

### 重伤不死

零新增补丁，两条既有链各加一个消费者：致死钳制链第四消费者钳 1 血 + 登记退场；
死亡抑制链第三 registry 作保险带。

**时序纪律**：钳制回调仍在 `Health.Hurt` 调用栈里，只做上短无敌与登记；
真正的退场、战痕落档与角色回收在下一个宿主 tick 执行。

战痕的凶手来自**只在随从在场期间**订阅的官方 `Health.OnHurt` 静态事件——
`CurrentHealth` setter 拿不到 `DamageInfo`，而给 `Health.Hurt` 的 Prefix 加参数会动到
既有 guard 断言的签名字面量。

### 远征：现实时间 + commit-before-reveal

计时用 `DateTime.UtcNow.Ticks` 而不是 `GameClock`（后者离线不推进）；
剩余时间一律 `max(0, Δ)` 回拨钳制。死亡率与成功率**随出发记录固化**——
明示给玩家的、结算用的、刻碑的是同一个数字。

结算 = roll → 结果与 `settled` 奖励债务先落档 → **发奖** → 翻牌只回放。
巢 / 远征 / 博物馆装进同一个 `BossRush_PetNest_Bundle_v2` 候选包提交，避免
"崽没了但碑没刻"。三个 v1 key 只在 v2 不存在时迁移读取，迁移成功后保留但不再写。

发奖**按条目记账**：现金走 `cashGranted`、战利品走 `grantedLootUnits` 件数游标，
正常补发只重做真正失败的那一格。
`EconomyManager.Add` 在 `Instance == null` 时返回 false 而不抛异常，因此必须接返回值，
丢弃它等于把"钱没发出去"当成发过了。奖励债务没有永久放弃上限：基地
`LevelManager`、经济与物品资源就绪后按固定退避继续；翻牌 UI 可以关闭，但欠账记录保留。
官方经济/背包 API 与 Mod 存档不能原子提交，因此采用至少一次语义——极端崩溃恰好发生在
外部送达后、游标落盘前时可能重复一格，但绝不静默少发。

**孤儿远征锁自愈**：v1 历史三键可能留下「崽 = OnExpedition 但没有远征记录」的旧半截状态。
迁入 Bundle_v2 后回基地由 `ReconcileOrphanedExpeditionLocks()` 扫一次，确认整包远征表确实没有
匹配记录才复位；Bundle 有写屏障或 `StoreFaulted` 时一步都不走，避免误解锁在途远征。

## 性能考量

- **零常驻**：局内至多一次 `CreateCharacterAsync`（出战席位非空才生成）；
  不带崽时 HUD 连 canvas 都不建。
- 随从维护与 HUD 都节流到 4Hz；HUD 模型是 **struct**，只有值变化才写 TMP text。
- 致死钳制、死亡抑制、清场豁免都先读静态 armed bool 早返，未带崽时零分配。
- 高频写（每次击杀记遗魂、统计计数）只入队不落盘，由官方采集与切图 flush 写下去。
- 面板与图鉴惰性构建，关闭即销毁；基地闲逛崽 ≤3 只且一只一帧分帧生成。
- 基地侧的 Boss 预设池预热被消费者门控（AGENTS.md 4.12）：图鉴或遗种巢至少一个启用、
  且池尚未填充时才做一次全量扫描；两个消费者都未启用时零成本，
  池填满后每次回基地也是零成本早返。

## 故障排查指南

| 现象 | 排查方向 |
| --- | --- |
| 打 Boss 不掉蛋也不涨遗魂 | 开关是否打开；是否在 Mode G / 丧尸模式里；该 Boss 的 `nameKey` 是否在血脉目录里（不在则 fail-closed）。**血脉目录会自动重建**：`InitializeEnemyPresets` 填充敌人预设表后、以及 Boss 池过滤状态变化时各触发一次 `NotifyEnemyPresetsRefreshed`；此外回基地时会先 `EnsureOfficialLineagesPrimed()` 主动预热一次预设池，因此目录里没有官方血脉不再是正常状态——若日志中看不到「血脉目录构建完成，条目数=<非 3>」，说明这三条链断了 |
| 竞技场中途关掉开关，Boss 死了还在记遗魂 | 已不应再发生：关闭路径经 `ShutdownIfEnabledTurnedOff()` 并联 `PetNestDropService.ClearAllTracking()`，handler 本体也会再查一次开关。若仍复现，看是不是新增了绕开 `ShutdownIfEnabledTurnedOff` 的关闭路径 |
| 换存档槽后新档出现旧档的崽 / 遗魂 | 已不应再发生：Bundle store 的缓存与 pending 都带槽位戳，命中缓存与落盘前各校验一次，不一致就自失效重载并丢弃跨档 pending |
| 某只崽卡在"远征中"永远回不来 | 回基地时 `ReconcileOrphanedExpeditionLocks()` 会自愈 v1 历史半截状态。若没自愈，多半是 Bundle 有写屏障 / `StoreFaulted`（那时自愈主动放弃，避免误解锁） |
| 蛋在背包里显示 `*BossRush_PetNest_RelicEgg*` | 本地化未注入，检查 `InjectLocalization_Extra_Integration()` 接线 |
| 蛋重启后变成占位物品 | 三处注册点漏了一处，跑 `PetNestEggItemRegistryGuard` |
| 孵化提示"血脉无法识别" | 官方 preset 改名导致老蛋漂移。这是 fail-closed 设计，蛋不会被消耗 |
| 带崽进局但没生成 | 看 `PetNestCompanionRuntime.LastBlockReasonId`：模式禁入 / 血脉 preset 不可用 / 席位为空 |
| 捡漏背包容量没变 | 容量 Modifier 是否挂在玩家而非宠物；stat key 是否写成了 `PetCapacity` |
| 远征倒计时不动 | 用的是现实时间，检查系统时钟；回拨会被钳制成 0 |
| 改动没保存 | 存档是否进入写屏障（版本不符 / payload 不可读）或 `StoreFaulted` |

诊断入口：F3 调试页「场景调试」里的三个遗种巢按钮（召唤 PoC 幼体 / 回收 / 输出探针报告）。

## 2026-09-04 遗种蛋在标准竞技场与无间炼狱曾 100% 作废

兼容分类：COMPAT（只补 defer 接线，不改掉落概率与 TypeID）。Finding CR-2026-09-04-001/002/003。

官方 `CharacterMainControl` 是先派发 `BeforeCharacterSpawnLootOnDead`、再
`if (dropBoxOnDead) CreateFromItem(characterItem)`。而 BossRush 的主掉落 handler 会把
`dropBoxOnDead` 置 false 并另建一个带**全新本地 Inventory** 的奖励箱，
全仓库没有任何代码把 `CharacterItem.Inventory` 转移进新箱子。
遗种蛋原本直接塞进 `boss.CharacterItem.Inventory`，且它的 handler 注册点与主 handler
在同一个函数体内（`RegisterBossRandomLootTracking`）必然配对生效——蛋必然被整只丢掉。
遗种蛋除天灾远征外没有第二个产出口，而远征需要先有崽，等于引导链彻底断开。

修复：接入仓库既有的 defer 协议（寒霜长矛/女巫镰刀在用的那套），四处接线——
判定 `ShouldDeferExtraBossDropToModPath`、pending 登记、
`AddBossSpecialLootToLootboxCoroutine` 里进箱消费、`FinalizeBossRushLootboxPathTracking` 撤销。
pending 用 `Dictionary<CharacterMainControl, string>` 而非 HashSet：血脉必须原样带到
consume 时才能 `TryStampLineage`，盖不上血脉的蛋孵化侧会 fail-closed。
无间炼狱那条分支连奖励箱都不建，改走该模式既有的世界掉落通道（`Item.Drop`）。
龙皇走手动注册路径、从没调用过 `MarkBossRushLootboxPathTracking`，也一并补上。

回归守卫：新增 `tests/ExtraBossDropDeferGuard.py`，锁住四个 integration × 四处接线、
判定必须显式并上 `infiniteHellMode`、世界掉落必须排在 Finalize 之前。经反向验证。

章节来源：`PetNest/PetNestDropService.cs`、`LootAndRewards/LootAndRewardsSpecialLoot.cs`、
`LootAndRewards/LootAndRewardsRandomBossLoot.cs`、`tests/ExtraBossDropDeferGuard.py`。
