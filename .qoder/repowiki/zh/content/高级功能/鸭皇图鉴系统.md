## 简介

鸭皇图鉴是一套贯穿全部玩法入口的收集型元系统。它不新开模式，而是让已有的 9 个入口
都能产出可积累的收集进度——每亲手击杀一个 Boss，图鉴里对应条目就点亮一格。

设计立项依据是仓库既有判断：模式赛道已经拥挤，「乘法型」的基地/元系统边际收益更高
（遗种巢与日报都是按这个逻辑立项的）。

## 玩家视角

- 在基地商店购买可用物品「鸭皇图鉴」（TypeID 500061），使用即打开面板，**不消耗物品**。
- 面板顶部是进度条（已解锁 X / 总数 Y，带里程碑刻度），下方是可滚动的卡片网格。
- 每张卡片显示立绘、Boss 名、累计击杀与最快击杀；初见日期和本地化的初见场景在详情中。
- 未解锁的条目显示同一张立绘压黑而成的剪影，Boss 名照常显示（Boss 筛选器本来就列出全部名字，
  隐藏名字并不构成信息保护），但统计数字隐藏。
- 点击卡片可放大立绘并查看详情。
- **入口只有物品这一个。** `CodexRuntimeModule.ToggleCodexPanel()` 全仓库唯一调用点是
  `Integration/Codex/CodexBookItem.cs` 的 `UsageBehavior`；Wiki 书（`WikiUIManager`）里
  没有任何图鉴按钮，也没有注册快捷键。曾有过「Wiki 书交叉入口」的描述，与代码不符，已更正。

## 数据流

图鉴的数据源是官方静态事件 `Health.OnDead` / `Health.OnHurt`，而不是任何模式的内部管线。
理由是所有入口的敌人死亡最终都走官方 `Health.Hurt()` 的死亡分支，与模式无关，这样一套订阅
就自然覆盖标准 BossRush、无间炼狱、Mode D/E/F/G、丧尸模式与原版 raid。

**Mode H 是唯一被排除的入口（owner 2026-09-03 定）**：它是观战模式，玩家本人不下场，
击杀由合同选手完成，本就不该进个人图鉴。真正需要显式排除的原因是 ERROR 完整互换——
互换期间玩家接管选手身体，官方会把伤害/击杀的 `fromCharacter` 改写成主角，
那一次击杀会伪装成「玩家亲手击杀」混进来。于是同一场比赛里 99% 的击杀不计、
ERROR 那次却计，口径自相矛盾，还让擂台 Boss 与「最快击杀」记录被污染。

订阅接线在全 Mod 的集中点 `Utilities/PlayerLifecycleRuntimeHooks.cs`，与日报采集器并列。

`CodexKillCollector` 的过滤序（顺序有意义）：

1. 开关门控早返
2. 排除 Mode H（必须早于「只记玩家亲手击杀」：ERROR 互换会把归属改写成主角）
3. 排除玩家自己的死亡
4. 只记玩家亲手击杀（环境伤害、随从击杀不算）
5. 排除友军（宠物 / 雇佣兵 / 临时同伴）
6. 排除基地场景
7. 排除遗种巢随从
8. 实例去重
9. 身份归属：主路查 preset nameKey；丧尸支路仅在丧尸模式激活时走组件查找

「最快击杀」记的是**首次玩家伤害到死亡**的区间，而不是「出场到死亡」。这样不必侵入 9 个模式的
生成路径，且全模式口径统一；代价是跨波躲藏会拉长表观时间，作为收集玩法的趣味数字可以接受。

## 存档设计

存档 key `BossRush_Codex_v1`，**跟随存档槽位**而非账号全局。三条理由：

1. 里程碑奖励落在当前槽位资产上，统计跟着槽位才不会出现「新槽位白拿、旧槽位拿不到」；
2. 账号级 `SaveGlobal` 每次调用立即整写并备份，高频击杀需要自建第二套节流，没有现成模板；
3. 遗种巢博物馆（同为图鉴语义）就是槽位级先例。

写盘纪律与日报一致：高频击杀只改内存 + 单一 pending，物理写盘只有三个出口——官方
`OnCollectSaveData` 顺带 merge、基地场景 Tick、宿主销毁兜底。schema 不符时写屏障只读不覆盖。

## 展示目录与立绘

展示目录取并集：当前 Boss 过滤池（含已注册的自定义 Boss，目录分类时先剔除再统一加入）∪ 官方 Boss 名单 ∪ 3 个自定义 Boss ∪ 5 个丧尸 Boss 合成条目 ∪
**存档中已有的历史条目**。最后一项解决的是「玩家在 Boss 筛选器里禁用了某 Boss 之后，
已收集的历史条目从图鉴里消失」。

立绘缓存刻意是 **fail-open**：Mode G/H 的展示 bundle 是入口门票、缺包必须挡住进入；
而图鉴面板展示的是玩家已解锁的内容，缺图不该让整个面板消失。因此缺图时走占位链：
bundle → 官方 Boss 图标 → 名字首字加圆底。

资产命名已冻结：`codex_portrait_<bossKey 全小写>`。

## 里程碑与成就

里程碑复用现有成就系统，不另建发奖管线。新增成就分类 `AchievementCategory.Codex`
（**追加在枚举末尾**，老档里已解锁成就的分类靠 int 值定位，插入中间会整体错位）。

5 条成就：解锁第 1 个条目、解锁 10 个、解锁 20 个、全收集、任意 Boss 十秒内速杀。

## 契约与注意事项

- 存档 key 与条目字段（`k` / `n` / `kills` / `first` / `fm` / `fast`）发布后只增不改。
- TypeID 500061 与本地化键 `BossRush_Codex_*`、`BossRush_CodexBook`。
- 立绘 bundle 名与 asset 命名规则。
- `Health` 两个静态事件的 handler 是全 Mod 最热路径之一：丧尸身份 key 直接返回常量、事件外壳零日志、开关早返；有效 Boss 死亡会创建候选并编码，
  由 `tests/CodexKillTrackingGuard.py` 守卫。
- 采集器内**严禁**任何物理落盘，`SaveFile` 只能出现在 `CodexSaveCoordinator`。

## 2026-09-06 历史条目即时入册与全录判定

`COMPAT`。首次击杀目录外 Boss（包括战役终章冠军之影）并被存档队列接受后，`CodexKillCollector` 在成就评估前调用 `CodexBossCatalog.SynchronizeHistoricalEntries`，增量并入历史 key。已有官方池无需每次击杀重建；目录版本变化也会使里程碑缓存重新评估。面板补判先同步历史条目，切槽仍使整个目录失效重建。

全录由 `IsFullyUnlocked` 逐一检查每个实际目录 key 的条目存在且 Kills > 0。额外历史条目或重复记录数量不能代替尚未击杀的 Boss；空目录绝不授予全录。保存 key、成就 ID、奖励数值与原击杀过滤不变。

回归：`tests/ContentThirdReviewFixesGuard.py` 与 `tests/fixtures/ContentThirdReviewFixes/run.py`，直接链接实际击杀采集器、目录与成就判定，覆盖冠军即时显示、补齐最后 key 才全录、相同数量但缺 key、重复击杀不重建、面板补判及切槽。Unity 面板和真实成就派奖仍需实机验证。

## 2026-09-11 长局最快击杀计时隔离（COMPAT）

`CodexKillCollector.OnGlobalHurt` 原先为所有受伤角色开计时，而杂兵在死亡采集的 Boss 判定处提前返回，
起点只进不出。长局累计到容量上限时会清空整表，仍在交战的 Boss 随之失去起点与十秒速杀判据。
现在计时只接受敌方、非基地、非遗种随从且 `ResolveBossKey` 可识别的 Boss，沿用丧尸 marker 分支。
玩家先造成伤害、最后由随从或环境补刀时仅清理起点，不计为个人图鉴击杀。

`tests/fixtures/ContentThirdReviewFixes/run.py` 直接执行生产采集器：先给 Boss 开表，再伤害/击杀
超过容量的杂兵，Boss 仍正确记录 9 秒并触发既有成就；致命 OnHurt 不重开计时，非玩家补刀清理起点。
原计时表上限、存档字段和未知时间 0 哨兵未变。一击致死未经过非致死 OnHurt 时仍没有有效计时，
需要后续明确兼容表达；本轮不把未测得的时间写成任意正数。未进行 Unity 实机验证。

## 2026-09-11 同帧速杀计时（COMPAT）

若玩家首击与致死在同一帧，计时表仍有真实起点但 `Time.time` 差值为零时，记录 `0.001` 秒的最小正单位，使有效速杀不会被存档的 `0` 未知哨兵吞掉。计时表未命中（例如容量清理、切图或未收到首击）继续保留 `0` 未知语义，不把缺失记录猜成一击。


## 2026-09-18 生产审核与收集体验（COMPAT）

- 收集目标仍是已有 Boss 的首杀与速杀，不新增模式、装备、掉落或第二套奖励系统。官方 Boss 跟随筛选器，三个自定义和五类丧尸依旧必收；历史已收集记录保留。自定义 Boss 已在公共池注册，目录先排除再按自定义分类，避免先占成“官方 Boss”。不把零击杀历史项加成无法完成的额外要求。公共池读取失败时降级显示，但不判全收集。
- `CodexData.Clone` 创建候选，`Store` 接受后才成为当前快照；拒绝不修改原条目的次数、用时或目录，不触发成就。读到写屏障/永久写故障后不再做候选编码。切槽同时复位里程碑缓存。面板补判已有有效速杀，复用成就幂等接口。
- Codec 不再把缺失/非数组 entries 当空档，不再跳过坏项、重复 key 或截断超限收藏。整个 payload 拒读后进入共享写屏障，原字节不动；v1 可选字段缺失仍读默认值。没有 schema/key 迁移。
- 计时表满时只拒绝新起点，已有战斗不清；任意归属的死亡先移除起点。丧尸 key 查询返回冻结常量，避免每次受伤的 Enum.ToString 与拼接。只观测到致命事件而没有起点时仍记未知，不推测一击用时。
- View 保留官方 ScrollRect、共享皮肤、TMP 和缓存；官方 NoteIndex 无法表达逐 Boss 次数/用时及待收集筛选，因此保留此自绘统计界面。单页最多 12 卡，翻页按需取立绘；只有语言/提交快照变化或用户操作才重建。先即时移除官方 prefab 的 VerticalLayoutGroup 再加 GridLayoutGroup，销毁路径归还输入。
- “只看待收集”只过滤显示，不能改变全收集分母。详情显示公共池/丧尸波/历史重访的真实来源，不承诺随机波下一只必出。不维护第二份刷怪表或 Boss 攻略数据库。长名字自适应，两种语言均能阅读；名称优先当前本地化，历史快照仅回落。有效极短用时显示 <0.1 秒，不显示 0.0 秒。
- 书基价 4000，官方 StockShop.DoRefreshStock 会按 MaxStock 补回一本，不是永久绝版。使用行为显式清零耐久消耗，不继承克隆源的消耗值。丢失书不影响收藏，可待补货重购。奖励不依赖买书。

验证入口：`python tools/run_runtime_regressions.py --filter ContentThirdReviewFixes`、`python tools/run_guards.py --filter Codex`。界面守卫只证明结构；正式编译、全量检查和操作级实机清单见本轮 `FIX_TRACKER.md` 与 `docs/代码审查/2026-09-18-鸭皇图鉴生产审核.md`。未采样游戏帧时间，不据此声称无性能问题。

  整个消失的闸：玩家在 Boss 筛选器里关掉了它，或者官方 preset 还没被
  `InitializeEnemyPresets` 扫到（没进过竞技场就是这个状态）。于是玩家看到的图鉴会缺格——
  既没有锁定卡，也没有统计入口和立绘，「还差哪几只没打」在册子里根本查不到。
- 新增第 1b 步 `CodexBossCatalog.AddOfficialRosterEntries()`：
  把 `CodexOfficialBossRegistry.OfficialBossKeys()`（40 条，来自
  `Assets/Data/CodexOfficialBosses.json`）里过滤池没给出的补成**未解锁的锁定卡**。
  显示名走官方本地化 key，立绘走同一条 `CodexPortraitCache` 通道（40 条在
  `tools/codex_official_presets.json` 里都有图），解析不出来就退回 key，不编造名字。
  名单读不出来时该步等于不存在（fail-open），目录退回旧口径，面板照开。
- 名单是**有序**消费的：`_bossOrder` 与 `_bosses` 同时登记，
  HashSet 的枚举顺序不稳定会让卡片位置无故变动。
- 连带影响：「全收集」的分母从「当前筛选池」变成「官方全部 Boss + 3 自定义 + 5 丧尸」。
  这是有意的——收藏册的完成度不该靠在筛选器里关掉几只来凑。已获得的成就不会回收。
