站点以 VitePress（`docs/.vitepress/config.mts`）为构建核心。`scripts/sync-content.mjs` 读取仓库根目录 `WikiContent/catalog.tsv` 与 `WikiContent/{zh,en}/` 正文，生成 `docs/` 与 `docs/en/`，英文首页和 `hubs/` 总览也经此链路生成。导航结构来自 `docs/.vitepress/data/structure.mts`，中英文 sidebar、nav、首页与主题组件共用；更新日志按 catalog 自动补入。

`useWiki().href` 先用 `localizePath` 添加语言前缀，再保留开头 `/` 交给 VitePress `withBase`。不得先剥离 `/`：VitePress 会原样保留相对地址，从深层页面点击时重复拼接目录。base 由 `DEPLOY_TARGET=cloudflare` 切换为 `/`，默认 `/BossRushMod/`；同一规范路径不应随来源页深度变化。

验证入口：`npm --prefix wiki-site run test:navigation` 执行真实 useWiki 与当前安装的 VitePress withBase，覆盖两种 base、中英文与深层来源页；构建后运行 `python tools/check_wiki_links.py` 检查 HTML 中链接和资源的实际 URL 落点，根部署时追加 `--base /`。单纯构建成功不能代替导航验证。

部署仍由根目录 `.github/workflows/deploy.yml` 驱动，产物为 `docs/.vitepress/dist`；本轮修复不改变发布目标或执行部署。
