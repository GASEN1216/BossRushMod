- 每个 public/private 方法都包裹 try-catch 并以 `DevLog("[ModeD] [ERROR] ...")` 记录异常，保证单点故障不中断整局。
- 物品池采用「扁平 List<int> + Dictionary<int, List<int>> 按品质分桶」的双层结构，通过 `CreateModeDQualityBuckets` / `RebuildModeDQualityBuckets` / `ClearModeDQualityBuckets` 三件套统一维护。
- 高频分配对象使用 static readonly 复用缓存（如 `presetFilterCache`、`presetFilterCache2`、`reusableVector3List`、`reusableSpawnQueue`），避免每波/每次筛选产生 GC。
- 敌人/物品随机选择优先从品质分桶中抽取，再回退到全池随机，并在失败时提供硬编码兜底 ID（如医疗品 fallback）。
- 通过 `partial class ModBehaviour` 将不同职责拆分到多个文件，但所有状态、配置、工具方法集中在同一宿主类上，跨文件协作仅通过该类的字段与方法。
- 波次推进使用「预期数 vs 结案数」双计数器（`modeDExpectedEnemiesInCurrentWave` / `modeDSpawnResolvedInCurrentWave`）配合 `waveToken` 守卫，确保异步生成回调不会误计入其他波次。
