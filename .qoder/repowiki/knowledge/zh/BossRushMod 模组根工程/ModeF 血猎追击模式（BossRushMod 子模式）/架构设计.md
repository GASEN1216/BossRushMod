模块以 `BossRush.ModBehaviour` 的 partial class 形式按职责拆分到多个文件，所有逻辑挂载在同一个 ModBehaviour 实例上，通过 `ModeFRuntimeModule`（继承 `BossRustRuntimeModuleBase`）作为运行时生命周期钩子注册。
- 入口与启动：`ModeFEntry.cs` 负责入场校验（裸装 + 船票/预付费 + 血猎收发器 + 无营旗）、道具原子性消耗与回退、调用 `StartModeF()` 完成状态重置、物品池预热、刷怪点分配、玩家传送、初始装备发放、变异词条抽取、Boss/Merchant/Courier 生成，并启动状态机。
- 核心状态机：`ModeFPhases.cs` 定义 `ModeFPhase`（Preparation → Bounty → HuntStorm → Extraction）及每阶段时长、掉血率、Boss 压力策略；`TickModeF` 每帧驱动阶段计时、持续掉血、命火过载计时、Boss 目标刷新、UI 更新与阶段切换。玩家击杀回血改按入场最大生命结算（普通 30%，悬赏 45%～60%）；局内最大生命成长封顶 +50%，溢出值按同一成长容量归一化为 0～100 命火。满命火进入 15 秒过载，通过三个 `PercentageAdd` Modifier 提供枪械/近战 +40% 与移速 +15%，同时施加官方 `GameplayDataSettings.Buffs.Burn` 并使 Mode F 失血 ×2；悬赏击杀续时 3 秒、剩余时间封顶 24 秒，正常结束回到 25 命火。
- 生命周期清理：`ExitModeF` 集中清理 Modifier、Boss、工事、商人、Courier、龙息 Buff 处理器等全部运行时资源。`EndModeFBloodfireOverload(false)` 撤销三个过载 Modifier 并清空命火状态；`CleanupModeFPlayerMaxHealthGrowth()` 随后从原始 Stat 目标撤销本局最大生命成长，再把玩家当前生命限制到恢复后的真实上限，禁止临时强化或超额生命泄漏到模式外。
- 数据模型：`ModeFModels.cs` 提供 `ModeFState`（会话 Token、阶段、活跃 Boss 列表、工事字典、撤离区域、命火充能、过载状态与剩余时间等）与 `ModeFFortificationMarker`、`ModeFBossDisplayNameMarker` 等 MonoBehaviour 标记。
- 子系统拆分：`ModeFBounty.cs` 管理悬赏印记、Boss 间击杀印记继承与成长；`ModeFBounty_EquipmentAndLoot.cs` 处理击杀掉落与高价值 loot 追踪；`ModeFExtraction.cs` 管理撤离点生成与倒计时；`ModeFFortifications*` 系列文件封装工事放置、修复奖励、运行时放置与清理；`ModeFMerchant.cs` 复用 Mode E 商人逻辑；`ModeFRespawn.cs` 处理 Boss 复活队列，死亡处理和每秒完整性检查都在成功移除活跃引用后立即建立补位债务，并由 `finally` 保证后续奖励、日志、掉落或清理异常也只能且必须入队一次；四阶段均立即调度，同时以单个 in-flight 生成限制并发；`ModeFItemUsageAndTriggers.cs` 拦截玩家物品使用触发 ModeF 专属行为；`ModeFRuntimeHooks.cs` 注入游戏事件钩子。
- UI 层：`ModeFUI.cs` 维护健康条名称覆盖、悬赏雷达 Canvas、玩家名缓存、阶段广播与玩家头顶奖励气泡；命火增长、悬赏续时和过载开始复用同一气泡路径，过载开始提示延长到 4 秒并明确火力、移速、失血和烧伤效果。`ModeFUI_BountyRadarAndHealthBars.cs`、`ModeFUI_BountyRadarAssets.cs`、`ModeFUIStaticCacheReset.cs` 分别负责奖励文本/雷达渲染、静态资源加载与缓存复位。
- 依赖方向：UI/子系统均单向依赖 `ModeFState` 与 `ModBehaviour` 提供的公共方法；Boss/AI 修改通过 Stat Modifier、AICharacterController 字段反射或公开 API 施加，避免直接耦合具体 Boss 类型。
