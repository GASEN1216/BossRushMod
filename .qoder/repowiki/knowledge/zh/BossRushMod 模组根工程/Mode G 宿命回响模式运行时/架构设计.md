模块以 `ModeGRuntimeModule` 为运行时入口，由 `ModeGEntry`（挂载在 `ModBehaviour` 上）负责启动/关闭、可用性门控与 HUD 生命周期；核心状态集中在不可变计划与可变状态的分离设计：`ModeGWavePlan` 在 Starting 阶段基于 `runSeed` 通过 `ModeGDeterministicRandom` 确定性生成 9 个 `WaveSlot`（含 primary key、逐槽 reserve key、bossCount 与 PlanVariant），Active 阶段只读。官方 key 来自可循环的确定性 draw bag，6 个及以上时同波 primary/reserve 严格互斥；只有 1-5 个时才从已有 key 按同一 runSeed 确定性复制到槽位，不创建新的 `EnemyPresetInfo`，因此最低合格官方池是 1 个。`ModeGRunState` 集中所有可变字段并通过 `TryAdvanceLifecycle` / `TryLockBattleResult` 的 CAS 守卫保证生命周期单向推进（None→Starting→Active→Rewarding→Exiting→None）与 battleResult 单次锁定；preview 是入口侧不可变值对象，不占生命周期相位。

跨模块门控集中在 `ModeGRuntimeGates`（定义于 `ModeGStateModel.cs`）：对外只暴露只读查询（`IsModeGRunInProgress`、`IsModeGEntryBlocked`、`IsModeGGlobalQuarantineActive`、`IsModeGOnDeadSuppressionActive`、`IsModeGAchievementDamageWindowActive`、`IsModeGStagingHealthBlocked`、`IsDaXingXingOwnedByModeG`、`GetTrackedBosses` 等），被 WavesArena、ZombieMode、Interactables、Patches、Utilities、Achievement 等模块消费，实现 Mode G 运行时与其余系统的最小耦合面。

署名 Boss 托管边界：三个托管 adapter（`Integration/DragonDescendant/DragonDescendantBoss_ModeGAdapter.cs`、`Integration/DragonKing/DragonKingBoss_ModeGAdapter.cs`、`Integration/PhantomWitch/PhantomWitchBoss_ModeGAdapter.cs`）+ `Utilities/ManagedBossSpawnContracts.cs` 构成 Mode G 专属 Boss 的生成契约层，由 `ModeGSpawnTransaction` 以事务性 lease 驱动；lease 失效后全部 fail-closed。单个署名 adapter 或资源不可用时，只以普通官方 Boss 替换对应私有署名槽。2026-08-17 owner 批准现有 `GetFilteredEnemyPresets()` 过滤池作为普通官方 Boss 资格来源；run-scoped 快照仍排除托管 Boss、拒绝空 stable key 与同 key 多 preset 引用，并要求至少 1 个唯一官方 key。旧逐 key 审计 DTO 保留供未来收紧策略使用，不再作为当前生产入口的硬编码 allowlist。

各职责按文件拆分：`ModeGRuntimeModule` 保留九波状态机与结算主流程，`ModeGRuntimeModule_PublicApiAndShutdown` 原样承接只读公共 API、胜利保护、场景守卫和统一终止/退款路径，使状态机主文件保持在源文件预算内；`ModeGRuntimeLifecycle` 承担玩家死亡订阅和 Boss 销毁边界，`ModeGRuntimeBridge` 承担 `ModBehaviour` 上的 Boss 池快照、managed 生成、落点、竞技场准备与横幅桥接；`ModeGDeathRouting` 处理死亡/胜利路由与成就 token 生成；`ModeGCombatTelemetry` 记录伤害/开火采样用于推断下一波反制；`ModeGSpawnTransaction` / `ModeGRewardTransaction` 分别管理 Boss 生成槽位与奖励发放的事务性提交；`ModeGNemesisPersistence`、`ModeGProfilePersistence`、`ModeGPresentationAssetCache` 提供宿敌持久化、个人成绩存档与展示资源缓存；`ModeGInteractable`、`ModeGMapSupportRegistry`、`ModeGFateContract`、`ModeGEncounterVariation`、`ModeGAvailability`、`ModeGHUD`、`ModeGCleanupController`、`ModeGAdaptiveCombat`、`ModeGRecapPanel` 等文件分别对接交互、地图支持、契约选择、遭遇变体、可用性开关、HUD 显示、统一清理、适应能力战斗与终局结算呈现（recap 面板/宿敌预告/图鉴与印章 near-miss）。地图支持直接复用地图选择 UI 的 `GetAllMapConfigs()`：非空 sceneName、sceneID 和 spawnPoints 形成 Verified 快照，preview 按当前 active scene 冻结玩家实际选择的 exact pair；无效配置、重复 pair 和 UI 外场景继续拒绝。首次有效地图读取后缓存快照，`IsInteractable` 热路径不再分配；`OnDestroy_Integration()` 同时清理地图快照与 `ModeGEncounterVariation` eligibility 字典。本地化 key（`BossRush_ModeG_*`）统一由 `Localization/LocalizationInjector.cs` 的 `InjectModeGLocalization()` 注入。依赖方向自顶向下：Entry → RuntimeModule → State/WavePlan/Telemetry/Transaction → 辅助子系统，无反向引用。

奖励交付先返还胜利必达信物，再逐帧物化普通奖励。背包 `AddAndMerge` 或仓库 `SendToPlayerStorage` 即使在事件回调中抛异常，也会根据实例已归属、已消费或 Incoming buffer 增量核对实际提交结果；只有背包、仓库和地面 agent 三路均未提交时才销毁实例并判失败。Rewarding 中死亡、切图或宿主销毁会先失效 attempt nonce，再取消 materializer，避免非胜利终局继续发奖。

Mode G 自动入口是明确的两阶段事务：地图选择 UI 已预扣的船票在确认页取消、打开失败或启动前预检失败时立即退回；Mode G 入场意图在切场景前冻结到 `BossRushMapSelectionHelper` 事务状态，不在加载帧重新读取可能尚未初始化的玩家背包。通用 `OnSceneLoaded` 过图路径会依该冻结意图同时延后 `bossRushArenaActive`、刷怪器禁用和清场，避免确认页等待期让 NPC/商店等系统误判竞技场已正式运行。只有玩家选定契约、全部预检通过、入场支付所有权转移且 runtime 成功推进到 Active 后，才在首波生成前提交竞技场所有权。
