- 持久状态只由 `ModeHStateMachine.TryTransition` 单点推进；`ModeHMatchPhase` 只从 `ModeHLifecycle` 派生，禁止另建第二个权威状态或跳转表。
- runtime owner token 只在 `ModeHRunState` 内存里，**绝不**写进任何持久 DTO；所有延迟回调都先过 `IsCallbackValid(token, runId, sceneGeneration)`。
- 所有写入 payload 的枚举显式赋整数且 `Unknown = 0`，只能在末尾追加新值。
- 确定性数据（五席、分流、敌军计划、侦察、战痕、奖励候选、双 nonce）一律经 `ModeHSeedStream` 的 domain/sequence 派生，禁用全局随机；概率先量化到百万分之一整数再判定。
- 口令、伤病与战痕共用 `ModeHCommandAdapter` 的同一套重申/还原设施，**禁止另建第二条字段修改路径**；控制点严格限于设计提案 §17.6.2 白名单。
- 玩家真实资产只有三条白名单路径：`ModeHEntry.TryRefundPrepaidTicket()`、`ModeHLoadoutKitApplicator`（只访问 owner 标记且 inactive 的临时实例）、`ModeHWarehouseStakeJournal`（唯一仓库写入者）。其余 Mode H 文件不得出现 `Inventory`/`PlayerStorage`/玩家 `ItemTreeData` 任一符号。
- 官方 static 事件只在唯一 owner 上以**命名 handler** 订阅一次并对称退订；禁止匿名委托、禁止按每个角色重复订阅；死亡帧上目标已 inactive，不得依赖 `activeInHierarchy`。
- fail-closed 贯穿全部关键路径：内容签名不符、认证未通过、快照六类条件、押品证据不一致，一律拒绝或回落到“技术中止 + 同场重开”，**绝不判负、绝不猜测、绝不静默删除 journal**。
- Harmony 新增严格限于 `CA_ControlOtherCharacter.CanMove/CanRun` 两个 postfix，no-throw 且 fail-closed 到原版 `false`；不得扩大到 `CanUseHand`/`CanControlAim` 或全局 team/输入/索敌/死亡逻辑。
- UI 全部运行时创建，`sortingOrder` 只引用 `BossRushUILayers` 常量；HUD 与诊断层不 `ClaimModalInput`、不暂停时间，六个非战斗模态页共用唯一一个 `ModalInputLease`。
- 日志统一 `ModBehaviour.DevLog("[ModeH] ...")`；需要在发布构建可见的告警走 `CriticalLog` 并限频。
- 每个 `catch` 都必须有解释性注释说明为什么吞掉异常（`EmptyCatchGuard` 预算约束）；单文件不超过 1200 行（`LargeFileBudgetGuard`）。
