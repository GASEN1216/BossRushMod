## 2026-08-29 编排层接线（此前整个模式不可达）

**事故本身值得记一笔**：交付时 55 个源文件、29 条 guard 全绿、编译通过、契约文档写着「已一次性完整实现」，但模式在游戏里根本进不去——约 25/55 文件是不可达代码。三处独立缺件各自都足以致命：入口 `ModeHInteractable.TryOpenEntry` 零调用方且没有任何地方 AddComponent；`ModeHRuntimeModule` 的四个 `partial void` 只有声明没有实现体（C# 会把无实现的 partial 方法连同**全部调用点**静默删除，编译与 guard 都不报错，运行时什么都不发生）；九张地图 JSON 都没有 `modeH*` 五点位，`SupportedMapCount` 恒为 0。根因之上还有一层：29 条 guard 全部只断言构件内部形状，没有一条断言构件有人调用。

**入口**：基地船坞的交互组注入一个 `ModeHInteractable`（`UIAndSigns.TryInjectModeHEntryOption`），形态与 PetNest / 日报的建筑交互一致——动态 AddComponent，零新增 prefab 与美术资源。注入门是「开关开启或存在待恢复记录」，避免出现点了必被拒的死选项；恢复入口复用同一选项。不走竞技场路牌：路牌只在 Legacy 竞技场开战后存在，而 Mode H 必须在**切图之前**冻结入场意图。

**编排层拆四个 partial**（拆分只为 `LargeFileBudgetGuard` 的 1200 行上限，语义上就是 `ModeHRuntimeModule` 本身）：`_SceneFlow` 是运行时字段的唯一声明处，承载 `OnSceneLoadedInternal`（意图匹配 → 按 §19.2 顺序取 arena 与 spectator 双租约 → 认证协程 → 用固定 runSeed 原子创建 lifecycle=Drafting 的首份 Season 并读回）与 `ShutdownRuntimeInternal`（§18.3 十步顺序，释放严格与取得相反）；`_UiFlow` 承载 `OnTransitionApplied` 与恢复壳；`_MatchFlow` 承载 `OnUpdateInternal` 与选秀到锁盘的命令；`_SeasonFlow` 承载幕间路由、转会与赛季终局，其中 `OpenNextMatchBrief` 是 matchIndex 的唯一推进点。

**落盘策略裁决**：`OnTransitionApplied` 只做三件事——把 runState 投影进 Season、路由页面、标脏，**绝不自己落盘**。一局里状态转换有几十次，逐次写盘既违反 §20.3「每批至多一次 SaveFile」也违反 §17.8「MatchSettling 是唯一原子全量写入点」。真正落盘只发生在少数显式点（Drafting 创建、RosterLocked、MatchBrief、MatchSettling、Intermission、TransferWindow、HallOfFame、SeasonEnded、Suspended）。中间态不写盘不丢任何契约保障：§20.3 的恢复规则规定战前无事实 token 时一律回落同一场 MatchBrief。

**失败出口**：开局链任何一步失败都走统一的 `AbortSetup`——退款、逆序释放租约、回到无 run 状态。arena 租约一旦清过原生敌人就**强制离场**，绝不原地回落 Legacy BossRush（§19.2）。
