模块按职责划分为 Achievement 与 Audio 两个子目录；Achievement 的业务由已注册运行模块执行，Audio 的下蛋与自定义音效由独立服务执行，宿主保留兼容入口：
- Achievement/AchievementRuntimeModule.cs 继承 `BossRushRuntimeModuleBase`，在 `OnUpdate` 直接执行快捷键 Tick，并持有成就与勋章事件委托。初始化和实际清理仍由原宿主槽位驱动，模块销毁提供幂等兜底。
- Achievement/BossRushAchievementManager.cs 是静态单例式管理器，集中注册所有成就（`RegisterAllAchiements`），维护已解锁/已领取集合并通过 `SavesSystem` 持久化；对外暴露 `TryUnlock`、`ClaimReward`、事件 `OnAchievementUnlocked`/`OnRewardClaimed`。
- Achievement/AchievementTriggers.cs 是 `AchievementRuntimeModule` 的 partial，持有成就会话初始化、通关/无间炼狱/Mode D/Boss 击杀判定、Mode G 会话与去重，订阅 `InteractablePickup.OnPickupSuccess`、`Health.OnHealthChange` 等游戏事件；模式与配置通过注册阶段绑定的窄查询读取。
- Achievement/AchievementTracker.cs 是纯静态状态机，区分“本局状态”（进入竞技场重置）与“累计统计”（跨局持久化），通过 `AUTO_SAVE_INTERVAL` 节流写入存档。
- Achievement 下的 UI 文件（AchievementView、AchievementEntryUI、AchievementIconLoader、SteamAchievementPopup）负责展示与资源加载，依赖 Manager/Tracker 提供的数据。AchievementMedalConfig 定义物品，AchievementMedalItem 的商店注入和库存保存归运行模块，原静态缓存与存档键保持。
- Audio/BossRushAudioManager.cs 实现单例 MonoBehaviour，通过 `Assets/Sounds/<NPC>/<file>` 路径查找并调用 `ModBehaviour.PlaySoundEffect` 播放；使用字典 + Action 将 NPC ID 映射到交互音效处理器。
- Audio/BossRushAudioRuntimeService.cs 持有下蛋、文件存在缓存与官方音效反射调用，缓存保持静态；玩家 fallback 与 Mod 路径通过窄查询在原消费位置读取。Audio/BossRushAudioHooks.cs 只保留原入口的单语句转发。
依赖方向：Triggers → Manager/Tracker → SavesSystem/Economy；UI → Manager；Audio Hooks → AudioRuntimeService → 官方音频接口；RandomEvents 与 Arena 的旧桥访问同一份下蛋静态缓存。

## 成就触发与勋章运行归属（2026-09-25，COMPAT）

`AchievementTriggers.cs` 与 `AchievementMedalItem.cs` 的业务 partial 已归同一个 `AchievementRuntimeModule`。模块持有初始化标记、Boss 引用去重、Mode G 三元组去重与会话门、玩家 Health 引用和血量基准、事件订阅状态；勋章的条目引用与库存仍保持原静态生命周期。宿主 `AchievementRuntimeHooks.cs` 保留旧成就与商店入口的单语句转发。

模块在原注册槽位绑定模式状态、难度、热键配置和商店判据的窄查询；查询在原消费位置执行，不缓存模式状态。原 Awake 槽位才初始化，原两次 Popup 实例请求及事件订阅顺序不变。销毁时仍先实际退订成就追踪，再执行 Manager/Icon 缓存重置；后续模块销毁幂等返回。勋章保存 / 读档事件仍在 Integration 原位置订阅和退订，保存键 `BossRush_MedalStock`、TypeID `500018`、默认库存、单位价格、保存失败与读档清缓存流程不变。

`AchievementRuntime` 执行回归直接编译完整生产触发、生命周期、勋章及宿主桥，并抽取根绑定与原清理槽位。覆盖 Legacy 引用去重、Mode G 会话隔离、玩家事件门、Health 重绑与销毁、热键与官方界面门、勋章重复注入 / 保存 / 切槽失败路径。Manager/Tracker 的存储内部、Unity 场景、真实商店及弹窗为宿主边界，结论限于 L2；真实成就解锁与跨模式 / 跨场景表现仍需 L3。

## 下蛋与音效服务归属（2026-09-25，COMPAT）

宿主在注册模块前为唯一 `BossRushAudioRuntimeService` 绑定玩家与 `info.path` 查询，绑定不读取值、不扫描 Resources、不创建音频管理器。已有 `BossRushAudioManager` 仍按需创建。服务承接原 `BossRushAudioHooks` 全部实际方法体，`TrySpawnEggForPlayer`、`PlaySoundEffect` 等旧入口与原静态清缓存入口保留。

下蛋仍先尝试 ngm，再获取主玩家 / fallback，缺缓存才扫描 `SpawnEgg`；取第一个结果、记录角色预设、Instantiate、忽略与玩家碰撞、调用 `Egg.Init` 的顺序和参数不变。ngm 每次实时检查 `Assets/ngm.mp3` 再检查根目录 `ngm.mp3`；普通音效的文件存在与缺失结果仍以不区分大小写的键缓存。官方 `PostCustomSFX` 返回 `EventInstance?`，原 void 委托创建失败时继续走反射 Invoke；归位保留这条 fallback 及全部异常边界。

`cachedSpawnEggBehavior`、`eggSpawnPreset`、文件存在字典、音频委托和解析标志仍为 static。RandomEvents 的读写和 Arena 的清怪豁免查询都转到服务属性，没有副本。卸载继续从 AlwaysOn 的原槽位调用清缓存，位于 MagicBlend 之后、NPC UI / Dialogue 之前，不提前搬到另一个模块销毁时点。

`AudioRuntime` 回归直接编译完整服务、旧桥与当前根装配 / 清理语句；在独立进程覆盖官方非 void 返回、兼容 void 委托和缺 AudioManager 三种形态。文件检查使用临时真实文件；Unity、资源扫描、实例化、碰撞及 FMOD 为记录替身，结论限于 L2。实机需从已有下蛋入口触发，观察玩家脚下的蛋、孵化延时和音效，过图后重试；无蛋、重复播放、目标错误或巡游鸭被清怪误删均为不合格。
