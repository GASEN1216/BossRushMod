模块按职责划分为 Achievement 与 Audio 两个子目录，均通过扩展 `ModBehaviour`（partial class）的方式与游戏主循环集成：
- Achievement/AchievementRuntimeModule.cs 继承 `BossRushRuntimeModuleBase`，在 `OnUpdate` 中委托给 `ModBehaviour.TickAchievementRuntime`，作为 Unity 生命周期入口。
- Achievement/BossRushAchievementManager.cs 是静态单例式管理器，集中注册所有成就（`RegisterAllAchiements`），维护已解锁/已领取集合并通过 `SavesSystem` 持久化；对外暴露 `TryUnlock`、`ClaimReward`、事件 `OnAchievementUnlocked`/`OnRewardClaimed`。
- Achievement/AchievementTriggers.cs 以 `partial class ModBehaviour` 形式注入成就会话初始化、通关/无间炼狱/Mode D/Boss 击杀等场景的判定逻辑，并订阅 `InteractablePickup.OnPickupSuccess`、`Health.OnHealthChange` 等游戏事件。
- Achievement/AchievementTracker.cs 是纯静态状态机，区分“本局状态”（进入竞技场重置）与“累计统计”（跨局持久化），通过 `AUTO_SAVE_INTERVAL` 节流写入存档。
- Achievement 下的 UI 文件（AchievementView、AchievementEntryUI、AchievementIconLoader、SteamAchievementPopup、AchievementMedalConfig/Item、BossRushAchievementDef）负责展示与资源加载，依赖 Manager/Tracker 提供的数据。
- Audio/BossRushAudioManager.cs 实现单例 MonoBehaviour，通过 `Assets/Sounds/<NPC>/<file>` 路径查找并调用 `ModBehaviour.PlaySoundEffect` 播放；使用字典 + Action 将 NPC ID 映射到交互音效处理器。
- Audio/BossRushAudioHooks.cs 同样以 partial class 扩展 `ModBehaviour`，用反射延迟解析 `Duckov.AudioManager.PostCustomSFX` 并缓存委托，实现无侵入的自定义音频播放。
依赖方向：Triggers → Manager/Tracker → SavesSystem/Economy；UI → Manager；Audio Hooks → ModBehaviour 反射层，彼此之间无直接耦合。
