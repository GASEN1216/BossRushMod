2026-09-25 核对：`ModeERuntimeModule` 是 Mode E 状态与算法的唯一实例 owner，以 partial 分布在本目录。宿主在 `ModBehaviourRuntimeModules.cs` 创建并注册同一实例，`ModeEHostBridge.cs` 保留旧入口转发；完整性计时、活敌索引、阵营缩放、恢复锚点、死亡与掉落订阅、会话和商人代次、贝壳账本及异步句柄均归模块。`OnDestroy` 先销毁贝壳运行时，再重置商人静态缓存，最后释放宿主引用。
- 启动流程：`ModeEStartup.cs` 提供分帧预热协程 `PrepareModeEStartupCoroutine`，依次预加载物品池、敌人池、阵营预设、地图刷怪点、商人缓存和烟雾特效；`TryStartModeE` 负责营旗检测、裸装校验、物资快照与位置捕获，失败时通过 `HandleModeEStartupFailureRecovery` 回滚玩家位置、销毁新增物品并返还营旗。
- 战斗与缩放：`ModeEBattle.cs` 与 `ModeEBattle_ScalingAndRuntime.cs` 管理存活敌人列表、按阵营维护独立敌人集合 `modeEFactionAliveMap`、计算各阵营死亡计数驱动个人层数缩放（每层生命/伤害 +5%）。
- 刷怪与雇佣：`ModeELotteryAndHiring.cs` 处理随机阵营抽取与雇佣逻辑；`ModeESpawnAllocation.cs` 转发给 `Utilities/ModeEFSpawnPreparation.cs`，由共享服务扫描地图刷怪点并平均分配给参战阵营；`ModeERespawnItems.cs` 配合 `RespawnItemConfig.cs` / `RespawnItemUsage.cs` 实现挑衅烟雾弹、混沌引爆器等消耗品重新生成 Boss。
- 商人经济：`ModeEMerchant.cs` 负责商人生成与分类物品池；`ModeEMerchantSupportClasses.cs` 保留反射契约和价格缓存，`ModeEShellSession.cs` 持有会话与余额操作，`ModeEShellTransactions.cs` 承接购买、出售与交付。`ModeEHarmonyPatch.cs` 的官方目标和调用顺序保持原样；事务门、扣款、提交、回滚和观察者次序没有调整。
- 商人支撑类型：交互入口在 `ModeEShopInteractable.cs`，宠物生成在 `ModeEPetSpawner.cs`。`ModeEMerchantSellAllUI` 仍是同一静态 owner，主体、分帧商店初始化和布局分别位于同名文件、`_ShopViewSetup.cs` 与 `_Layout.cs`，缓存与事件订阅只有一份。
- UI 与名称：`ModeEUiAndHealthBars.cs` 通过反射绑定游戏内 HealthBar 显示阵营名与友方绿色血条；`ModeELifecycle.cs` 负责阵营气泡、模式结束时的敌人清理与阵营恢复。
- 预设所有权：Mode E/F 克隆的 `CharacterRandomPreset` 由角色对象上的 `ModeECharacterPresetLease` 持有，角色销毁完成后再释放；结束模式按禁掉落、注销运行时、停用、销毁角色的顺序清理，不用 Hurt 触发奖励/死亡副作用。
- 动态商店：分类 `StockShop` 在 inactive 对象上创建，以官方 `Merchant_Normal` 引导 Awake，同帧 Start 前恢复稳定 `ModeE_*` ID 并覆盖库存；反射回读失败时整座商人 fail-closed。
- 配置常量：`FactionFlagConfig.cs` 集中定义 7 种营旗 TypeID、本地化键与商店注入；`RespawnItemConfig.cs` 定义 4 种刷怪消耗品 TypeID、品质、价值与 UsageBehavior 装配。
- 共享依赖：D/E/F 配装查询通过已绑定的 `ModeDItemPool`；Arena 目录通过 `WavesArenaRuntimeModule`；生成阶段计时器位于 `Utilities/ModeEFSpawnProfiler.cs`。`ModeEFSpawnPreparation` 由宿主创建单一实例并绑定 E/F，持有扫描、分配和扁平化缓存，玩家阵营在取用时查询；安全传送、后备点请求和两种条件清理的顺序保持。Mode F 与丧尸商人仍使用部分 Mode E 分类池与生成接口，E/F 共享生成、商人和后处理的最终服务归位仍在迁移计划簇 4 中，当前不能视为解耦终态。
