Unity + C#，基于 Duckov 官方 Mod 框架 (`Duckov.Modding.ModBehaviour`)，使用 Cysharp `UniTask` 进行异步生成与场景加载，通过反射访问 `CharacterSpawnerRoot.created` 字段禁用原生刷怪器，借助 `ObjectCache`、`BossRushMapConfig`、`BossRushMapSelectionHelper` 等共享缓存与配置组件。

## 入场兼容（2026-09-26，COMPAT / WIRE+）

[地图选择](file://MapSelection/BossRushMapSelectionHelper.cs) 在官方 `MapSelectionView.NotifyEntryClicked`
前观察自有条目并记录索引，不替换官方确认/扣票。DEMO 接管必须匹配选中的目标，不能抢先消费另一张图的入场标记。

[宿主场景回调](file://ModBehaviour.cs) 在任何 runtime 清理前调用 `ShouldIgnoreAuxiliarySceneLoad`：
只在 BossRush 待入场/竞技场状态，过滤非活动、非内置、非登记、非目标且不含 LevelManager/MultiSceneCore
的附加资源场景。真正关卡、基地、菜单仍分发；登记表不可读时保留既有行为，不凭 Mod 名称或背包物品拦截。

[自定义落点](file://Integration/BossRushIntegration_TravelAndSetup.cs) 等 SceneLoader 与 MultiSceneCore
结束加载后才开始等待角色就绪，避免出场过程覆盖竞技场落点。生产回归见 `EntryAndReforgeCompatibility`
与 `ModeHSceneEntry`。这证明通用缺陷已被隔离复现并修复；秘法纪元等具体组合尚无 L3 证据。

## 首次出生直接到目标（2026-09-26）

[初始出生](file://MapSelection/BossRushInitialSpawn.cs) 等官方 `WaitForConfirm` 返回成功，
再用切图前的统一模式判据冻结入场资格。`GetPlayerStartLocation` 后置替换本次关卡的出生位置，
按 `SubSceneEntry.Info.SceneReference.Name` 精确找到地下/冷库等目标子场景，并返回实际 sceneID。
官方首次创建使用目标坐标；配套 `LoadAndTeleport(MultiSceneLocation)` 前缀只认当前 core 的
一次性专属 path，转交官方世界坐标重载，官方初始化末尾的 startPos 也因此保持一致。
先核验配套路由已安装，缺失则不返回虚构 path。旧传送只在初始到达未成功时负责定位；NPC/玩法初始化照常。

Mode E/H 不启用；DEMO 的 F/G 保留原出场，带 customSpawnPos 的 F/G 沿用原来的目标规则。
取消/关闭选图、普通地图点击、新入口及消费都会失效旧资格；组件随 MultiSceneCore 销毁，无每帧任务。
直接传送回退入口、第三方改走 useLocation 或完全替换官方初始化时保留加载后传送，不能承诺任意出场 Mod 都命中。
