# 天空岛剧情 owner

2026-09-08，`COMPAT / SCHEMA+`。天空岛已从纯探索会话扩展独立槽位剧情；源码保留在 `DebugAndTools/SkyIsland/`，由正式地图会话拥有，新增状态不放入 `ModBehaviour` partial。

`SkyIslandStoryRules` 冻结剧情动作前置和互斥结果，`SkyIslandStoryCodec` 复用共享 JSON token / writer，`SkyIslandStoryService` 持有共享槽位存档与保存协调引擎。新增 key `BossRush_SkyIsland_Story_v1`；两航标、四支线、三捷径、折翎、钟守、结局及区域探索各自为持久事实。换槽与删档使会话失效，坏 schema 只读保护。

`SkyIslandStorySaveRecovery` 是离岛保存失败时的短期 owner。成功保存后退订并销毁自身；原地图可卸载，候选状态仍由 recovery 持有。入口必须拒绝同槽 recovery 尚未结束时创建第二份故事 store。独立出击地图允许非基地保存，每次调用 `Tick` 都要传实际战斗安全状态；被推迟的物理写通过同样的安全门重试。

`SkyIslandContent` 经唯一 IO 入口 `JsonDataRegistry` 消费正式 `Assets/Data/SkyIsland/World.json` 的 15 遭遇与 5 进度门，严格校验稳定 ID / marker / 手动挑战类型、完整集合与门条件；错误整表 fallback 并正式日志告警。

遭遇死亡记录是普通 `SkyIslandEnemyRecord`，官方销毁角色不能抹掉清场事实；清场回调直到存档接受才停止，丢失活体仅补未死槽。D/G 航标分别需要主组与 `_02`。正式掉落/经验/魂沿用官方死亡路径，角色创建期间的 preset 留在 async 局部 owner，生成后交给角色组件，角色销毁后延迟释放。天空岛退出不能销毁仍在 CreateCharacterAsync 使用的 preset。

详细规则见 `zh/content/游戏模式系统/天空岛剧情与持久化.md`。生产剧情回归 `SkyIslandStory` 96 条断言、完整遭遇 owner 回归 `SkyIslandEncounters` 28 条断言已通过，均登记于 `tools/run_runtime_regressions.py`；真实 Unity 敌人、交互、门和存盘仍由地图总体 smoke 验证。

## 2026-09-09 内容扩充：物资、敌人档次、噬风与居民服务

分类 `COMPAT / SCHEMA+`。交付文档此前把「独有任务物品、商店售价、可重复领取的经济奖励」明确留作后续定稿，

**搜刮点 owner**：`SkyIslandScavenging` 由 Session 持有。39 个锚点写在纯逻辑的 `SkyIslandLootTables`
（marker + 极坐标偏移 + 档次 + 区域），进图装配时一次性解析成落点：地面射线、墙体胶囊、
与已有玩法标记 4.5 m 净距、与其它已落位点 3 m 净距，四项任一不过就跳过该点（fail-open）。
按 4.12 门控，玩家进入 72 m 才建箱，**一次 Tick 最多建一个**。三个档次
（生活物资 1–3 / 航务补给 2–5 / 星工遗存 4–7）只决定品质带与件数。

**箱子唯一建造点是 `SkyIslandRewardCrate`**（搜刮点 / Boss 战利品 / 委托谢礼共用），三条约束收在一处：
① 先在**未激活**的暂存父节点下实例化再摘掉官方 `LootBoxLoader`——它的 `Awake` 会按位置哈希随机
`SetActive` 并写 `MultiSceneCore.inLevelData`；② 必须 `EnsureLocalInventory`，官方按位置哈希共享库存，
靠得近的两个箱子会串味；③ `InstantiateSync` 缺资源时返回同 TypeID 的**空壳 FallbackItem**，
既不为 null 也不抛，必须回读 `TypeID` 才能确认。

**物品池唯一查询点是 `SkyIslandLootPools`**，用 `GetAllTypeIds` 而**不是** `Search`——官方 `Search`
在结果为空时会自行降级 quality 反复重搜，会把「星工遗存」悄悄降成杂物。自定义内容靠
`LootBlacklistRegistry` 挡住，`Special` tag 不是可靠护栏。结果必须 `Sort()`：`GetAllTypeIds`
经过 HashSet，顺序不稳定，不排序则同一 seed 在不同机器上抽到不同物品。

## 可玩性复审修复（2026-09-09，COMPAT）

**遭遇按出击刷新**是本轮最重要的一条。原先 13 组自动遭遇全部靠 `clearedEncounters` **永久**
抑制生成，而 39 个搜刮点每趟重刷 —— 第二次进岛起零敌人、约百件产出无限重复。
`Tick` 的短路条件收窄成 `!encounter.Started && encounter.Manual && completed(id)`：
自动组每趟重刷，具名剧情对手（折翎 / 钟守 / 噬风）仍一次性。
**存档 schema 不动**：`clearedEncounters` 对自动组降级为「剧情装置的前置证据」
（D+D_02 修风标、G+G_02 修星灯、S4 校准观星镜），一次达成永久有效。
`RemainingClearable` 必须同步去掉 `!completed(id)`，否则委托侧仍然是死的。

**剧情面板必须有战斗门**。面板走共享模态租约压 `Time.timeScale = 0`，而这个暂停**是可靠的**
（`ModBehaviour.LateUpdate` 排在官方 `TimeScaleManager.Update()` 之后，Unity 保证 Update 全部先于
LateUpdate）—— 没有门它就是战斗中的免费暂停键，且面板里挂着苔药与整备，可以定格战斗再回满血。
`CanOpenStoryPanel` + `HasLivingEnemiesWithin(point, 35f)` 挡打开时机，`WorldStory.Tick` 自动收起。
**按半径不按全图**：`HasLivingEnemies` 是全图口径，把敌人丢在岛的另一头会让全岛剧情交互死锁。

其余：档次倍率改成严格递增（Champion 2.2 → 4.5，原先弱于 Elite 2.6）；噬风 ×18 两相位 →
×13 四相位、预警 9 m/1 s → 7 m/1.4 s（官方爆炸**无距离衰减**，能否逃脱只由半径÷预警决定）；
件数 1–2 / 2–3 / 2–4（原先 Voyage 比 Starworks 还多）；苔药改按缺失血量比例计价 + 300 s 冷却；
谢礼箱按轮次 120° 错开落点（原先三轮全压在苇白/留言板身上）；折翎战败后隐藏并留旧腰牌纪念物；
区域到访半径 120 → 60 m（四条支路桥头到对岸地标只有 73–117 m，原值站桥头就点亮）；
撤离读条在官方界面打开时**冻结**而非清零；`Scav` 不再改 `nameKey`（保住官方击杀计数）；
`ZhelingPass` 门牌改为如实写「近路」（`A→B→C→D→E→G` 全程无门，折翎可跳过）。

**守卫盲区教训**：上述问题**全部落在守卫没钉住的位置**（三张倍率表、件数、120 m 半径、
折翎可见性、苔药价格与冷却），改了不会红。本轮逐个补断言并新增 `check_encounter_refresh`。

## 2026-09-09 可玩性复审第二轮：交互可达性与官方语义

四条「编译与结构守卫都查不出」的缺陷，详见 `zh/content/游戏模式系统/天空岛剧情与持久化.md` 同名小节。

- **交互体不得与已有玩法标记同点**：官方 `CA_Interact` 按距离**严格小于**取唯一目标，
  同点时距离相等、结果由物理返回顺序决定，且滚轮只在同组内切换。完成纪念物曾建在装置
  自身位置上（盖住 K1 / K2 / K3 与敲钟），航路图曾以 `localPosition = Vector3.zero` 叠在见闻点上。
  两处统一退开 `SkyIslandRewardCrate.InteractableSeparation = 3.2f`，落点复用经几何回归的
  `TryFindCratePosition`，方位角取标记名稳定散列。
- **官方爆炸遮挡在抬高地形上恒失效**：`ExplosionManager.CheckObsticle` 硬编码射线 y = 0.5，
  天空岛岛面在 0–62 m，遮挡恒为「无」，叠加官方爆炸无距离衰减 ⇒ 全岛爆炸穿墙。
  `SkyIslandExplosionObstaclePatch` 压到 `min(startY, endY) + 0.3`（y=0 平地上正好还原官方 0.5），
  由 `SkyIslandRaidLease` 按 raid 场景 `Arm` / `Disarm`，未武装时交还原方法，官方地图零变化。
- **相位提速不得自乘**：`EnterPhase` 的 `/= 1.25f` 在四档下复利到 2.44，叠档次后 1/4.15。
  改为按 `Bind` 记下的基线算绝对值，`MaxPhaseSpeedup = 1.6` 封顶。
- **遭遇 preset 必须按身份取**：`sources[i % sources.Count]` 让全岛带队者永远同一个；
  改走 `StableHash(id + "#" + index)`（不能用 `string.GetHashCode`，跨运行时口径不同）。

另修：存档落盘门由全图 `HasLivingEnemies` 改为 `HasLivingEnemiesWithin(玩家, 45)`
（自动组按出击刷新后全图口径等于永久关门）；剧情面板增加 `reopen` / `Refreshed()`，
选项随状态刷新。

## 2026-09-10 剧情面板版式重做（COMPAT）

旧版 `SkyIslandStoryPresentation` 把每个元素钉在写死的 `anchoredPosition` 上（标题 y=275、
正文 y=139、第 i 个选项 y=5-i*52、「继续」y=-282），字号写死、`overflowMode` 取 TMP 默认的
Overflow —— 超框既不裁剪也不省略，**直接画到面板外**。离线量过一遍真实文案：标题框 750×55 /
字号 30，三条英文 `PointName` 实际要 810~975 px，折两行需 72 px；第 6 个选项会和固定在
y=-282 的「继续旅程」叠住（今天最多 5 个选项撞不上，但那是数出来的巧合，不是结构保证）。
**选项按钮与正文实测不超框**（50 条选项、352 条正文各 0 超框），别顺手改它们的字号。

现在改成「先量后排、容不下按优先级挤」：高度全部走共享的 `BossRushUI.MeasureTextHeight` 实测，
面板高度被 `ZombieModeUIHelper.GetReferenceViewportSize()` 夹住，容不下时按固定优先级收缩 ——
**页脚 > 选项 > 标题 > 正文 > 插图**；正文压到下限还放不下就套 `ConfigureScrollRect`，
滚动而不是溢出。标题开自动缩放并以 `Ellipsis` 兜底。选项按钮补上了此前完全没有的
悬停/按下态（`GetHoverColor` / `GetPressedColor` / `GetButtonTextColor`）。

`SetBodyText` 换正文时**必须重新量高**：选项回执可能比原正文长得多，旧版直接赋值就会把新文本
画到面板外。

插图由 `SkyIslandUiArt` 提供，形态照 `CampaignAssetCache`：bundle 优先 → 开发期 raw PNG → 无，
**fail-open**。装置面板上挂着 K1/K2/K3 与敲响归航钟，绝不能因为一张图没出来就打不开。
两类图对应面板的两种形态：`skyisland_portrait_<npcId>` 是居民面板的头像位（512×512 抠图立绘），
`skyisland_scene_<region>` 是装置/见闻面板顶部的区域横幅（1024×288，比例必须配 828×232 的槽位，
出 8:3 再拉伸会把云海竖向压掉 34%）。`RegionOf` 只认 `A`–`H` 与 `S1`–`S4`，解析不出来就不配图，
**不猜** —— 猜错会给玩家配一张别的岛的图。素材由 `tools/gen_sky_island_ui_art.py` 生成，
画风锚定 `ArtSource/SkyIsland/VANILLA_GRADE.md` 实测的 H18–40 暖琥珀色带。

常驻内存：全部读满约 20 MB（12 横幅 + 6 立绘），按需加载、由
`SkyIslandRuntimeModule.OnDestroy` 统一释放（沿用设计复审 D-4 的「静态缓存归模块 owner」口径）。

离线证明是 `tests/SkyIslandStoryPanelLayoutPropertyTest.py`：从生产源码读常量、用真实文案重放
整套布局算术，对 15 种组合断言面板不超屏、选项不压页脚、元素不掉出面板；6 条人为破坏 5 条转红
（第 6 条改的是**可收缩**的正文下限，被收缩算法按设计吸收，不是判据漏）。
版式可以离线预览：`python tools/preview_sky_island_panel.py` 按生产常量与真实素材重画一张
示意图 —— **那不是截图**，字体度量与 TMP 不同、圆角是近似，最终观感仍须实机确认。

## 2026-09-10 局内 HUD 重做（COMPAT）

owner 反馈「不要在屏幕中上方写字，太像网游」。旧版复用试验场的 `ArenaPrototypeControls.CreateHud`：
屏幕正中偏上 920×90 的裸文字、常驻四行长句，实测中文要 4 行 100 px、英文 6 行 150 px，框装不下。

新增 `SkyIslandHud`，照主流游戏分三层：

1. **常驻只留右侧一张小卡**：与 `CampaignHud` 同一视觉语言（深色面板 + 3 px 青色竖线），
   只放区域 / 目标 / 物资与委托小标，高度实测、无内容整卡收掉。左上角留给随机事件徽章与波次提示；
   契约追踪条也在右上角，本卡按 `CampaignObjectiveTracker.IsArmed` 动态下移一档避让。
2. **区域名是进出时的一次性大标题**：淡入 0.35 s / 停留 2.1 s / 淡出 0.9 s，放在**中线偏下**
   （`AreaTitleY` 为负），背后垫二维柔边压暗（横向两侧 smoothstep × 竖向余弦钟形）。
   只做竖向渐变的话左右两侧是硬边；不垫压暗的话浅色字压在高亮云海上读不出来。
3. **其余按需出现**：撤离读秒只在环里，公告 4.5 s 后淡掉，存档状态**正常时不显示**（只在 `!story.CanWrite` 时提示）。

同轮审核自己上一版 UI 找出并修掉：`ArenaPrototypeControls.Label()` 的 `LayoutElement.preferredHeight` 压住了
`ContentSizeFitter`（优先级高于 TMP），导致 HUD 溢出修复实际无效；量高探针用延迟 `Destroy` 会在开面板那帧
闪出重叠文字（改 `DestroyImmediate`）；横幅「渐隐」其实是纯色横条（改真渐变）；插图保留 CPU 像素拷贝
（`LoadImage(..., markNonReadable: true)`，常驻约 20 MB → 10 MB）。

`tests/SkyIslandHudGuard.py` 钉住六条纪律。反向验证第一轮 7 条里 6 条转红：拿掉存档提示门控那条没转红，
因为 `!story.CanWrite` 在 `BeginStoryChallenge` 里也有，整文件子串判断被骗过；已改为逐个调用点检查同一语句内的门控。

版式示意图：`python tools/preview_sky_island_panel.py` 输出 `output/sky_island_hud_preview.png`（按生产常量重画，
铺真实岛景当底，**不是截图**）。观感仍须实机确认，见 `docs/天空岛_待人工验证清单.md` 第 2.6 步。
