`SkyIslandSceneReferenceBridge` 为正式 `Assets/SkyIsland/SkyIslandRaid.unity` / `BossRush_SkyIsland` 提供官方场景引用与 metadata。真实 DLL 核对显示，`SceneLoader.LoadScene(SceneReference, …)` 按 `Name` 调用 `SceneManager.LoadSceneAsync(string, …)`，无需修改官方加载状态机。Eflatun 的 `LoadedScene` 原生按完整 Path 查询；bridge 只注册独占 GUID ↔ Path 项并对自身引用的 `UnsafeReason` 做兼容。

Unity 返回的 `BuildIndex = -1` 保持原样。不往 `SceneInfoCollection.Entries` 塞 -1 条目，不改变全局 `GetSceneID(int)` / `GetSceneInfo(int)`；精确 sceneID/reference 查询提供天空岛 metadata，MultiSceneCore 的名字、主场景/活动子场景身份根据真实 core Scene 路径提供。其它路径的同名 Scene 和其它 -1 场景不共享天空岛身份。

单个 Raid Scene 同时拥有官方 MultiSceneCore 与可玩世界。其 `SubScenes` 含自身 sceneID，并由真实 `SceneLocationsProvider` 提供 `StartPoints/PlayerSpawn`。官方 `LoadAndTeleport` 保留，private `LoadSubScene` 仅在自身 core + 自身 reference 命中时使用已经加载的 Scene，设置官方 activeSubScene/cachedSubsceneEntry、执行 LocalOnSubSceneLoaded，下一帧解除 loading 后触发实际 OnSubSceneLoaded 委托。官方墓碑服务因此沿既有订阅恢复；场景切换取消会回滚尚未广播的激活状态。`GetSetActiveWithSceneParent(-1)` 只有在 core 的 path/handle 与当前 active Scene 一致时返回活跃的天空岛父容器，避免墓碑隐藏，又不把其它 -1 归入本图。

路径映射和 14 处窄范围 Harmony 前缀由独立 Harmony owner 安装，模块销毁请求清理后，等待官方加载结束且目标 Scene 卸载，再撤销自己的补丁及自己新增且未被改写的映射，避免官方 async 后续读取 Name 时引用失效；安装失败立即回滚。所有反射目标必须存在才发布注册完成；失败回滚并报错。实际游戏 DLL 的 C# 7.3 编译探针通过；`tests/fixtures/SkyIslandSceneReferenceBridge` 使用生产桥接代码与真实安装的 Harmony 执行，Unity 和官方类是隔离替身，37 条断言覆盖身份隔离、实际路径位置服务、墓碑父容器、事件顺序、取消恢复、官方加载期间延迟清理及清理重入。它不代替 Duckov 的真实加载、角色/相机初始化或死亡复进实机验收。

## 2026-09-09 天空岛原创生活模型与独立美术验收（COMPAT / OPERATIONAL / SCHEMA+）

本轮生活布景在 12 座岛上放置 14 类原创模型、28 个实例，每类均有整图摆放记录。模型定义属于 `tools/sky_island_life_models.py`；`build_model`、`model_geometry`、`stamp` 复用整图基础造型与共享色板，分别负责单体构建、按材质提取几何和变换合入岛区。码头补给、村落售卖与炊饮、农田种植、工坊维修各自形成道具组合；主路、桥口、玩法标记与中央活动空间由规划保留净空。完整模型清单、分布和三篇已核实的美术参考见 [SETTLEMENT.md](../../../../../../ArtSource/SkyIsland/SETTLEMENT.md)。

## 2026-09-10 天空岛岛内验收套件（COMPAT）

独立出击关卡不能用主验收套件：`RunSuite` 从基地出发、切竞技场、收尾 `RunFinalChecks` 又切回基地，而天空岛一切图，会话、租约、bundle 与这趟出击的全部内容就都没了。因此 `CheckStartGate` 一直显式拒绝它，代价是 `M_SKY_ISLAND_01..09` 长期零自动覆盖。本轮的做法是另开一条入口而不是放宽主门：`F3GameplayValidationSkyIsland.TryStartSkyIsland` 反过来要求人已经在岛上且会话已就绪、活动场景是 raid 场景、当前槽是专用测试档；`RunSession` 两个阶段按 `_skyIslandMode` 分流，`RunSkyIslandFinalChecks` **不切图**，跑完把玩家留在岛上。用例本体在 `F3GameplayValidationSkyIslandCases.cs`，共 26 条自动 ID 登记进 `GameplayCoverage.json` 的 `SKY_ISLAND.automatic`。

三条纪律由 `tests/SkyIslandValidationSuiteGuard.py` 钉住，10 条人为破坏逐条转红。第一，**全程只读**：套件跑在玩家真实的一趟出击上，写剧情、搬玩家、刷怪、开箱都会污染他正在做的事，且这种污染在报告里看不出来；守卫的禁用清单特别区分 `TryApply` 的两个同名入口——静态 `SkyIslandStoryRules.TryApply` 是纯函数（允许），实例 `SkyIslandStoryService.TryApply` 会 `store.Store()`（禁止）。第二，**判据不成立时记 SKIP 不记 PASS**：英文完整性用例在中文语境下扫不出中文残留是恒真，为此加了 `SkyIslandSkipCase` 与 `RunSyncCase` 的 SKIP 通道，不改共享 `SyncValidation` 委托签名。第三，**CJK 码位区间写整数常量**，不写字面汉字也不写 `\u` 转义——两者都会在文件被按非 UTF-8 读写或经过折反斜杠的工具时静默变形，而断言完全靠区间成立，变形后会安静地永远为真。

会话侧新增的是只读观测面：`SkyIslandSession.ValidationSnapshot()` 返回纯数据快照（往返两次做差即 `M_SKY_ISLAND_01` 要的「无残留」基线），`ValidationIsInsideExtractionAt()` 与真实撤离判定共用同一个半径常量但不读玩家、不改状态；`SkyIslandExplosionObstaclePatch.IsArmedFor(scene)` 让人在岛内第一次能确认爆炸遮挡补丁真的挂上了。

配套的离线证明是 `tests/SkyIslandInteractionCompetitionPropertyTest.py`：`SkyIslandRewardCrate.TryFindCratePosition` 只做地面射线与墙体胶囊两项裁决，**不查「与其它交互体净空」**，三个调用方各自只躲开自己那一个锚点，跨系统组合从无人复算。该测试用真实作者几何算出 77 个静态交互体坐标两两比较，2926 对零重叠、最紧余量 0.60 m，并直接 import 落点复算器复用同一份实现。它不证明官方 `InteractableLootbox` 预制体的真实 collider 尺寸（离线拿不到，由岛内 `SKY_INTERACTION_SEPARATION` 按 `Collider.bounds` 实测），也不证明居民漫游后的站位。

本轮**没有开游戏**，套件与全部断言均为「代码就绪、未实机」；逐条人工步骤见 `docs/制作教程/天空岛/天空岛_待人工验证清单.md`。注意 `GameplayCoverage.json` 的 `automatic` 是全局口径，登记之后从基地跑的主套件不会再报 `PASS`，只会报 `INCOMPLETE`。
