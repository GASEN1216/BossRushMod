本模块由三部分组成：
- `Common/`：运行时基础设施。`Lifecycle/` 定义 `IBossRushRuntimeModule` 抽象接口与 `BossRushRuntimeModuleBase` 默认实现，并由 `BossRushRuntimeModuleHost` 集中管理模块的 OnAwake/OnStart/OnSceneLoaded/OnUpdate/OnLateUpdate/OnDestroy 生命周期分发，所有回调均被 try/catch 包裹并通过 `ModBehaviour.DevLog` 输出警告；`Infrastructure/` 提供 `IHarmonyPatchGroup` + `HarmonyPatchGroupRegistrar` 静态注册表，用于按功能分组登记并去重 Harmony Patch 组；`Equipment/` 通过泛型基类 `EquipmentAbilityManager<TConfig,TAction>` 统一处理输入拦截（反射缓存 `CharacterInputControl.inputActions`）、动作生命周期与角色绑定；`Lifecycle/` 自 2026-09-06 起还承载两份内容子系统共用的存档实现：`BossRushSaveCoordinatorEngine`（`IBossRushSaveBatchSource` 数据源 + 落盘协调状态机：pending 合并、IsSaving / 基地闸 / 每帧闸推迟、600 帧重试预算、「欠一次 SaveFile」独立记账；征程 / 图鉴 / 日报 / 遗种巢各持一个实例，是它们唯一的 `SavesSystem.SaveFile` 调用点）与 `BossRushSlotJsonStore<T>`（槽位级单 key JSON 整存：幂等订阅、槽位烙印、写屏障、回读核对、`Store()` 只入队；征程 / 图鉴 / 日报共用）；其他子目录（`Data/JsonDataRegistry` 与全 Mod 共享的节点 JSON 解析器 / 写出器 `Data/BossRushJsonValue`（原 `ModeH/ModeHJsonValue`，并入了遗种巢的 `PetNestJson`）、`Effects/`、`Events/BossRushEventBus`、`MapConfig/`、`Stats/RuntimeStatModifierTracker`、`Utils/`）提供数据、特效、事件总线、地图出生点、统计修正等横切能力。顶层 `Interactables/BossRushBuildingInteractableBase` 是「靠近建筑 → 交互完成 → 打开面板」交互体的共享骨架（报箱 / 公告板 / 展示柜 / 许愿台 / 终章召唤石）。
- `Injection/`：当前为占位文件，仅保留 `partial class ModBehaviour` 以维持目录结构，实际注入逻辑已迁移至主 Mod 入口。
- `Patches/`：按游戏子系统划分（BaseHub、Combat、Death、Economy、ItemStatsSystem、UI），每个子目录包含若干 `[HarmonyPatch]` 方法与对应的 `*PatchGroup.cs` 空分组声明，由 `HarmonyPatchGroupRegistrar.Register` 登记；补丁契约与稳定性规则在 `AGENTS.md` 中约定，要求显式指定重载方法签名、避免脆弱时机假设、更新后核对目标签名。
依赖方向单向：`Patches/` → `Common/Infrastructure`（注册分组）→ `Common/Lifecycle`（可选）；`Common/Equipment` 通过反射访问游戏类型，不反向依赖 Patches。

## 2026-09-05：启动自检按实际补丁方法验证

`COMPAT`，CR-2026-09-05-020。`HarmonyBindingSelfCheck` 按类统计时，逐个检查该类以约定方法名或 Harmony 属性声明的 Prefix/Postfix/Transpiler/Finalizer。对应 PatchInfo 集合必须同时匹配 owner 和 MethodInfo；同目标另一类的成功补丁不能替缺失类背书。空补丁类不视为通过，动态 TargetMethod(s) 仍明确跳过，启动一次及清理后复位保持不变。自检只读，不补装或替换补丁策略。

`tests/fixtures/HarmonyBindingSecondReview/run.py` 在独立 Windows .NET Framework 进程用实际安装的 Harmony 验证部分挂载、异 owner、属性命名、四种补丁和动态跳过；它不向游戏进程注入补丁。结构约束由 `HarmonyBindingMethodIdentityGuard.py` 固定。
