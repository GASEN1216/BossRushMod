# 遗种巢 PetNest 养崽系统 · 架构设计

> 状态：实装中。本页随实施步骤逐步补全，当前覆盖到**步骤 0（PoC 技术验证闸门）**。
> 设计来源：`docs/设计提案/2026-08-28_养崽系统创意脑暴.md`。

## 1. 系统定位

遗种巢是**基地侧的养成 / 收集系统**，不是第九个游戏模式入口。它把 mod 存量最丰厚的
内容（Boss 池）反转成收集与陪伴对象：

```
打 Boss → 掉「遗种蛋」/「遗魂」 → 巢中孵化幼体 → 单席随从进局 / 天灾远征 → 博物馆图鉴与纪念碑
```

四条工程硬原则贯穿全案：**最小化修改 / 最大化复用 / 无性能问题 / 最佳设计模式**。
全案 **零新增 Harmony 补丁**——两处需求都走既有补丁加消费者。

## 4. 关键机制

### 4.1 跟随驱动 = `AICharacterController.leader`

官方 `PetAI` **没有**跟随移动逻辑（只做速度同步 + >40m 传送）。真正的跟随来自
`AICharacterController.Update`：

```
if (leader != null && searchedEnemy == null) patrolPosition = leader.transform.position;
```

因此随从组件只写 `leader`，索敌与作战完全交还原生行为树（免费获得自动作战）。
**不写 `searchedEnemy`、不写 `leaderAI`**——后者会在 leader 与成员之间双向同步目标。

`patrol` 分支在 `searchedEnemy != null` 时不跟随，崽会追着敌人跑远，所以自写一份
>40m 传送兜底（阈值与落点公式沿用官方 `PetAI.Update`）。

### 4.2 中性化五件套

克隆 preset 上、**CreateCharacterAsync 调用之前**写：

| 字段 | 值 | 理由 |
| --- | --- | --- |
| `hasSkill` | `false` | 技能白名单化之前，幼体不带 Boss 技能（自爆 / 召唤 / 范围） |
| `exp` | `0` | 随从不是可击杀目标，不给经验 |
| `hasSoul` | `false` | 不掉灵魂方块，避免 `SoulCollector` 把随从死亡当战利品来源 |
| `team` | `Teams.player` | 随从进局的根基，也是清场豁免判据之一 |
| `dropBoxOnDead` | `false` | 随从倒下是重伤退场，不是战利品事件 |

必须在 await 窗口之前写：窗口期间波次统计、掉落、经验、成就只能看到 clone 身份。

### 4.3 只缩 `modelRoot`

`CharacterMainControl.modelRoot` 是 public Transform；角色碰撞体只在
`SetCharacterModel` 内计算一次（混用世界坐标差值与未缩放常量），缩角色根会让
碰撞 / 寻路与视觉永久失配。因此幼体只缩 `modelRoot`（基准 0.4x），**纯视觉缩小**。
已知取舍：大体型幼体碰撞体不缩，可能挡路——首版接受，P2 再议。

### 4.4 捡漏背包 = 借用官方 PetProxy 席位

官方 `PetProxy.Update` 被 `LevelManager.PetCharacter` 门控，命中后：把 PetProxy 自身
transform 贴到宠物位置、每秒把 Inventory 容量同步成**玩家**的 `PetCapcity` stat。
backing field 是 `private CharacterMainControl petCharacter`，无 setter，因此需要反射写。

**实装期实测修正（与实施计划原文不同）**：`petCharacter` 并非“无可见赋值点”，
关卡初始化会执行

```
petCharacter = await petPreset.CreateCharacterAsync(mainCharacter.position + Vector3.one * 99f, ...)
```

即**每张图都有官方宠物占席**，席位永不为空。若照“在场就让位”字面执行，捡漏背包
将永不激活。因此实现的是**借席不夺席**：

- 只在非基地图借席（基地由官方 `PetHouse` 驱动宠物驻留位）；
- 借席前记录原占位者，离场 / 死亡 / 切图必然还原；
- 还席时若席位已不是自己的随从，一律不覆盖；
- 反射解析失败 / 类型变更 / 任何异常 → fail-closed：随从无背包，不崩。

官方宠物本身不受影响：它仍存在、仍跟随玩家，只是借席期间 PetProxy 的位置耦合
指向随从。

## 4.5 数据层与血脉目录（步骤 1）

| 文件 | 职责 |

| `PetNest/PetNestTuning.cs` | 数值常量与契约常量单点（三个存档 key、schemaVersion、本地化前缀、蛋血脉 KV 键、远征目的地 / 性格 id）。全表数值为草案，待 owner 审定 |

序列化枚举取值冻结：`PetNestPetState`（InNest=0 / Deployed=1 / OnExpedition=2 / Downed=3）、
`PetNestRiskTier`（Safe=0 / Rough=1 / Desperate=2）。

## 4.6 配置与存档管线（步骤 2）

| 文件 | 职责 |
| --- | --- |
| `Config/ConfigPetNest.cs` | 入口总开关 `petNestEnabled`（默认 false）+ ModConfig 镜像键 `BossRush_PetNestEnabled` + 唯一只读 getter `IsPetNestConfiguredEnabled()`。与 `Config/Config.cs` 拆开只为 1200 行预算，语义是同一 partial class |
| `PetNest/PetNestJson.cs` | 极简 JSON 编解码。既有 `SimpleJsonHelper` 只支持“扁平对象 + 一层数组”，撑不住「巢 → 崽[] → 天赋[]/战痕[]」两层嵌套；ModeH 的 JsonValue 按计划不 import，避免两套系统互为升级阻塞项 |
| `PetNest/PetNestPersistenceCodec.cs` | DTO ↔ JSON 手写编解码（不用反射：字段名是存档契约，必须可 grep），解码后立即 `Normalize()` |
| `PetNest/PetNestPersistence.cs` | 三 key store + 官方存档事件生命周期 |
| `PetNest/PetNestSaveCoordinator.cs` | 遗种巢**唯一** `SavesSystem.SaveFile` 触达点，每批至多一次 |

存档形态：三个 key 一律 `Save<string>` **JSON 整存** + `{schemaVersion, payload}` envelope。
不用 typed `Save<T>` 的原因：ES3 会把 assembly-qualified 类型名写进存档，mod 程序集
改名或类型重构就会让老档读不回来；整存字符串把这层耦合彻底切断。

写屏障口径：`schemaVersion` 与当前版本不符、payload 不可读、key 分类失败 →
**只读不写，绝不覆盖该 key**；写入路径异常 → 单向 `StoreFaulted`。
战斗中不落盘：`Store` 只入队 pending，物理写入统一由协调器批量触发；
`SavesSystem.IsSaving` 时改走 deferred，重试有预算上限，超预算保留 pending 并报错。

## 4.7 运行时模块与领域服务（步骤 3）

| 文件 | 职责 |
| --- | --- |
| `PetNest/PetNestRuntimeModule.cs` | `BossRushRuntimeModuleBase` 实现，复用 host 已有的六个回调，不新增全局 hook |
| `PetNest/PetNestService.cs` | 巢 CRUD / 出战席位（单席） / 遗魂账本；所有写操作走「改内存 → Store 入队 → 协调器落盘」 |

单实例纪律：`Common/Lifecycle/BossRushRuntimeModuleRegistration.cs` 先把实例存进
`petNestRuntime` 字段，再把**同一个引用**注册给 host；只读门面
`ModBehaviour.PetNestRuntime`。禁止二次 `new`（Mode G 的入口实例/host 实例分裂是反例）。

**dormant 契约**：`petNestEnabled = false` 时不订阅存档、不建血脉目录、不 tick 协调器。
开关是运行时可变的（ModConfig 单键回调），因此 bootstrap 走幂等的 `EnsureBootstrapped()`
并在 Awake / Start / OnSceneLoaded / OnUpdate 里重试；运行时关掉开关会经
`ShutdownIfEnabledTurnedOff()` 退订并作废目录，回到 dormant。

领域服务契约：单席位（设新席自动复位旧席）、远征锁定的崽拒绝上席与移除、
超容显式失败不静默丢弃、写屏障/StoreFaulted 时 `Commit` 返回 false 让调用方提示
"本次改动未能保存"。

## 4.8 掉落双轨（步骤 4）

| 轨道 | 机制 |
| --- | --- |
| 欧轨 | Boss 击杀后按 `PetNestTuning.EggDropChance` 直掉该血脉的「遗种蛋」（TypeID 500059 实体物品） |
| 非轨 | 每次击杀必记「遗魂」到账本（纯账本，不掉实体），数量镜像官方 `SoulCollector` 的 `MaxHealth / 15` 口径且有下限；同血脉攒够 `SoulsPerCondensedEgg` 可定向凝蛋 |

挂接点是**单点**：`LootAndRewards.RegisterBossRandomLootTracking` 体内并联一行
`PetNestDropService.TryTrack(this, character)`，清理侧并联 `ClearTracking`。
该函数覆盖全部 Boss 生成调用位，并且天然**不含** Mode G 托管路径
（ModeG adapter 会 `ClearBossRandomLootTracking`）与丧尸模式——正好等于首版掉落范围。
零新增 Harmony 补丁。

事件纪律（AGENTS.md 4.6）：per-character 订阅先退旧再挂新，注册失败回滚追踪状态，
角色回收时必然退订。

性能：一局可能几十次击杀，遗魂记账走 `AddSouls(commit:false)` + `StageCommit()`
只入队不落盘，由官方 `OnCollectSaveData` 与切图/回基地的 flush 写下去。

遗种蛋（`Integration/Items/RelicEggConfig.cs`）：**通用蛋 + KV 记血脉**——全谱系只占
一个 TypeID，血脉写在 `Item.Variables` 的 `PetNest_Lineage` 上随 `ItemTreeData` 持久化；
`MaxStack = 1`（堆叠合并会让不同血脉的蛋并成一枚，血脉丢失）；零新增 bundle，
走 `BossRushDynamicItemRegistry` 的 `FallbackLoader` 从既有物品克隆。
三处注册点（configurator / BuildPlans / 本地化）漏一处就会在重启后变 FallbackItem，
由 `PetNestEggItemRegistryGuard` 守。

本地化唯一入口 `Localization/PetNestLocalization.cs`，挂
`InjectLocalization_Extra_Integration()`，前缀 `BossRush_PetNest_`。

## 5. 性能门控

- 零常驻：局内至多一次 `CreateCharacterAsync`（出战席位非空才生成）；
- 随从维护节流到 4Hz，热路径零分配；
- 致死钳制链先读静态 `IsCompanionArmed` bool 早返，未带崽时不建集合、不分配。
