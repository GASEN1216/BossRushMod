## 1. 系统定位

遗种巢是**基地侧的养成 / 收集系统**，不是第九个游戏模式入口。它把 mod 存量最丰厚的
内容（Boss 池）反转成收集与陪伴对象：

```
打 Boss → 掉「遗种蛋」/「遗魂」 → 巢中孵化幼体 → 单席随从进局 / 天灾远征 → 博物馆图鉴与纪念碑
```

四条工程硬原则贯穿全案：**最小化修改 / 最大化复用 / 无性能问题 / 最佳设计模式**。
全案 **零新增 Harmony 补丁**——两处需求都走既有补丁加消费者。

## 4. 关键机制

### 4.1 跟随驱动 = `AICharacterController.leader`

官方 `PetAI` **没有**跟随移动逻辑（只做速度同步 + >40m 传送）。真正的跟随来自
`AICharacterController.Update`：

```
if (leader != null && searchedEnemy == null) patrolPosition = leader.transform.position;
```

因此随从组件只写 `leader`，索敌与作战完全交还原生行为树（免费获得自动作战）。
**不写 `searchedEnemy`、不写 `leaderAI`**——后者会在 leader 与成员之间双向同步目标。

`patrol` 分支在 `searchedEnemy != null` 时不跟随，崽会追着敌人跑远，所以自写一份
>40m 传送兜底（阈值与落点公式沿用官方 `PetAI.Update`）。

### 4.2 中性化五件套

克隆 preset 上、**CreateCharacterAsync 调用之前**写：

| 字段 | 值 | 理由 |
| --- | --- | --- |
| `hasSkill` | `false` | 技能白名单化之前，幼体不带 Boss 技能（自爆 / 召唤 / 范围） |
| `exp` | `0` | 随从不是可击杀目标，不给经验 |
| `hasSoul` | `false` | 不掉灵魂方块，避免 `SoulCollector` 把随从死亡当战利品来源 |
| `team` | `Teams.player` | 随从进局的根基，也是清场豁免判据之一 |
| `dropBoxOnDead` | `false` | 随从倒下是重伤退场，不是战利品事件 |

必须在 await 窗口之前写：窗口期间波次统计、掉落、经验、成就只能看到 clone 身份。

### 4.3 只缩 `modelRoot`

`CharacterMainControl.modelRoot` 是 public Transform；角色碰撞体只在
`SetCharacterModel` 内计算一次（混用世界坐标差值与未缩放常量），缩角色根会让
碰撞 / 寻路与视觉永久失配。因此幼体只缩 `modelRoot`（基准 0.4x），**纯视觉缩小**。
已知取舍：大体型幼体碰撞体不缩，可能挡路——首版接受，P2 再议。

### 4.4 捡漏背包 = 借用官方 PetProxy 席位

官方 `PetProxy.Update` 被 `LevelManager.PetCharacter` 门控，命中后：把 PetProxy 自身
transform 贴到宠物位置、每秒把 Inventory 容量同步成**玩家**的 `PetCapcity` stat。
backing field 是 `private CharacterMainControl petCharacter`，无 setter，因此需要反射写。

**实装期实测修正（与实施计划原文不同）**：`petCharacter` 并非“无可见赋值点”，
关卡初始化会执行

```
petCharacter = await petPreset.CreateCharacterAsync(mainCharacter.position + Vector3.one * 99f, ...)
```

即**每张图都有官方宠物占席**，席位永不为空。若照“在场就让位”字面执行，捡漏背包
将永不激活。因此实现的是**借席不夺席**：

- 只在非基地图借席（基地由官方 `PetHouse` 驱动宠物驻留位）；
- 借席前记录原占位者，离场 / 死亡 / 切图必然还原；
- 还席时若席位已不是自己的随从，一律不覆盖；
- 反射解析失败 / 类型变更 / 任何异常 → fail-closed：随从无背包，不崩。

官方宠物本身不受影响：它仍存在、仍跟随玩家，只是借席期间 PetProxy 的位置耦合
指向随从。

## 4.6 配置与存档管线（步骤 2）

| 文件 | 职责 |
| --- | --- |
| `Config/ConfigPetNest.cs` | 默认内容 `petNestEnabled=true` + 兼容保留的旧镜像键 `BossRush_PetNestEnabled` + 唯一只读 getter `IsPetNestConfiguredEnabled()`。与 `Config/Config.cs` 拆开只为 1200 行预算，语义是同一 partial class |
| `PetNest/PetNestJson.cs` | 极简 JSON 编解码。既有 `SimpleJsonHelper` 只支持“扁平对象 + 一层数组”，撑不住「巢 → 崽[] → 天赋[]/战痕[]」两层嵌套；ModeH 的 JsonValue 按计划不 import，避免两套系统互为升级阻塞项 |
| `PetNest/PetNestPersistenceCodec.cs` | DTO ↔ JSON 手写编解码（不用反射：字段名是存档契约，必须可 grep），解码后立即 `Normalize()` |
| `PetNest/PetNestPersistence.cs` | Bundle_v2 权威 store + 三个 v1 只读迁移源 + 官方存档事件生命周期 |
| `PetNest/PetNestSaveCoordinator.cs` | 遗种巢**唯一** `SavesSystem.SaveFile` 触达点，每批至多一次 |

存档形态：`BossRush_PetNest_Bundle_v2` 是唯一权威 `Save<string>` JSON，顶层含
`schemaVersion=2`、`generation` 与三个分区。旧 Nest/Expedition/Museum v1 key 永久只读保留；
仅在 v2 不存在时合并迁移，v2 写入并回读成功才完成切换。v2 已存在却损坏、过新或不可读时
fail-closed，绝不回退可能过期的 v1。不用 typed `Save<T>` 的原因不变。

写屏障口径：Bundle schema 不符、payload 不可读、key 分类失败 →
**整包只读不写**；写入路径异常 → 单向 `StoreFaulted`。
战斗中不落盘：`Store` 只入队 pending，物理写入统一由协调器批量触发；
`SavesSystem.IsSaving` 时改走 deferred，重试有预算上限，超预算保留 pending 并报错。

## 4.7 运行时模块与领域服务（步骤 3）

| 文件 | 职责 |
| --- | --- |
| `PetNest/PetNestRuntimeModule.cs` | `BossRushRuntimeModuleBase` 实现，复用 host 已有的六个回调，不新增全局 hook |
| `PetNest/PetNestService.cs` | 巢 CRUD / 出战席位（单席） / 遗魂账本；所有写操作走「改内存 → Store 入队 → 协调器落盘」 |

单实例纪律：`Common/Lifecycle/BossRushRuntimeModuleRegistration.cs` 先把实例存进
`petNestRuntime` 字段，再把**同一个引用**注册给 host；只读门面
`ModBehaviour.PetNestRuntime`。禁止二次 `new`（Mode G 的入口实例/host 实例分裂是反例）。

**dormant 契约**：`petNestEnabled = false` 时不订阅存档、不建血脉目录、不 tick 协调器。
开关是运行时可变的（ModConfig 单键回调），因此 bootstrap 走幂等的 `EnsureBootstrapped()`
并在 Awake / Start / OnSceneLoaded / OnUpdate 里重试；运行时关掉开关会经
`ShutdownIfEnabledTurnedOff()` 退订并作废目录，回到 dormant。

领域服务契约：单席位（设新席自动复位旧席）、远征锁定的崽拒绝上席与移除、
超容显式失败不静默丢弃、写屏障/StoreFaulted 时 `Commit` 返回 false 让调用方提示
"本次改动未能保存"。

## 4.8 掉落双轨（步骤 4）

| 轨道 | 机制 |
| --- | --- |
| 欧轨 | Boss 击杀后按 `PetNestTuning.EggDropChance` 直掉该血脉的「遗种蛋」（TypeID 500059 实体物品） |
| 非轨 | 每次击杀必记「遗魂」到账本（纯账本，不掉实体），数量镜像官方 `SoulCollector` 的 `MaxHealth / 15` 口径且有下限；同血脉攒够 `SoulsPerCondensedEgg` 可定向凝蛋 |

挂接点是**单点**：`LootAndRewards.RegisterBossRandomLootTracking` 体内并联一行
`PetNestDropService.TryTrack(this, character)`，清理侧并联 `ClearTracking`。
该函数覆盖全部 Boss 生成调用位，并且天然**不含** Mode G 托管路径
（ModeG adapter 会 `ClearBossRandomLootTracking`）与丧尸模式——正好等于首版掉落范围。
零新增 Harmony 补丁。

事件纪律（AGENTS.md 4.6）：per-character 订阅先退旧再挂新，注册失败回滚追踪状态，
角色回收时必然退订。

性能：一局可能几十次击杀，遗魂记账走 `AddSouls(commit:false)` + `StageCommit()`
只入队不落盘，由官方 `OnCollectSaveData` 与切图/回基地的 flush 写下去。

遗种蛋（`Integration/Items/RelicEggConfig.cs`）：**通用蛋 + KV 记血脉**——全谱系只占
一个 TypeID，血脉写在 `Item.Variables` 的 `PetNest_Lineage` 上随 `ItemTreeData` 持久化；
`MaxStack = 1`（堆叠合并会让不同血脉的蛋并成一枚，血脉丢失）；零新增 bundle，
走 `BossRushDynamicItemRegistry` 的 `FallbackLoader` 从既有物品克隆。
三处注册点（configurator / BuildPlans / 本地化）漏一处就会在重启后变 FallbackItem，
由 `PetNestEggItemRegistryGuard` 守。

本地化唯一入口 `Localization/PetNestLocalization.cs`，挂
`InjectLocalization_Extra_Integration()`，前缀 `BossRush_PetNest_`。

## 4.9 孵化、凝蛋与命名（步骤 5）

`PetNest/PetNestHatchService.cs`。三层 roll **孵化即锁定**：出身天赋 ×2（不重复抽）、
性格 ×1、异色，概率与条数全部走 `PetNestTuning` 常量。

**commit-before-reveal**：roll 出来的结果先入巢落档，成功之后才消耗蛋，最后才把
只读结果快照交给演出层。孵化服务因此**不 import 任何 View / UI 符号**
（`PetNestHatchCommitGuard` 逐条断言），任何时点断电都不会出现"演出播了但崽没进巢"。

**fail-closed 不消耗蛋**：蛋上的血脉 KV 读不到、或血脉不在目录里（官方 preset 改名
导致老蛋漂移）时，提示并原样保留蛋。消耗蛋失败会回滚已入巢的崽，避免一蛋两崽。

凝蛋是事务：先扣遗魂 → 入巢 → 入巢失败退还遗魂。凝出来的崽直接入巢，不产实体蛋，
避免"凝出来的蛋放不进背包"这种半成品状态。

天赋池注意：`PetCapcity` 是**格子数**（官方 `Mathf.RoundToInt`），必须常量加，
按百分比会在基础值为 0 时永远加不出格子。

## 4.10 随从进局正式管线（步骤 6）

| 文件 | 职责 |
| --- | --- |
| `PetNest/PetNestModeGate.cs` | 模式门控。禁入：Mode G / 末日丧尸 / Mode H；允许：标准三档 / 竞技场 / D / E / F。**只经公开只读门面判定**，不引用其他模式的内部符号 |
| `PetNest/PetNestCompanionRuntime.cs` | 局内生命周期：入场生成 → 跟随作战 → 重伤退场 → 离场清理，全部路径共用一个 `CleanupOnce()` |

**Mode H 禁入是实装期新增的保守判定**：脑暴 §5.4 的门控表写于 Mode H 立项之前。
Mode H 是观战模式，擂台由 arena isolation lease 独占并清空原生敌人，塞随从进去只会
污染隔离核对。`Needs owner confirmation`。

零常驻：出战席位为空时连门控都不查；局内至多一次 `CreateCharacterAsync`；
异步生成在 await 之后重验 owner / scene generation / 玩家引用，半成品 handle 在
`finally` 里回收。

**阵营取主人的实际阵营**而不是硬编码 `Teams.player`——Mode E 会把玩家改到别的阵营，
硬编码会让随从在阵营混战里被误伤（同 `SummonStaffAction` 的取法）。

幼体激活时复用既有净化入口 `SanitizeBossRushZombieSpawn` 去掉自爆技能与 BoomCar
特殊挂件（官方敌方 preset 里确实有会自爆的），随后做伤害归一。

清场豁免与敌对性安全网：`WavesArenaEnemyMaintenance` 的两处清场入口与
`ModBehaviour` 的敌对性安全网都豁免随从。豁免走**静态身份表**而不是 `preset.team`——
运行时 `SetTeam` 不会改写 `characterPreset.team`，Mode E 换阵营时 preset 前置条件会失效。
既有的 `bool isPet = false;` 字面量与 DeathWraith 检查顺序保持原样（DeathWraith guard 依赖）。

捡漏背包的两件套与随从同寿命：借席（`TryBorrowSeat` / `ReleaseSeat`）+ 容量 Modifier。
容量 Modifier 必须挂**玩家**的 `CharacterItem`——官方 `PetProxy` 每秒读的是
`CharacterMainControl.Main.PetCapcity`，挂宠物完全无效；且必须用 `ModifierType.Add`
常量加（`PetCapcity` 是格子数，官方 `Mathf.RoundToInt`，百分比在基础值为 0 时加不出格子）。
stat key 拼写就是 `PetCapcity`（少一个 a），改成 `PetCapacity` 会静默失效。

## 4.11 重伤退场与战痕（步骤 7）

「你在场，它不死」的落地，**零新增 Harmony 补丁**：

| 链 | 消费者 |
| --- | --- |
| 致死钳制链（`Health.CurrentHealth` setter Prefix） | 第四消费者 `TryClampPetNestCompanion`：钳到 1 血 + 登记退场 |
| 死亡抑制链（`CharacterMainControl.OnDead` Prefix） | 第三 registry `PetNestDeathSuppressionRegistry`（保险带：极端时序下随从真死时，不让本 Mod 的两个额外掉落 handler 误触发） |

**时序纪律**：钳制回调仍在 `Health.Hurt` 的调用栈里，因此只做两件事——上短无敌
（必须同帧生效才能挡住连击）和登记待办。真正的退场、战痕落档与角色回收由
`PetNestDownedHandler.Tick()` 在下一个宿主 tick 执行。在 Hurt 栈里销毁角色、写存档、
改场景状态是宿主崩溃的经典配方。

**凶手来源**：`CurrentHealth` setter 拿不到 `DamageInfo`。给 `Health.Hurt` 的 Prefix
加参数会动到 `ReverseScaleLethalProtectionGuard` 与 `ModeGPerformanceGuard` 断言的签名
字面量，因此改为订阅官方 `Health.OnHurt` 静态事件——且**只在随从在场期间订阅**
（OnHurt 是全场热路径，常驻订阅等于给每次伤害加一个委托调用），离场立刻退订。

**战痕**：时间 / 地图 / 凶手 + 一条永久小 Modifier。每崽上限
`PetNestTuning.MaxScarsPerPet`，溢出时最旧的一条并进 `mergedOldScarCount`（履历还在，
存档不涨）；同一 stat 上的减益有叠加封顶，全封顶后新疤只记履历不再恶化数值。

`PetNestDeathSuppressionRegistry` 是**薄封装**：身份来源直接复用随从组件的静态表，
不维护第二份簿记（两份簿记必然失步）。

## 4.12 天灾远征（步骤 8）

`PetNest/PetNestExpeditionService.cs`。玩家不在场的异步玩法，也是整个系统
**唯一的真死来源**。三目的地（风暴海域 electricity / 酸雨废墟 poison /
极寒荒原 ice）× 三档位（平安 / 风浪 / 亡命）。首版是**纯结算模拟**：不加载场景、
不改天气。

**现实时间计时**：用 `DateTime.UtcNow.Ticks`，不用 `GameClock`——后者离线不推进
（Update 里 `Time.deltaTime * 60`），关掉游戏远征就冻住。现实时间 ticks 是仓库既有
先例（`BossRush_WishReward_NextAvailableTicks`）。剩余时间一律 `max(0, Δ)` 钳制。

**死亡率随出发记录固化**：`deathRate` / `successRate` 在出发时写进记录。出发前明示给
玩家的、结算用的、纪念碑刻的，必须是同一个数字；后续调数值不影响已出发的远征。

**commit-before-reveal**：结算 = roll → 结果、`settled` 与奖励债务先落档 → 发奖 → 翻牌只回放。
服务层不 import 任何 View 符号；`MarkRevealed` 里不得出现任何 roll。结算幂等：
已 settled 不重复 roll。发奖采用 `cashGranted` / `grantedLootUnits` 游标续发；外部 API 与
Mod 存档无法原子提交，按至少一次语义处理极端崩溃窗口，宁可重复一格也不静默少发。

**元素亲和**：血脉元素与目的地匹配时成功率上浮。收集不同血脉从此有功能意义。

**真死**：移除 `PetRecord`（不可逆）→ 纪念碑刻档。碑上**必须**有风险档位与出发时
固化的死亡率——"亡命"两个字是玩家自己按下的，碑文替系统记住这一点。
纪念碑有上限，溢出的最旧条目合并为碑林计数。

**事务范围**：一次结算会同时改崽状态、远征记录和纪念碑，因此三分区装进同一个
Bundle_v2 候选包提交，避免"崽没了但碑没刻"的半截状态。

首版产出 = 现金 + 同血脉遗魂，亡命档小概率带回一枚遗种蛋。材料 / 装备件的产出表
需要经 owner 审定的官方物品 ID 表，首版不猜 ID；DTO 的 `outcomeLootTypeIds`
已经预留，补表时只填 `RollLoot`，不动结构。

## 5.0 计划完整性审计与资源落位（2026-08-29）

对实施计划 0-13 步与两张契约表做了一轮逐条只读审计（178 项），43 项非 DONE。
其中大多数是已登记的合理偏差（借席不夺席、Config 拆文件、凝蛋即孵化等），
真正的缺口已全部补上：

**Modifier 单位错 100 倍（最严重）。** 天赋 `8f/12f/5f` 与战痕 `-2f/-10f` 被当作
「百分数」写，而官方 `ModifierType.PercentageAdd` 走的是 `result *= (1 + 累加值)`
（`鸭科夫源码/ItemStatsSystem/Stat.cs:263`），本仓同口径。于是一道疤是 WalkSpeed
**-200%**、一条天赋是 **+800%**。常量已全部改成小数（`-0.02f` / `0.08f`），
展示层按官方 `EndowmentEntry` 同款 ×100 换算回百分数。

**天赋 statKey 有三个在角色 Item 上不存在**（`Damage` 是**武器** Item 的 stat，
`SightDistance` / `DodgeChance` 查无此项），挂上去 `AddModifier` 直接返回 false
静默失效。已换成 `GunDamageMultiplier` / `MeleeDamageMultiplier` / `GunScatterMultiplier`。

**命名功能玩家够不到。** `TryRename` 写了但全仓零调用者，而本地化文案对玩家承诺过
「起个名字」。补了 `PetNestRenameModal`（TMP 输入框 + 独占 modal lease）作为入口。

**远征选崽是死字段。** `_selectedPetId` 只读不写，页面提示「先在巢里选一只崽」
描述的是不存在的操作。现在巢页卡片的「设为出战」与「改名」都会顺手选中它，
面板用 Warning 描边标出当前远征目标。

其余：借席失败时不再照挂容量加成（fail-closed）、重伤退场的崽不再因局中途换图而
复活入场、`DownedInvincibleSeconds` 接成兜底解除（防 Tick 停摆导致永久无敌）、
遗魂取整对齐官方 `RoundToInt`、远征在基地内到期时打开面板即结算、
战痕封顶与目的地元素表各自去重到唯一权威实现、清掉 7 处死代码。

**资源落位。** 计划里「零新增 bundle」是没有美术时的降级，现已补齐：
建筑模型 bundle（脚本确定性生成的 prefab，43 renderer / 0 collider）、
建筑图标（铅笔线稿，与既有建筑图标同风格）、遗种蛋图标。三者缺失时的
占位 fallback **保留不动**——那是契约的一部分。

## 5.1 对抗式审查修复（17 条）

实装完成后对全子系统做了一轮多维度审查 + 三视角对抗式复核，17 条经复核确认的缺陷已修复。
其中若干条是"看起来能跑、实际主玩法是死的"，值得单独记住：

**存档事务原子性。** 历史实现曾逐个 Store 三个 key，即使先检查 `CanStore`，进程崩溃或
物理写入局部失败仍可能产生分叉。现在三个分区统一进入 `BossRush_PetNest_Bundle_v2`：
所有领域写操作先深拷贝候选包，在候选上完成孵化、出发、结算、揭示、释放与账本变化，
编码/Store 成功后才交换权威缓存。三份 v1 key 只负责一次迁移，不再参与运行时提交。

**发奖可恢复。** 落档成功而发奖失败（或中途崩溃）时 `settled` 已经是 true，
`TrySettle` 再也不会重入，奖励永久丢失。现在 `rewardsGranted` 是与 `settled` 分开的
第二个标记，`TryGrantPendingRewards()` 幂等补发，翻牌前也会先补发。

**随从入场门控的采样时机。** 门控原先只在 `sceneLoaded` 采样一次，而带
`customSpawnPos` 的竞技场要等协程才置 `bossRushArenaActive`、Mode D 有 0.5s 延迟、
`IsActive` 更要等开波——9 张竞技场地图里 8 张在那一刻五个标志全是 false。
「单席随从进局」这条主玩法在多数入场路径上是死的。现在有 90 秒 / 1 秒一次的入场重试窗口。

**伤害归一三重失效。** 原先在 `CreateCharacterAsync` **返回之后**写 preset 的
`damageMultiplier`——官方只在创建内部消费一次，之后没有任何读者；运行时 Modifier 又取了
`"Damage"`（那是**武器 Item** 的 stat，角色 Item 上取不到）且 `PercentageMultiply`
传 0.06 是 ×1.06 而不是降到 6%。幼体一直带着 Boss 原始伤害。现在归一写在 clone preset 上
（创建之前），并在创建后按正确 key 兜底钳制。

**天赋与战痕原本只是展示文本。** 没有任何地方把它们转成 Modifier，两只天赋完全不同的
崽进局后属性一模一样。现在 `ApplyPetModifiers` 在激活时挂上（`PetCapcity` 跳过——
官方读的是玩家 stat）。

**UI 静默截断三处。** 卡片区按裸 y 预算铺、动作按钮硬截断 6 个：巢里第 5 只之后的崽
永远无法出战、第三个远征目的地「极寒荒原」不可达、阵亡纪念碑一行都渲染不出来。
现在内容区与动作区都是带 `ScrollRect` 的滚动列表。

**演出层不拦输入。** canvas 建成 `interactive:false`，遮罩只是"看起来"挡住了，
下面仍然活着的面板照样能被盲点到——孵化时列表刚好重排，玩家会静默连吞第二枚蛋。
现在两个演出层都接管输入、带跳过按钮、切图显式停。

其余修复：关开关必须清 store 缓存（否则切档再开会把旧档覆盖到新档）、
建筑注入要看开关（关闭且未建过时不注册，避免玩家花 1500 建一个点不动的摆件）、
战痕凶手改在下一 tick 读（官方 `OnHurt` 在 `CurrentHealth` 赋值**之后**才派发）、
翻牌显示崽名而不是内部 petId、按钮失败原因落到玩家可读提示。

`PetNestRuntimeModule.OnUpdate` 在未 bootstrap 时先尝试 `EnsureBootstrapped()` 再早返，开关在场景内被关掉又打开时能当帧复活；此前唯一唤醒路径是 `OnSceneLoaded`，不切场景就要一直保持 dormant。开关关闭状态下这仍是两次 bool 加一次 no-throw getter 的 O(1) 早返，dormant 零开销不变。`tests/PetNestRuntimeModuleGuard.py` 的早返断言已同步冻结这一形态。日报模块采用同一写法，两系统保持同构。

## 2026-08-29 收口更新（血脉目录时序、自定义血脉与养成）

**血脉目录时序（P0）**：目录此前在 bootstrap（`ModBehaviour.Start`）构建一次就再不重建，而 `enemyPresets` 要等玩家第一次进竞技场才由 `WavesArena.InitializeEnemyPresets` 填充——构建时读到的是空池，于是全部官方 Boss 都不在目录里，表现为不掉蛋、不记遗魂、老蛋孵不出、崽带不进局。现在 `PetNestRuntimeModule` 提供 `NotifyEnemyPresetsRefreshed()`（未 bootstrap 时早返 → `Invalidate()` → `EnsureBuilt(_owner)`），由两处触发：`InitializeEnemyPresets` 全量扫描末尾，以及 `BossFilter.InvalidateFilteredPresetsCache`（唯一咽喉点，覆盖初始化/单点开关/全开/全关/预设刷新五条路径）。后者让掉落资格随玩家在场内改 Boss 池即时收敛。重建幂等，只发生在这两类低频时刻，无每帧成本。

**自定义血脉幼体（P1）**：三个自定义 Boss 的 runtime preset 是各自生成那一刻才 `Instantiate` 的角色属性，不进任何全局注册表，而 `ObjectCache.GetCharacterPresets()` 是有意不刷新的一次性快照，因此永远查不到——龙王/龙裔/女巫的崽此前每局都以 `lineage_preset_missing` 被拦在场外。新增 `PetNestCompanionSpawner.ResolveCompanionSourcePreset`：自定义血脉解析各自的官方底模（龙裔与龙王共用 `Cname_Boss_Red`，女巫用 `Cname_Ghost` 回落 `Cname_Boss_Red`），其余走通用解析；血脉身份由 `CreateIsolatedAsync` 在中性化之前写 `clone.nameKey` 补上。**通用的 `ResolveSourcePreset` 有意不动**：目录的官方循环正是靠它对自定义 key 返 null 来 fail-closed 跳过，从而把这三条血脉留给 `AddCustomLineages` 登记（带元素覆盖、缩放档与显示名）；让通用解析认自定义 key 会导致官方循环以 `IsCustomBoss=false` 抢注，这些设定全部失效。自定义血脉显示名改用各 Boss Config 的双语常量，不再显示裸 key。

**龙王掉落并联**：龙王不走 `RegisterBossRandomLootTracking`，而是自建 `dragonKingLootEventHandlers` 手动订阅 `BeforeCharacterSpawnLootOnDead`，因此遗种巢掉落追踪对它从未生效。现在在那条手动路径上并联 `PetNestDropService.TryTrack`，离场与死亡两个清理点并联 `ClearTracking`（幂等，不重构手动路径）。

**养成（owner 2026-08-29 定数值）**：新增 `PetNestProgressionService`。Lv10 封顶、每级 100 exp 线性；经验来源为进局存活归巢 +10（重伤退场也算，战痕已是惩罚）、随从击杀 +2（单局封顶 +30）、远征存活 +25；每 3 级给玩家 +1 格捡漏背包。`AddExp` **只改内存不落档**，由调用方按自身事务边界提交（远征侧并进既有 `CommitBoth`，不破坏那条链的原子性）。击杀经验通过 `Health.OnDead` 幂等成对订阅，只在随从在场窗口内挂，热路径是零分配早返链 + `HashSet` 受害者去重。归巢结算挂在基地分支最前面，必须早于 `RestoreDownedPetsOnReturnToBase`（会复位 Downed）与 `CleanupOnce`（会清 active id）。`careerCount` 补上进局计数，与契约注释「进局 + 远征」对齐。成年体快照本轮不写入：Lv10 的触发点多在局外，拿不到 `maxHealth`/`damageFactor` 真值。

**巢容量与放生**：容量改为纯派生的 `PetNestService.GetEffectiveNestCapacity()`——基础 12，图鉴解锁血脉数每达 10/20/30 各 +4，封顶 24；不写档，存档 `capacity` 字段只作老档下限。新增 `TryReleasePet` 单事务（移出巢 + 清席 + 返还 60 同血脉遗魂，失败逐项回滚）与 `PetNestReleaseConfirmModal` 二次确认弹窗，给巢满一个可预期的腾位出口（此前唯一手段是押 22% 死亡率的亡命远征等崽死）。

## 2026-08-29 收口更新（P1/P2 复审修复与防御性自愈）

**基地侧血脉目录空窗（P1，CR-2026-08-29-015）**：上一轮修的是「预设池填充**之后**重建目录」，没覆盖「填充**之前**」这段每会话必现的窗口。`InitializeEnemyPresets` 的全部调用点都在进竞技场路径与调试面板（`BossRushIntegration_StartAndScene` 的 `bossRushArenaPlanned` 分支、`_TravelAndSetup`、`ModeEBattle`、`ModeGRuntimeBridge`、`BossFilter.OpenBossPoolWindow`），基地启动一处都不触发；而 `GetFilteredEnemyPresets` 在 `enemyPresets == null` 时返回空表。结果：重启会话后直接在基地孵官方血脉蛋 → `lineage_unknown`（文案「血脉无法识别，已原样保留」误导玩家以为蛋坏了），巢页卡片显示裸 `Cname_*` key、博物馆分母失真、遗魂账本官方血脉整行缺失、凝蛋按钮消失；进一次竞技场后当场自愈。

修复：`WavesArena` 提供图鉴/遗种巢共享幂等入口 `EnsureEnemyPresetsReadyForGameplayCatalogs()`（池已填充时零成本返回，未填充时走 `InitializeEnemyPresets`）；两个消费者至少一个启用才预热，同一进程只实际扫描一次。池填充和 BossFilter 变化都同时通知图鉴与遗种巢，已打开图鉴立即刷新，未打开只失效缓存。

**关开关不清掉落追踪（P1，CR-2026-08-29-016）**：`PetNestDropService` 的 handler 是 bootstrap 期间挂到 per-boss `BeforeCharacterSpawnLootOnDead` 上的，`_bootstrapped` 置回 false 之后它们仍挂在场上的 Boss 身上；此前 `ClearAllTracking` 的唯一调用链是宿主销毁。竞技场中途关掉开关后，场上已追踪 Boss 死亡仍会记遗魂、可能掉蛋、弹「可凝蛋」提示，穿透「关闭即不产蛋不记魂」的 dormant 契约。

修复两道：① `ShutdownIfEnabledTurnedOff()` 在 `_bootstrapped` 早返**之前**调 `ClearAllTracking()`——两个关闭分支（`OnSceneLoaded` / `OnUpdate`）都经这里，是唯一咽喉点，放在早返之后等于没修；② handler 本体 `OnBossBeforeSpawnLoot` 加 `IsEnabled(owner)` 二次检查作为第二道防线，防止将来新增关闭路径又漏清。第二道防线只在 Boss 死亡帧判一次，不是每帧热路径。

**`_hooks` 慢泄漏（P2，CR-2026-08-29-020）**：条目摘除此前只发生在 Boss 死亡路径与逐只清理，`LootAndRewards` 的 stale 清扫只清自家四表。未死亡也未被逐只清理的 Boss（中途弃局、直接撤离、切图销毁）条目永不移除，长会话跨多局无上限累积（死角色 key + 捕获 owner/character 的委托）。修复：`OnSceneLoaded` 顶部与既有的两个「跨局去重集合必须清」并排调一次 `ClearAllTracking()`。不会误清本局追踪——Boss 是场景加载完成之后才生成并注册的（全部注册点都在 `CreateCharacterAsync` 完成回调里）。

**OnExpedition 孤儿锁自愈（防御性）**：v1 历史三键可能已经留下「Nest 写成功、Expedition 未写」的半截状态。迁入 Bundle_v2 后 `ReconcileOrphanedExpeditionLocks()` 在回基地扫描；Bundle 有写屏障/故障时一步都不走，匹配采用 expedition id 或同一崽未结算记录两条，宁可漏修不可误修。

**跨存档槽缓存渗漏（防御性，与日报 CR-2026-08-29-017 同构）**：权威 Bundle store 的缓存与 pending 带 `_cacheSlot`；读取命中与物理 flush 前都校验 `SavesSystem.CurrentSlot`，不一致即丢弃旧槽缓存/pending 并从新槽重读。v1 store 只在迁移读取期使用，同样保留槽位自校验。

**远征发奖按条目记账**：`cashGranted` 记录现金到账，`grantedLootUnits` 是物品件数游标，
`rewardGrantAttempts` 仅诊断尝试次数，不再是永久放弃门槛。`rewardsGranted` 只在两类游标全部完成后
置位。基地 `LevelManager`、经济、物品资源任一未就绪都不尝试；失败固定退避继续。
正常重试不重做已记账格子，但外部送达与游标落盘之间存在不可原子化的崩溃窗口，因此明确采用
至少一次语义，而不是承诺“不可能重复”。翻牌与欠账解耦，玩家关闭揭示不会删除欠账记录。

Bundle_v2 是 `SCHEMA+`：v1 三键缺少这些字段时按默认值迁入；一旦 v2 产生新状态，旧 Mod
版本不保证能看到最新状态。v2 损坏或版本过新进入整包写屏障，不回退 v1。

## 2026-09-04 深度复审修复

`COMPAT`。孵化先从已确认的原容器可逆摘蛋，提交新崽候选时不提前 flush；候选被拒绝则放回原格，接管成功才销毁蛋，联合落盘成功后才揭示结果。落盘失败保留新崽与容器的写欠账，不把已接管的蛋放回造成双份。

远征实际发奖前要求资产保存边界就绪。游标提交和后续物理写重试都采集主角色物品树、仓库、官方溢出缓冲区及现金，再写 Bundle_v2。官方 OnCollectSaveData 同样采集，避免“新崽/已发游标 + 旧物品快照”。旧文中的“该窗口不可原子化”是修复前限制；当前这组资产与游标进入同一 ES3 缓存文件，仍需实机中断/IO 故障验证，不宣称游戏文件 IO 具有绝对原子性。

遗种蛋清除克隆源的使用行为并解绑 UsageUtilities，不会部署便携安全区。龙皇的遗种蛋/熔石 pending 生产者先订阅，主掉落消费者后订阅，涵盖无间炼狱同步消费。
