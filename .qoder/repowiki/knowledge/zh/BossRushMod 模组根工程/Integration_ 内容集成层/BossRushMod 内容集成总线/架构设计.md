模块以 `IntegrationRuntimeHooks.cs` 暴露的 `StartIntegrationRuntime` / `OnSceneLoadedIntegrationRuntime` / `CleanupIntegrationRuntimeOnDestroy` 三个入口挂载到宿主 `ModBehaviour`，由 `IntegrationDeferredBootstrap.cs` 中的协程编排分阶段启动：先执行 `InitializeAlwaysOnDeferredContent`、`InitializeDynamicItems`、`LoadEquipmentContent` 等“基础内容”步骤，再按场景句柄等待并触发 FlightTotem、ReverseScale、FenHuangHalberd、PhantomWitchScythe、NewWeapons 等子系统的场景级 Setup。

内部按功能域划分子目录，每个子系统遵循相似分层：
- 配置/数据：如 `Affinity/AffinityConfig.cs`、`DragonKing/DragonKingConfig.cs`、`WishFountain/WishFountainConfigAndValidation.cs`。
- 运行时核心：如 `AffinityManager`、`SetBonusManager`、`MutatorManager`、`WishFountainService`。
- UI/交互：如 `AffinityUIManager`、`ReforgeUIManager`、`WishFountainUI`、`UI/ImageViewerUI`。
- 持久化：通过 `Saves.SavesSystem` 事件（`OnSetFile`/`OnCollectSaveData`）或独立 `*Persistence*.cs` 文件管理存档键（约定使用 `BossRush_` 前缀）。
- 静态缓存清理：大量子系统提供 `*StaticCacheReset.cs` 配合热重载。

公共基础设施集中在根与 `Common`：
- `EquipmentFactory` / `ItemFactory` / `EquipmentContentRegistry` 作为装备与物品注册中心，所有新增装备必须走工厂管线。
- `NPCs/Common/NPCModuleRegistry` + `INPCModule` 接口实现 NPC 自动发现与按 `SpawnOrder` 排序生成，Courier/Goblin/Nurse 内置为模块；新增 NPC 优先实现该接口而非直接修改 `ModBehaviour`。
- `Utils/` 提供 NPC 移动、路径、名称气泡、交互组等共享工具。

依赖方向自顶向下：`IntegrationDeferredBootstrap` → 各子系统 Bootstrap → 子系统 Runtime → 共享 Utils / Affinity / EquipmentFactory；子系统之间不互相调用，仅通过全局管理器（如 `AffinityManager`、`Saves.SavesSystem`）通信。
