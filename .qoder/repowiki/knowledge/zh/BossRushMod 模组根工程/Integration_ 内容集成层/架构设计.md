顶层通过 IntegrationRuntimeHooks / IntegrationDeferredBootstrap / EquipmentRuntimeHooks 等入口在 Unity 生命周期中按顺序装配各子系统；每个子系统（Affinity、Bonus、DeathWraith、DragonKing、FlightTotem、Frostmourne、Items、Mutators、NPCs、NewWeapons、PhantomWitch、Reforge、ReverseScale、Wedding、WishFountain 等）遵循统一的三段式结构：Config 定义数据、Runtime/AbilityManager 承载行为、Bootstrap/Factory 负责注册到共享容器（EquipmentFactory、ItemFactory、EquipmentContentRegistry、SetBonusPlaceholderRegistry、NewWeaponPlaceholderRegistry）。跨子系统的协作集中在根级工厂与注册表上——装备与物品由 EquipmentFactory/ItemFactory 集中创建，UI 通过 UIImageViewer 等共享组件复用，NPC 相关子系统共用 Utils/NPC*Helper 与 Constants 中的常量。Boss 类（DragonKing、PhantomWitch、DeathWraith、DragonDescendant）还通过各自的 AbilityController + AssetManager + Config 组合对外暴露能力，并由 IntegrationRuntimeHooks 在场景加载时触发。

2026-09-02（COMPAT）：`BossRushDynamicItemRegistry.GetPublishedTypeIds()` 返回排序后的 ID 副本，本身不加载资源、不暴露可变 Plans。F3 工厂验收逐帧使用此快照，通过既有 EnsureRegistered/InstantiateSync 检查身份、名称和图标，再销毁游离实例；它不代替真实装备效果、获得途径与重启回读的人工场景。
