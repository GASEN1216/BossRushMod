# UI 制作共识

> 2026-09-24 定稿。来源：owner 指出「一股脑把所有功能都做成按钮丢出来，不符合最佳 UI 交互」，遗种巢面板据此按主流交互重排；owner 点名鸭王杯（Mode H）入场选人页「很干净，就要那种效果」。
> 本文是**新做 UI 的默认做法**：新界面按它设计，改旧界面时顺手往它靠。它和根 `AGENTS.md` §4.14（共享库、配色、字形、官方界面复用）、§4.17（常驻 HUD）一起用：§4.14 管「用什么零件、什么颜色」，本文管「页面怎么组织、按钮放哪、怎么才干净」。三者冲突时以代码与守卫为准，再以 AGENTS 为准，并回来修本文。

主流参照（设计时可以直接对照）：Apple HIG 的 [Split views](https://developer.apple.com/design/human-interface-guidelines/split-views) / [Sidebars](https://developer.apple.com/design/human-interface-guidelines/sidebars)、iOS 照片的「选择」批量模式、「破坏性按钮与安全按钮拉开距离」（旧版 HIG Controls）、宝可梦 HOME 的盒子 + 概要（[Game UI Database](https://gameuidatabase.com/gameData.php?id=1049)）、定价页的档位对比卡。

---

## 1. 一句话原则

**一屏只让玩家做一件事；按钮跟着它作用的东西走；看不见的信息比挤满的信息好。**

判断一个界面「对不对」只问三个问题：

1. 玩家打开它，第一眼知道该点哪里吗？（每屏一个主操作）
2. 每颗按钮点下去作用在谁身上，一眼看得出吗？（按钮挨着它的对象）
3. 删掉哪些字和按钮，玩家不会有任何损失？（把它们删掉或收进详情 / 说明）

---

## 2. 先选页型，再画界面

动手前先决定这是哪一种页。不要从「有哪些功能」出发把按钮一个个摆上去。

| 页型 | 什么时候用 | 骨架 | 样板 |
| --- | --- | --- | --- |
| **A 单决策页** | 玩家这一步只要做一个选择，选完流程就往下走 | 页头横幅 + 一句引导 + 一排数量有界的大卡（不滚动）；点卡即决定、立刻推进；其余参数用默认值 | 鸭王杯入场选人页：`ModeH/ModeHUIPages.cs` 的 `CreateChampionCards` / `BuildChampionCard`，内容 `ModeH/ModeHRuntimeModule_MatchFlow.cs` 的 `BuildDraftPageContent` |
| **B 列表 + 详情** | 管理一组对象（崽、藏品、NPC、存档……），每个对象有好几种操作 | 左栏：列表头（数量、「选择」进批量）+ 紧凑行，行上没有按钮；右栏：选中对象的全部信息 + 底栏只放作用于它的操作 | 遗种巢「巢」页：`PetNest/PetNestUINestPage.cs`（组装）、`PetNest/PetNestUILayout.cs` 的 `RenderNest`（画法） |
| **C 分区任务清单** | 几类「可以去做的事」，每条自己能做完 | 分区标题 + 一行一项，行内一个动作按钮，进度用进度条 + 数字；做不了的项不挂按钮，写还差什么 | 遗种巢「孵化」页：`PetNestUIPages.BuildHatchPage` |
| **D 一屏表单** | 要选几个参数再提交一次（目的地、难度、档位） | 从上到下：选对象（头像小卡）→ 分段按钮 → 对比卡 → 底栏一个提交按钮；每项都有合理默认值 | 遗种巢「天灾远征」页：`PetNestUIPages.BuildExpeditionPage` / `AppendDepartCards` |
| **E 确认弹窗** | 不可逆或有风险的操作 | 标题问句 + 对象（装饰名）+ 后果（红 / 黄字）+ 左危险右取消两颗按钮；ESC = 取消 | 共享件 `Common/UI/BossRushConfirmDialog.cs`（`BossRushConfirmDialog.Show(new Options { … })`）；遗种巢的放生 / 亡命出发原是它之前的两份自写样板，2026-09-24 第二轮已迁到它（批量名单、流光名字经可选的 `DecorateTarget`） |
| **F 常驻 HUD** | 进局就一直在、不是玩家主动打开的 | 不可点、不挡输入，跟随官方 HUD 显隐与暂停 | 规则见根 `AGENTS.md` §4.17 |
| **官方界面** | 叙事、图鉴、商店、任务 | 直接用官方对话 / NoteIndex / 商店 / Quest，不自绘 | 根 `AGENTS.md` §4.14 最后三条 |

选型的顺序：**能用官方界面就用官方 → 能做成单决策页就不做表单 → 集合管理才用列表 + 详情**。页型定下来，按钮位置基本也就定了（第 3 节）。

## 3. 按钮放哪（按钮归位）

| 操作作用于 | 放在哪里 | 例子 |
| --- | --- | --- |
| 一个对象 | 该对象的**详情底栏**，或它那一**行里** | 遗种巢详情里的「设为出战」「放生」；遗魂账本行里的「凝蛋」 |
| 当前页的全部对象 | **列表头**右侧（批量「选择」、排序、筛选） | 遗种巢容量行右边的「选择 / 完成」 |
| 这一页的结论 | **底栏右侧**，一颗主操作 | 远征页的「出发」 |
| 换一个视图 | **页签**（不是按钮），可带待办数字「孵化 ·2」 | 遗种巢四个页签 |
| 低频、非破坏的维护 | 小号次级按钮，挨着它改的东西 | 名字旁边的「改名」 |
| 说明、帮助 | 页眉「说明」或空状态里，不堆在列表底部 | 遗种巢页眉「说明」 |
| 关闭 | 页眉右上 + ESC | 所有面板 |

不要做的：

- **每张卡都挂两三颗按钮**。十几张卡就是几十颗按钮，玩家分不清哪颗管哪只。把操作收进详情，卡片整张可点即可。
- **把单对象操作和全局操作混在一条底部动作条里**（旧巢页的「不带崽出门 / 放生选中 / 批量放生」）。
- **让操作依赖看不见的选中状态**（旧版「先在巢里选一只，再到远征页派它」）。跨页要带着对象过去（「派去远征」直接切页并预选）。
- **交互菜单与面板页签重复**。建筑 / NPC 的交互菜单只放一个「打开」加上当下有事可做的快捷项，快捷项按条件显隐（`PetNestInteractable.RefreshOptionsWhenApproached`，口径同护士治疗项）。

## 4. 按钮的层级

- **每屏最多一个主操作**：`BossRushUIColors.AccentFill` 整块填充，放在最右。没有明确主操作的屏可以一个都不设。
- **危险、不可逆**：进确认弹窗前是**次级样式 + `DangerText` 描边 + 红字**，放在底栏最左、与安全按钮拉开；确认弹窗里的那颗才是 `Danger` 实心。确认弹窗一律用共享的 `BossRushConfirmDialog`（默认 `ModalConfirm` 层，压在各模式面板之上；丧尸模式传更高的层级常量；`Anchor` 传面板根物体，面板没了弹窗自动取消）。批量放生这种「主操作本身就是危险操作、后面还有确认」的，可以 `Danger` 实心放最右。
- **其余一律次级**：`BossRushUIKit.StyleSecondaryButton`（深底 + 描边）。`Accent` 只做描边、竖条、小字强调，不铺满按钮。
- **不挂灰按钮**（§4.14）：做不了就不画，原因写进正文或底栏状态字（「远征中 · 剩余 8 分钟」）。例外：钱不够、冷却中照挂，按钮上写价钱或秒数。
- **文案 = 动词 + 对象**：「选他出战」「放生 3 只」「出发 · 冒险」。不用「确定」「执行」这种看不出后果的词。
- **按钮数量**：一条底栏 ≤ 3 颗；超过就说明页型选错了（该拆详情或分二级）。

## 5. 信息的层级（渐进披露）

- **列表行 / 卡片只放认出它所需的信息**：图、名字、一行状态（「霜狼 · Lv7 · ★ 出战」）。性格效果、天赋、战痕这些进详情。
- **详情按「区头 + 正文」分段**，区头短（「性格」「出身」「战痕」），正文是白话。
- **说明文字不放在列表底下**：放页眉「说明」页、空状态、或它解释的那个东西旁边（捡漏背包的说明放在出战席位格和出战崽详情里）。
- **风险 / 免责披露要有，但分场景降级**：流程本身不押真资产时放页脚一行小字（Mode H 选人页的 `CompactRiskNotice`）；真正要做危险操作时，在确认弹窗里用红 / 黄字强提示。不做整条实心红横幅。
- **同类合并**：十枚同血脉的蛋是一行「×10」，不是十张卡。
- **同页超过 3–4 个并列选项**要分二级、改成分段按钮或列表（§4.14；列表页上限 6 项）。

## 6. 选择与状态

- **选中必须看得见**：卡片 / 行的选中态统一用 `WarningText` 描边；分段按钮选中压一点 `Accent` 底色 + `WarningText` 描边 + 粗体。
- **选中态不置灰**（置灰读作「不能选」）。
- **默认选中合理值**：打开就有一个能直接提交的状态（远征默认选元素契合的目的地、最安全的档位）。
- **批量模式**是 iOS 照片的口径：列表头「选择」进入 → 行上出现勾选框（点行即勾）→ 右栏换成「已选 N 只 · 后果」摘要与操作 →「完成」退出。不能勾的行不画勾选框。
- **同页重绘保住滚动位置**，切页才回顶部；同页重绘不重播入场动画。

## 7. 干净的视觉（鸭王杯选人页拆解）

owner 点名要的「干净」，拆开是下面这些做法。数值以代码常量为准（`ModeH/ModeHUI.cs`、`ModeH/ModeHUIPages.cs` 末尾的 const 区），这里列的是当前取值，供对照：

1. **页头只放三样东西**：模式横幅（`BossRushUIHero.CreateBanner`）+ 压在横幅上的徽记与标题（`BossRushUIHero.CreateEmblem` / `PlaceTitleRow`，标题 32 号）+ 横幅下**一句** 18 号次色引导（「挑一位替你上擂台……选好马上开打」）。没有横幅图时退回「徽记 + 标题」一行，不画灰块占位。
2. **一页只做一件事**：「挑一位选手出战」。点卡片就签下、自动配搭档、一路开打；下注、整备全按默认值，玩家不需要在这一页做第二个决定。
3. **数量有界、一排排开、不滚动**：五张大卡等宽并排（单卡最宽 360、最高 560，间距 16，卡内边距 16），面板 1480×860，安全边距 48。数量随玩家状态变化的东西才进滚动区。
4. **卡片内部自上而下一条竖线**：立绘（占卡高约 40%，取不到按 图鉴立绘 → 官方图标 → 模式徽记淡显 → 名字首字 退级）→ 名字 26 号主色 → 打法定位 18 号强调色 → 两三句白话 17 号次色 → 底部一颗描边按钮「选他出战」。**整张卡可点**，悬停时描边换色；按钮只是把「能点」说清楚。
5. **颜色克制**：深色底（`Surface` / `SurfaceRaised`）+ 一种强调色（`Accent`，只用在定位字、竖条、描边）+ 少量状态色（异常选手的竖条用 `Warning`）。整页没有一块大面积实心色块。
6. **风险披露降成页脚一行 14 号次色小字**，排在动作带上方；知情权还在，但不抢主角。
7. **字号最多四级**：标题 32 / 名字 26 / 定位与引导 18 / 正文 17（注脚 14 算第五级，只给披露用）。
8. **动效轻**：五张卡错峰升起（每张晚 0.05 秒、0.28 秒、上移 18），同页刷新不重播；按钮第一帧就能点。
9. **文案是白话**：「挑一位替你上擂台」「先上场的倒下了，它顶上」。不堆内部术语（旧卡把「异常名 / 招牌口令名 / 传闻」三行术语拼一起，被 owner 实测打回）。

做别的页型时，能搬的就搬：页头三件套、大留白、卡片竖线结构、克制配色、页脚小字披露、轻动效、白话文案。

**不要照搬的一处**：Mode H 共享按钮样式把所有 `IsDanger` 画成实心红块（选人页死胡同时出现的「退出本赛季」、恢复壳的「放弃赛季」），不符合第 4 节，已列入对照审查 B-04。学选人页的版式，危险按钮按第 4 节做。

## 8. 反馈与空状态

- **失败原因显示在操作附近**（巢页在详情顶部、分页在内容区顶部），红字、白话、说清怎么办。不给反馈，「巢满」和「点歪了」无法区分。
- **空状态告诉玩家下一步**：「巢是空的。去打 Boss，把它们的遗种带回来」+ 怎么开始。读档失败与「真的没有」必须分开讲。
- **进度用进度条 + 数字**（`12 / 20`），够数时进度条换成 `Success`，行内出现动作按钮。
- **倒计时每秒只改那一段字**（`LiveBody` / `LiveFooter`），不整页重建；到点只刷新一次。

## 9. 技术底线（已在 §4.14，这里只列检查点）

- 画布、层级、遮罩、底图、描边、字体、按钮配色、缓动、入场动画一律走共享库（`BossRushUI`、`BossRushUIKit`、`ZombieModeUIHelper`、`BossRushUIHero`、`BossRushUIEntranceAnimation`），面板和卡片要经过 `ApplyPanelStroke` / `CreateCard` 才有质感层。
- 模态面板独占输入租约、ESC 关闭（`PetNestCancelKey` 一类，压着子窗口时让给子窗口），关闭走淡出。
  流程里的一步（不是玩家主动打开的面板，比如鸭王杯的选人 / 看盘 / 结算页）没有可退回的地方时不接 ESC，照常交给官方暂停菜单——吞掉 ESC 会让玩家在这一步打不开暂停菜单；有「返回」的页（整备页、押物品页的「完成」）ESC 等于点返回（鸭王杯用 `ModeHActionData.IsCancel` 标出这颗，2026-09-24）。
- TMP 单行字框高 ≥ 字号 × 1.45 + 4，否则 Ellipsis 会把整行清空；量完宽度的按钮标签要重新打开自动缩字。
- 玩家可见文字中英双语、只用 GBK 收录字符（★ √ · × ■ → 可以用；Emoji、✓、• 不行）。
- 可滚动的内容一定是 `ScrollRect` + 布局组，不按裸 y 预算截断。
- 单文件行数预算（新文件 1200 行）：界面拆成「数据组装 / 画法」两类文件（`PetNestUIPages.cs` + `PetNestUI.cs` / `PetNestUILayout.cs` 的分法）。

## 10. 交付前自检

逐条打钩，不过的写进交付说明：

- [ ] 这页属于第 2 节哪种页型？说得出来。
- [ ] 打开第一眼只有一个主操作（或没有），它在最右。
- [ ] 每颗按钮挨着它作用的对象；底栏没有混放单对象操作与全局操作。
- [ ] 没有灰掉的按钮 / 选项；做不了的原因写在正文里。
- [ ] 危险操作：红描边红字、靠左、有确认弹窗、ESC = 取消。
- [ ] 列表行只有识别信息；长说明在详情 / 说明 / 空状态。
- [ ] 选中态看得见、不置灰，打开就有默认选中。
- [ ] 空状态和失败提示都写了「下一步」。
- [ ] 页头只有横幅 / 标题 + 一句引导；没有大面积实心色块；字号不超过四级。
- [ ] 中英文各看一遍：按钮字没被清空、没被省略号截断。
- [ ] 同页重绘不跳回顶部、不重播动画。
- [ ] 结构约束写成守卫（`tests/UILayoutReadabilityGuard.py` 一类几何断言，或像 `PetNestUILayerGuard` 那样钉住「危险操作必须先确认」），并做反向验证。
- [ ] 给 owner 的实机清单里写了「看哪一屏、点哪里、什么算不合格」。
