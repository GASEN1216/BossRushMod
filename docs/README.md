# docs 目录说明

`docs/` 按"常用资料留根目录、按文档类型分类目录、大型专题独立顶层目录"三层组织。AI 协作规则的唯一入口是仓库根目录 `AGENTS.md`，本目录只保留专项资料和 local-only 过程文档。

需要按模块查找当前实现资料时，从 [仓库知识库导航](../.qoder/repowiki/README.md) 进入；其中包含模块 scope 索引、架构知识卡、主题级详解和代码变更后的同步清单。

## 按大型专题分目录

仅当一个专题同时拥有"设计 / spec / 实现规划 / 资源"等多阶段文档（体量大）时，才考虑独立顶层目录。这两个目录内部按"阶段"分子目录：

- [末日丧尸模式/](末日丧尸模式)：末日丧尸模式（Zombie Mode）专题
- [未来拓展/](未来拓展)：中长期内容拓展专题

其他专题（龙王/龙皇、幽灵女巫、护士 NPC 等）仍按"文档类型"散落在上述分类目录中。

## AI 工作目录

- `superpowers/{plans,specs}`：由 AI 技能（brainstorming、writing-plans 等）自动写入，不要手动改动其结构。

## 维护约定

- 单一文档优先放入对应类型目录；仅经常翻阅的总览/提示词/配置表才放在 `docs/` 根目录。
- 同一专题的交付、验收与过程记录放同一个子目录（例：`制作教程/天空岛/`），不要散落在 `docs/` 根目录。
- 移动或改名文档时，同步改仓库里的所有引用：`AGENTS.md`、`CODE_REVIEW_FINDINGS.md`、`FIX_TRACKER.md`、`.qoder/repowiki/`、代码注释与守卫文案。
- 修改行为、架构、配置或内容时，同步更新 `.qoder/repowiki/` 中对应知识卡与主题文档。
- 新增大型专题（拥有 4 阶段文档）才考虑建顶层目录，并按 设计/ spec/ 实现规划/ 资源/ 4 个子目录组织。
- 命名统一：专题与目录名使用「拓展」而非「扩展」。
